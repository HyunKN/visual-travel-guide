# 제품 목표와 첫 검증 범위

상태: 시나리오 기반 프로토타입의 제품 범위. 로컬 구현·자동/브라우저 검사와 실제 사람 관찰을 구분한다. 실행·검증 현황은 [프로토타입 안내](../prototype/README.md)와 [검증 기록](../prototype/VERIFICATION.md), 진행 상태는 해당 Issue에서 확인한다. 장기 구상은 [프로젝트 README](../README.md), 첫 구현 상세는 [프로토타입 설계](prototype/README.md)를 따른다.

2026-10-17에 제공된 세 사용자 테스트·인터뷰는 [관찰 결과·백로그 근거](prototype/OBSERVATION_RESULTS.md)에 정리했다. 전체/부분 선택·설명 이해·복귀·확대 조작·질문 방식·비교 목적의 보완 근거로 사용한다. 후속 4차 Product Backlog와 개별 US에서 개발 범위·우선순위·상대 추정·Sprint 배치·DoD를 작성·검수했다. 프로토타입의 준비된 사진 목록을 실제 제품 요구사항으로 고정하지 않으며, 계획의 작성과 실제 기능 구현·성능 검증을 구분한다.

## 사용자와 문제

경복궁을 가이드 없이 둘러보는 방문객이 눈앞 건물과 문양·구조물 같은 특정 부분의 이름·의미를 알아보는 과업을 다룬다. 이름을 모르거나 검색이 번거로우면 궁금해도 그냥 지나칠 수 있다. 첫 한국어 프로토타입 관찰을 국내·외 모든 방문객의 결과로 일반화하지 않는다.

기존 지도·검색·안내판·오디오가이드로 충분한 상황도 함께 확인한다. 기존 조사·경험 공유는 문제 이해에 참고하되, 이 서비스가 탐색 부담을 줄이고 관심을 높이는지는 아직 검증하지 않았다.

**주요 검토사항: 첫 진입에서 도움을 이해하고 첫 결과에 도달하는 경험.** 처음 쓰는 사람이 이 앱이 자신의 관람에 어떤 도움이 되는지, 무엇부터 하면 어떤 결과를 얻는지 이해하도록 한다. 참여자의 도움에 대한 의문과 제작자의 다른 관광앱 사용 회고를 [F10·B06 및 후속 UX 조사](prototype/OBSERVATION_RESULTS.md)에 연결했다. UX 연구·기업의 실제 흐름·공개 효과 데이터를 조사한 뒤 구체적인 UI를 정하며, 튜토리얼이나 시작 화면을 미리 필수 기능으로 확정하지 않는다. 첫 경험과 실제 재사용의 관계는 미검증이다.

[Product Backlog 4차 작성본 공개 요약](PRODUCT_BACKLOG_DRAFT.md)은 5개 Epic·12개 Story·전체 46 SP를 기준으로 한다. Must 39 SP는 Sprint 1에 17 SP, Sprint 2에 22 SP를 배치했고 Should 7 SP는 후순위 미배치다. SP는 가안이며 Sprint 0의 기술 검증과 이후 Review로 재검토한다. 공통 DoD는 채택됐지만 제품 Story의 실제 AC 통과·목표 달성·외부 제출은 별도 증거가 필요하다. 현재 수업 주차와 실제 Sprint 착수 여부도 구분한다.

## 첫 구현 단위

2026-10-17 변경: 먼저 하나의 모바일 앱을 만들고 같은 앱에서 시나리오 과제를 순서대로 관찰한다. 홈 상단 검색과 사진 탐색·공통 하단 이동·직전 화면 복귀를 제공하며, S1~S5가 콘텐츠·목적지를 잠그지 않는다. 이름·부분·단어 검색은 확보한7대상의 정적 설명 안에서 실제로 동작한다. 임의 사진 인식·외부 검색·자유 질문 답변 기능으로 설명하지 않는다.

보완 범위는 [개발 설계](prototype/FLOW_EXTENSION_DESIGN.md)를 따른다. 다른 사진으로 탐색을 이어가고 돌아오는 흐름·v2 계약·준비된 건물 후보 확인·고정 다음 관람·관련 질문 지원 한계를 구현했다. 실제 AI·검색·추천 기술의 구현이나 검증을 포함하지 않는다. 사람 관찰은 [실행 안내](prototype/OBSERVATION_RUNBOOK.md)의 시작 조건을 따른다.

단순한 홈 → 준비된 장면에서 건물 전체 또는 관심 부분 지정 → 명칭·짧은 설명·출처 → 필요하면 관련 질문 선택.

- 준비된 사진은 촬영 입력을 대신하는 테스트 장면이다. 사진 갤러리에서 정답을 찾는 별도 과업을 추가하지 않는다.
- 건물 전체와 문양·구조물 탐색을 각각 관찰한다. 후보 비교는 선택이 모호할 때만 제공한다.
- 홈에는 주요 행동 하나와 호기심 카드 최대 하나를 둔다. 카드도 같은 설명 화면으로 연결한다.
- 대상 수정, 해당 없음, 준비된 질문 없음, 자료 누락에서 돌아갈 수 있어야 한다.
- 방문 전 예시와 관람 구역 맥락은 준비된 설정으로 모사한다. 사전 연결 자료를 인식·GPS 성능처럼 표현하지 않는다.

현재 프로토타입은 모바일 웹과 HTML/CSS/JavaScript로 구현한다. 구체적인 사진·부분·설명은 [콘텐츠 계약](prototype/DATA.md)의 검수 조건으로 선정한다. 화면·자료·작업 분할은 상세 설계, 수용 범위·진행 상태는 연결된 기능 Issue, 변경·검증 증거는 PR에서 관리한다.

## 이번 범위 밖

자동 사진 인식, 자유 사진 업로드·촬영, 실제 위치 권한, 전체 경복궁 대상 검색·지도 탐색, 길찾기, 자유 질문 입력·LLM, 음성·다국어, 계정·설치 유도는 후속 범위다. 준비된 자료 안의 이름·단어 검색은 현재 범위다. 전국 지원, 실내 정밀 위치 추정, AR, 자동 일정 생성도 현재 요구사항으로 확정하지 않았다.

## 확인할 질문

1. 이름을 모르더라도 건물 전체 또는 궁금한 부분을 지정할 수 있는가?
2. 잘못 선택하면 고칠 수 있고, 어떤 대상을 설명하는지 이해하는가?
3. 기본 설명·관련 질문이 실제 궁금증에 답하는가? 무엇이 빠져 있는가?
4. 카드가 선택적으로 관심을 끄는가? 탭 이후 실제 장면을 다시 살피는가?

동작 확인은 [QUALITY](QUALITY.md), 화면 규칙은 [DESIGN](DESIGN.md), 모의 관찰은 [TESTING](prototype/TESTING.md)에 따른다. 사용자 관찰 결과와 다음 우선순위는 Issue에 기록한다. 소수 관찰에서 기존 방식 대비 개선 수치나 일반 제품 효과를 주장하지 않는다.

## 자료 취급

대상 자료에는 식별자, 명칭, 설명, 출처 URL과 확인일을 연결한다. 사진에는 출처와 이용 가능 조건을 기록한다. 언어·좌표 등 후속 기능에 필요한 항목은 그 범위를 정할 때 추가한다.

공개 문서·데이터에는 개인 식별 정보, 인증정보, 원본 제출 자료를 포함하지 않는다. 실제 사용자 사진·위치의 전송·보관·삭제 방식은 해당 기능 도입 전에 결정한다. 확인할 수 없는 설명은 임의로 생성해 채우지 않는다.
