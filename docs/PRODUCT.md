# 제품 목표와 첫 검증 범위

상태: 첫 프로토타입 범위 초안. 구현과 사용자 검증은 아직 하지 않았다. 장기 구상은 [프로젝트 README](../README.md)에 남아 있으며, 이번 구현 범위는 이 문서가 기준이다.

## 사용자와 문제

낯선 관광지를 가이드 없이 둘러보는 방문객이 눈앞 대상의 이름과 의미를 확인하는 과업을 다룬다. 대상 이름을 모르면 검색을 시작하기 어렵고, 후보와 실제 대상을 맞춰 보거나 설명을 찾는 과정에서 다른 서비스로 이동해야 할 수 있다.

기존 지도·검색·안내판·오디오가이드로 충분한 상황도 함께 확인한다. 문제와 개선 효과는 가설이며, 모든 관광객에게 일반화하지 않는다.

## 첫 구현 단위

준비된 사진 선택 → 후보 비교 → 대상 선택 → 명칭·짧은 설명·출처 확인.

- 준비된 사진과 사전 연결한 후보로 사용 흐름을 먼저 검증한다.
- 후보 비교에 필요한 명칭·이미지를 보여주고, 사용자가 선택한 대상의 설명을 연결한다.
- 후보 선택을 바꾸면 새 대상의 설명을 보여준다.
- 사전 연결 데이터 사용 사실을 밝힌다. 이 흐름의 성공을 사진 인식 정확도의 증거로 사용하지 않는다.

대상 관광지는 최신 프로젝트 README의 경복궁 방향을 따른다. 첫 명세에는 지원 사진·건물 목록, 설명 출처, 후보를 구분할 단서, 완료 기준을 구체화한다. 구체적인 목록과 정식 플랫폼·기술 스택은 아직 미정이다. README의 HTML/CSS/JavaScript 계획은 클릭형 프로토타입의 계획이며 실제 구현을 뜻하지 않는다.

## 이번 범위 밖

자동 사진 인식, 자유 사진 업로드·촬영, 위치 권한, 검색·구역 탐색, 지도·길찾기, 다국어 확장, 현장 방향 안내는 후속 범위다. 전국 지원, 실내 정밀 위치 추정, AR, 자동 일정 생성도 현재 요구사항으로 확정하지 않았다.

## 확인할 질문

1. 사용자가 준비된 사진에 맞는 후보를 비교하고 선택할 수 있는가?
2. 다른 후보로 선택을 바꿀 수 있고, 어떤 대상을 설명하는지 이해하는가?
3. 설명과 출처가 궁금증을 해소하는 데 도움이 되는가?
4. 기존 검색·안내와 비교했을 때 어떤 이점과 불편이 있는가?

동작 확인은 [QUALITY](QUALITY.md), 화면 규칙은 [DESIGN](DESIGN.md)에 따른다. 사용자 관찰 결과와 다음 우선순위는 Issue에 기록한다. 비교 조건과 기준선 없이 개선 수치나 제품 효과를 주장하지 않는다.

## 자료 취급

대상 자료에는 식별자, 명칭, 설명, 출처 URL과 확인일을 연결한다. 사진에는 출처와 이용 가능 조건을 기록한다. 언어·좌표 등 후속 기능에 필요한 항목은 그 범위를 정할 때 추가한다.

공개 문서·데이터에는 개인 식별 정보, 인증정보, 원본 제출 자료를 포함하지 않는다. 실제 사용자 사진·위치의 전송·보관·삭제 방식은 해당 기능 도입 전에 결정한다. 확인할 수 없는 설명은 임의로 생성해 채우지 않는다.
