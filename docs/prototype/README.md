# 시나리오 기반 프로토타입 설계안

문서 버전: 0.1 · 작성일: 2026-10-14 · 상태: 구현 전 검토안.

설계 조사 기준: `main`, `2c350649260a480864b754178ac0976356c961aa`. 이 커밋에는 아래 설계와 앱 코드가 들어 있지 않다. 인계할 때는 설계가 포함된 실제 커밋 또는 같은 checkout의 미커밋 파일을 함께 전달한다.

## 1. 이번에 만들 것

**경복궁 장면을 보며 건물 또는 특정 부분에 생긴 궁금증을 표현하고, 그 대상에 맞는 짧은 설명을 읽는 모바일 웹 프로토타입.** 준비된 소수 장면 안에서 실제로 누르고, 선택을 수정하고, 질문하고, 되돌아가는 경험을 만든다. 자동 인식·생성 답변·실제 위치 추적은 이번 구현에 넣지 않는다.

관람 전에는 예시를 열어보고, 관람 중에는 같은 화면 구조에서 현재 구역의 내용을 보는 경험을 모사한다. 첫 홈은 주요 행동 하나와 호기심 카드 최대 하나로 구성한다. 두 진입 경로 모두 같은 대상·설명 화면을 사용한다.

```text
홈 ─ 궁금한 부분 알아보기 → 전체/문양·구조물 지정 → 이름·기본 설명
  └ 호기심 카드 ────────────────────────────────→ 설명
                               ↑                    │
                               └─ 대상 수정          └→ 관련 질문 → 답변
```

이 설계의 목적은 제한된 장면에서 사용 흐름을 관찰하는 것이다. 인식 정확도, 자유 질문 자동 응답, 설치·재방문율, 문화 관심 증가, 현장 위치 안내 효과는 별도 검증이 필요하다.

## 3. 결정 수준

| ID | 내용 | 상태 / 구현에 미치는 영향 |
| --- | --- | --- |
| D01 | 경복궁의 건물과 선택된 세부 요소에 대한 궁금증을 다룬다. | 대화에서 확인한 방향. 전체 궁궐 지원은 아님 |
| D02 | 상황을 준비하고 사용 흐름을 관찰한다. 실제 AI 전체 구현은 뒤로 둔다. | 대화에서 확인한 방향 |
| D03 | 궁금한 대상을 직접 알아보는 진입을 중심에 두고 작은 호기심 카드도 살핀다. 홈은 단순하게 유지한다. | 대화에서 확인한 방향. 카드 문구·배치는 시안 제안 |
| D04 | 방문 전 체험과 현장 재진입에 같은 화면 구조를 사용한다. | 채택하려는 방향. 재방문 효과는 미검증 |

| D07 | 전체 또는 부분을 선택하면 이름·짧은 설명을 먼저 보여주고, 원하면 관련 질문을 고른다. | 최신 사용자 답변을 반영한 범위. 자유 입력은 후속 검토 |
| D08 | 기존 AI Workflow의 Issue·PR 기록을 사용하고 환경 설정 채팅에도 전달한다. | 사용자 요청 확인. 게시·전달 완료 여부는 실제 링크로 기록 |
| D09 | 실제 장면 3개 내외, 건물·세부 요소를 합쳐 지원 대상 3~5개, 설명 4~6개로 제한한다. | 콘텐츠 준비량 제안. 대상 이름·사진·사실 설명은 자료 검수 후 결정 |
| D10 | 한 명의 진행자와 한 명의 첫 사용 관찰 참여자로 리허설한다. | 현재 가능한 조건. 모집단 성공률을 산출할 표본이 아님 |

미정 사항은 구체적인 사진·해설 자료, 시각 토큰, 실행 환경과 실제 테스트 기기다. 각각 P01/P06, P02, P07에서 확인한다. 제안은 승인된 작업의 구현자가 선택 근거를 남기고 작게 조정할 수 있으나, 제품 범위나 관찰 목적을 바꾸는 결정은 사용자에게 확인한다.

## 5. 실제로 동작할 것과 모사할 것

| 실제 구현 | 모사 / 제한 |
| --- | --- |
| 모바일 화면 이동, 대상 지정, 수정, 질문 표현, 설명·출처 표시 | 사진은 선정한 장면만 사용 |
| 장면 속 부분을 누르거나 텍스트 대안으로 선택 | 선택 좌표는 준비된 영역에만 연결. 이미지 모델 없음 |
| 답변 없음·대상 불일치·뒤로 가기 | 입력 질문의 의미를 자동 판별하지 않음 |
| 방문 전/구역 맥락에 따른 카드 표시 | 구역은 진행자가 사전 설정. 위치 권한 요청 없음 |
| 준비된 관련 질문·설명 또는 지원하지 않음 표시 | 목록 밖의 자연스러운 질문은 관찰자가 별도 기록 |

로그인, 계정, 설치 유도, QR 제작·현장 부착, 지도·동선, 실시간 카메라, 자유 사진 업로드, 다국어, 음성 입력·TTS, 서버·DB, 모델/API 연결, 자동 추천 최적화, 행동 분석 SDK는 제외한다.

## 6. 단계와 종료 조건

1. **설계 확정:** 기본 설명→관련 질문과 부분 탐색을 기준으로 상세 설계·작업 분할을 검토한다. 실제 자료 확보는 P01부터 시작한다.
2. **첫 작동 흐름:** 지원 장면 하나로 홈 → 지정 → 설명 → 수정이 실제 브라우저에서 된다. 개발 중 자료 자리표시자는 명확히 표시한다.
3. **관찰 가능한 버전:** 세 상황, 실패·복구, 검수된 사진·설명, 실행 안내가 준비되고 F01~F13을 점검한다. 사용자 관찰에는 자리표시자 자료를 사용하지 않는다.
4. **모의 관찰:** S1~S3을 진행하고 개입·미지원·중단을 포함한 사실을 기록한다. 관찰 사실과 제품 해석을 분리한다.
5. **다음 판단:** 무엇을 바꿀지 또는 어떤 실제 기능이 필요한지 후속 Issue로 결정한다. 현장 방문은 검증할 버전을 고정한 뒤 별도 계획한다.

이 설계 문서가 완성되었다는 것은 앱·사용성 검증이 완료되었다는 뜻이 아니다.

## 7. 설계 근거와 한계

- 질문 중심 안내를 다룬 [가상 박물관 연구](https://arxiv.org/abs/1902.03527)는 질문 제시 방식에 따라 결과가 달라질 수 있음을 보여준다. 가상 환경의 결과를 경복궁 현장 효과로 옮겨 주장하지 않는다. 여기서는 카드 수를 제한하고 강제 노출보다 선택 가능한 진입을 시험한다는 설계 참고로 사용한다.
- [Digital Exhibit Labels in Museums](https://tidal.northwestern.edu/media/files/pubs/pn4758-robertsA.pdf)는 화면 상호작용 증가와 해석·호기심의 대화가 같은 지표가 아님을 보여준다. 그래서 카드 탭과 실제 장면 재관찰·후속 질문을 따로 기록한다.
- [위치 기반 박물관 가이드의 능동성·선택 연구](https://www.sciencedirect.com/science/article/pii/S0953543811000567)는 사용자의 통제감을 고려하게 한다. 자동 알림보다 홈에서 무시할 수 있는 카드로 시작하는 것은 이 프로젝트의 제안이다.

기존 자료 조사와 비공식 경험 공유는 문제를 이해하는 참고이며, 이번 프로토타입의 개선 효과를 입증한 실험은 아니다. 방문 전 유입과 현장 재방문은 장기 흐름이며 첫 관찰에서는 전달받은 링크로 시작한다. 유입 경로·설치 전환·재방문은 별도의 실사용 조사에서 확인한다.
