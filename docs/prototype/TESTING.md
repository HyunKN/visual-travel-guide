# 모의 관람 시나리오와 관찰 계획

설계 추가(미구현·미관찰): [보완 개발 설계 8·9절](FLOW_EXTENSION_DESIGN.md)에 후보 비교 S4, 설명 이후 행동, G01~G10 기능 조건을 정의했다. 아래 S1~S3 관찰은 유지하며, 추가 상황은 해당 구현·자료 검수가 끝나야 시행한다. 자유 질문 앱·진행자 응답 서비스·기존 방식 대비 성능 비교·기술 PoC를 이번 관찰 준비의 필수 조건으로 추가하지 않는다.

상태: 사람 관찰 전 계획. 현재 앱의 기능 검사·환경·남은 항목은 [검증 기록](../../prototype/VERIFICATION.md)에 있다. 자동 브라우저 검사가 성공해도 사람의 궁금증이 해소되었다고 판정하지 않는다.

## 1. 이번 관찰의 질문

1. 이름을 모르는 건물에서도 사용자가 알아보기를 시작하고 설명 대상을 이해하는가?
2. 건물 속 문양·구조물을 스스로 탐색해 지정하고, 잘못 고른 부분을 고칠 수 있는가?
3. 짧은 설명과 관련 질문 중 무엇이 실제 궁금증에 답하고 무엇이 부족한가?
4. 홈의 카드가 선택적으로 관심을 끄는가? 카드 탭 뒤 실제 장면을 다시 살피거나 후속 질문이 생기는가?

관찰 목적은 문제를 찾고 다음 설계를 정하는 것이다. 성공률 목표 85%, 시간 단축 30% 등 장기 README의 목표치를 이번 소규모 관찰 통과 기준으로 사용하지 않는다.

## 2. 환경과 사전 준비

- 진행자 1명, 첫 사용 관찰 참여자 1명을 기본으로 한다. 설계를 아는 제작자의 리허설은 첫 사용 결과와 분리한다.
- 큰 화면·인쇄 사진·영상 중 하나로 경복궁 장면을 보여주고 참여자는 스마트폰으로 프로토타입을 사용한다. 화면 앞에서 서서 보거나 실제 주변을 살펴보는 동작은 선택적으로 모사한다.
- 관찰 장면과 앱에 준비된 사진이 같은 곳을 보여준다는 점을 설명한다. 앱 사진은 촬영 입력을 대신한 것이다. 갤러리에서 정답 사진을 찾는 과업을 추가하지 않는다.
- 사용 기기·OS·브라우저, 앱 커밋, contentVersion, 선택 preset, 입력 방식, 큰 화면 자료, 실행 환경을 먼저 기록한다.
- 사진·설명 검수 완료와 F01~F13의 필수 동작 확인 후 사람 관찰을 시작한다. 앱 장애가 뚜렷하면 사용자 문제로 분류하지 않는다.
- 관찰 메모 여부·목적을 설명하고 동의를 받는다. 녹음·영상은 기본으로 하지 않는다. 공개 기록은 익명 요약만 남기고 이름·원본 발화·화면 속 개인정보를 올리지 않는다. 별도 원본 기록을 만들면 저장 위치·삭제 시점을 미리 정한다.
- 시간 예산 제안: 안내 3분, 장면 3개 각 4~6분, 회고 5분. 제한 시간은 성공 기준이 아니며 피로·의사에 따라 중단한다.

### 시작 안내 예문

> 이건 준비된 경복궁 사진과 설명을 사용한 프로토타입입니다. 자동 사진 인식이나 현재 위치 확인은 하지 않습니다. 사용 방법에서 어렵거나 불필요한 점을 보려는 테스트예요. 궁금한 점이 없거나 더 쓰고 싶지 않으면 넘어가도 됩니다. 원하는 방식으로 써보고, 막히는 순간을 알려주세요.

버튼 이름이나 정답 대상의 고유명칭은 시작 안내에서 먼저 말하지 않는다.

### 세 대상의 배치 제안

근정전·경회루·자경전 십장생굴뚝은 모두 준비한다. 다음 배치는 사진·설명 검수 전 제안이며, 한 대상에서 사용할 전체·부분 사진이 여러 장일 수 있다. 사진 후보와 촬영일 기준은 [DATA](DATA.md)를 따른다.

| 관찰 | 대상·장면 제안 | 확인하려는 행동 |
| --- | --- | --- |
| S1 / C01 | 경회루 전경 | 이름을 모르는 건물 전체를 알아보고 짧은 설명·출처를 확인 |
| S2 / C02 | 근정전과 앞마당, 필요하면 가까운 구도로 별도 리허설 | 스스로 관심 부분을 발견·지정. 바닥·난간·돌 조각 중 사진과 설명 검수가 끝난 부분을 지원 |
| S3 / C03 | 앞선 두 과업에서 보여주지 않은 자경전 십장생굴뚝 | 선택적인 호기심 카드에서 설명으로 들어가거나 무시하고, 이후 장면을 다시 살피는지 관찰 |

S2에서 굴뚝을 먼저 설명한 뒤 같은 굴뚝을 S3의 처음 발견한 대상으로 처리하지 않는다. 근정전의 다른 구도를 추가로 사용하는 경우 첫 시도의 자발적 탐색과 후속 지정 과업 결과를 구분한다. 굴뚝 사진에는 자경전 건물 전체가 보이지 않으므로 사진에 없는 건물을 선택 가능한 대상으로 만들거나 굴뚝을 건물로 소개하지 않는다. 설명 화면에서 대상 수정으로 돌아갈 때의 장면·선택 행동은 실제 자료에 맞춰 P06 통합 전 확인한다.

## 3. S1 — 건물 전체가 궁금한 상황

**준비:** C01, previsit 또는 현장 모사 preset 하나로 고정. 첫 시도는 카드가 꺼진 홈. 건물의 이름을 사전에 알려주지 않는다.

**중립적인 과업:**

> 이곳을 둘러보다 이 건물이 어떤 곳인지 궁금해졌다고 생각해 주세요. 이 화면으로 알아볼 수 있는지 해보세요.

**예상 가능 경로:** H → V → 건물 전체 → A. 이는 관찰자 참고이며 참여자에게 누를 순서로 읽어주지 않는다. 텍스트 대안이나 다른 행동을 선택해도 기록한다.

**볼 것:** 시작 행동의 발견, 사진과 실제 장면의 연결 이해, 부분/전체 구분, 설명 대상 확인, 읽고 싶은 양, 출처 확인 방식.

**끝난 뒤 확인:** “무엇에 대한 설명이었나요?”, “알고 싶었던 것에 어느 정도 답이 됐나요?”, “아직 남은 궁금증이 있나요?”

**결과 구분:** 독립 완료 / 단서 후 완료 / 일부만 해결 / 다른 대상 설명을 읽음 / 중단. 참여자가 읽기를 끝냈다고 버튼을 눌렀다는 이유만으로 의미 이해를 성공 처리하지 않는다.

## 4. S2 — 문양·구조물 탐색과 부분 질문

**준비:** C02, 아직 보지 않은 세부 요소가 있는 장면. 사진에 정답 테두리·화살표·대상 이름을 미리 표시하지 않는다. 지원 부분 최소 1개와 인접한 미지원 영역을 포함한다.

### S2-a: 관심 부분을 스스로 찾기

> 사진을 잠깐 둘러보세요. 건물이나 주변에서 더 알아보고 싶은 부분이 있으면 이 화면으로 살펴봐 주세요. 없으면 없다고 해도 됩니다.

참여자가 문양·구조물을 고르면 어디인지, 무엇이 궁금한지 먼저 듣는다. 새로운 관심이 없으면 그대로 기록한다. 진행자가 “문양이 신기하지 않나요?”라고 유도하지 않는다.

**경로:** H → V → 부분 지정·미리보기 → A → 필요 시 Q의 준비된 질문 → A. 건물 전체 설명에만 도달한다면 부분 선택 기능을 몰랐는지, 관심이 전체에 있었는지 구분한다.

**볼 것:** 이름 없이 부분을 지정하는 방식, 터치 의도와 선택 영역의 일치, 전체 설명 대신 해당 부분 설명이 나오는지, 원래 궁금증과 준비된 질문의 관계.

결과를 ① 원하는 부분을 지정했는지 ② 그 부분이 콘텐츠 지원 범위였는지 ③ 제공된 설명이 궁금증에 답했는지로 나눠 기록한다. 미지원 부분에 관심을 보인 것은 지정 실패나 관심 유도 실패와 같지 않다.

### S2-b: 지정 기능 확인용 보조 과업

자발적인 관심이 없거나 미지원 부분만 고른 경우에만, 자발적 관심 관찰을 끝낸 뒤 시행한다.

> 이 부분의 이름이나 쓰임을 이 화면으로 알아볼 수 있는지 해보세요.

진행자는 사진의 지원 부분을 가리킬 수 있다. 이 결과는 **지정된 과업의 사용성**이며 자발적 발견·관심의 증거로 사용하지 않는다. S2-a와 분리해 기록한다.

### S2-c: 수정·미지원 확인

자연스럽게 다른 대상이 선택되거나 미지원 질문이 생겼으면 그 경로를 관찰한다. 그런 상황이 없었다면 주 과업 뒤 별도 기능 확인으로 진행한다. 오류를 몰래 주입하지 않는다.

> 방금 선택한 곳이 원래 궁금했던 부분과 다르다면 어떻게 바꾸겠어요?

미지원 부분에서 사용자가 계속 원하는 대상을 표현할 수 있는지, ‘해당 없음’을 고를 수 있는지, 전체 건물로 강제로 몰리지 않는지 확인한다. 준비된 질문에 없는 궁금증은 진행자가 메모하며, 임의 설명으로 해결 처리하지 않는다.

## 5. S3 — 질문 없이 둘러보는 중 호기심 카드

**준비:** C03, 앞선 과업과 다른 대상. 카드 1개가 있는 홈. 위치는 사전 설정한 구역으로 모사하고 테스트 안내에 명시한다.

**중립적인 과업:**

> 이번에는 특별히 찾아볼 질문 없이 이 주변을 둘러보고 있다고 생각해 주세요. 화면을 자유롭게 봐도 되고 그냥 지나가도 됩니다.

`카드를 눌러보세요`라고 말하지 않는다. 카드를 무시하거나 앱을 닫는 것도 결과다.

**볼 것:** 카드 발견/무시, 본문을 열게 한 요소, 주요 행동 방해 여부, 카드→설명 대상 일치, 설명 후 장면 재관찰, 새 질문, 관심 없음.

**끝난 뒤 확인:** “눈에 들어온 것이 있었나요?”, “화면을 본 뒤 사진에서 다시 찾아본 부분이 있나요?” 클릭만으로 문화 관심이 높아졌다고 해석하지 않는다.

S1→S2→S3 순서는 준비된 질문이 앞선 자발적 질문을 유도하는 일을 줄이기 위한 선택이다. 순서·익숙해짐·대상 차이의 영향은 남는다. 같은 한 사람의 카드 on/off 차이를 A/B 효과나 시간 개선으로 계산하지 않는다.

## 6. 개입과 관찰 기록

처음에는 기다리고 관찰한다. 약 20~30초 멈춤은 질문할 수 있는 참고 시점이지 실패 판정선이 아니다. “지금 무엇을 하려던 건가요?”처럼 의도를 먼저 확인한다.

| 수준 | 진행자의 행동 | 결과 해석 |
| --- | --- | --- |
| I0 | 도움 없음 | 독립 수행 |
| I1 | 과업 재설명 또는 의도 질문 | 가벼운 개입을 명시 |
| I2 | 기능 위치·버튼 단서 제공 | 도움받은 수행 |
| I3 | 직접 조작·정답 대상 제시 | 독립 완료로 집계하지 않음 |

실제 기록은 관련 Issue의 익명 요약 또는 사용자와 합의한 비공개 관찰지에 둔다. 이 설계 문서에 사람별 진행 상황을 누적하지 않는다.

```text
실행 ID / 날짜 / 앱 커밋 / contentVersion / preset:
기기·OS·브라우저 / 큰 화면 자료 / 순서:
상황 ID / 자발적 과업인지 보조 과업인지:
원한 대상·질문(개인정보를 뺀 요약):
관찰한 행동 / 선택 경로 / 멈춘 지점:
개입 수준·내용:
결과: 독립 완료 / 도움 후 완료 / 일부 해결 / 미지원 / 중단 / 앱 오류
설명 이해·남은 질문:
시간(측정했다면 시작·종료 정의와 중단 포함):
사실 / 해석 / 다음 확인을 각각 분리:
후속 Issue 또는 다음 판단:
```

| F02 | 부분 영역 누르기, 여백 누르기, 화면 크기 변경 | 올바른 부분 미리보기 / 여백 무반응 / 같은 부분 유지 | 좌표 경계 검사 + 브라우저 |

| F08 | 카드 선택 | 카드 scene/target/question/answer와 동일한 설명 | 자료 검사 + 브라우저 |
| F09 | 화면 뒤로/브라우저 뒤로/홈/새로고침 | SCREENS 초기화 표와 일치 | 통합 브라우저 |
| F10 | 키보드만으로 전체·부분·관련 질문·복구 사용 | 모든 경로 접근, 포커스 식별·복귀 | 수동 키보드 |
| F11 | 좁은 화면·글자 확대·실제 스마트폰 | 버튼·설명 잘림 없음, 터치·스크롤·회전 가능 | 렌더링 + 실기기 별도 |
| F12 | previsit/구역 preset, 카드 없음 | 맥락 문구 변경, 가짜 GPS 없음, 카드 0~1 | 브라우저 |
| F13 | 잘못된 ID/누락 설명·출처/이미지 실패 | 원인별 복구, 허구 답변 없음 | 자료 검사 + 오류 fixture |

F09에는 `V → A(기본) → Q → A(질문) → 기본 설명으로 → 뒤로`, `H → A(카드) → Q → A(질문) → 뒤로 두 번`, 홈 초기화 뒤 브라우저 뒤로, 장면 교체 뒤 오래된 history 진입을 포함한다. 시간순 복귀와 무효화 규칙은 SCREENS를 따른다.

필수 회귀 자동화는 F01·F04·F08·F09와 잘못된 자료 참조에 우선한다. 단순 문구의 모든 줄을 단위 테스트로 복제하지 않는다. F02의 좌표 계산은 버그 위험이 있는 경계이므로 작은 순수 함수 검사로 검증해도 좋다. 전체 검사 목록을 여러 도구로 중복 실행할 필요는 없다.

## 8. 판정과 다음 단계

- **기능 준비 완료:** 필수 기능 확인이 통과하고 실제 기기 제한·콘텐츠 검수 상태가 기록됨. 에뮬레이션만 했다면 실제 스마트폰 통과로 표시하지 않는다.
- **첫 관찰 완료:** S1~S3의 시행 여부, 개입, 미지원·중단, 해석 제한이 기록됨. 관심 없음도 유효한 결과다.
- **수정 우선:** 다른 대상 답변, 빠져나올 수 없는 경로, 잘못된 문화유산 설명은 먼저 고친다. 표면 스타일보다 의도·대상·답변 연결을 먼저 확인한다.
- **후속 검증:** 자유 질문이 반복적으로 남으면 입력·LLM 필요성을 검토한다. 부분 지정이 어렵다면 촬영/크롭 UX를 시험한다. 카드가 방해되면 수·문구·위치를 고치거나 제거한다.
- **현장 방문:** 실제 관람 동선, 화면 반사, 한 손 조작, 통신, 위치/촬영을 별도 계획한다. 이번 모의 테스트가 현장 조건까지 검증한 것은 아니다.
