# 실제 앱 UI와 전통 굿즈 참고

조사일: 2026-10-14. 용도: 첫 프로토타입의 시각 설계 근거. 실제 앱의 공식 화면·사용 설명과 실제 판매 상품을 조사했다. 설치한 앱의 동작을 직접 테스트하거나 상품을 실물로 평가한 결과는 아니다.

합의 원본은 [DESIGN](../DESIGN.md), 기능·상태 원본은 [SCREENS](SCREENS.md), 제외 기준은 [ANTI_SLOP](ANTI_SLOP.md)다. 이 문서의 관찰과 적용 제안은 구분한다. 상품에 판매 페이지가 있다는 사실만으로 판매량·선호도·UI 효과가 검증됐다고 주장하지 않는다.

## 1. 확정한 방향과 남은 선택

**흰색 바탕, 둥글고 정돈된 실제 앱 UI, 기와 먹색·짙은 남색 중심, 작은 주홍 포인트(2026-10-16 사용자 선택).** 전통 건축·물건의 특징을 필요한 지점에 추려 넣는다. 누런 배경은 사용하지 않는다.

확정한 것은 위 방향이다. 아래 반경·간격·배치 수치는 다음 시안을 위한 제안이며 Apple에서 측정한 값이나 사용성 검증값이 아니다. 최종 화면·정확한 색상값·글꼴은 아직 선택하지 않았다.

## 2. 실제 앱에서 가져올 구조

### UI01 — Apple 사진 앱의 사진 보기와 Visual Look Up

- 원본: [Apple 공식 사용 안내](https://support.apple.com/en-euro/guide/iphone/iph21c29a1cf/27/ios/27), [공식 화면 이미지](https://ipcdn-web.apple.com/assets/v2/web/8d4fd202-0b1b-48e1-85ac-eff8ee1269ab).
- 확인: 공식 안내와 화면 이미지 직접 열람. 사진을 크게 보고, 정보 버튼에서 대상 정보를 열고 닫는 흐름이다. 사진 주변의 조작부는 원형·캡슐형으로 묶여 있다.
- 적용 제안: V는 사진을 중심에 두고 조작부를 주변에 정리한다. A에서도 어떤 부분을 선택했는지 사진으로 확인할 수 있게 한다.
- 적용 경계: 사진 보관함, 즐겨찾기, 편집·삭제 기능은 가져오지 않는다. 우리는 준비된 영역 선택이며 자동 인식 아이콘·반짝임을 표시하지 않는다. 사진 앱 전체의 큰 여백까지 그대로 복제하지 않는다.

### UI02 — Apple 사진 앱의 정보 패널

- 원본: [사진·비디오 정보 보기](https://support.apple.com/en-euro/guide/iphone/iph0edb9c18f/27/ios/27), [공식 화면 이미지](https://ipcdn-web.apple.com/assets/v2/web/010a8029-1bd8-4524-b395-9a6f1dc1c28d).
- 확인: 사진을 위에 유지하고 아래에서 정보를 읽는다. 관련 정보는 둥근 묶음과 행으로 정리되어 있다. 화면 이미지를 직접 열람했다.
- 적용 제안: A를 선택 사진 → 이름·짧은 설명 → 출처 → 관련 질문 순으로 구성한다. 모든 문장을 개별 카드로 나누지 않는다. 사진과 설명의 연결이 둥근 모서리보다 우선이다.
- 적용 경계: 메타데이터 표, 지도, 촬영 정보는 필요 없다. 하단 패널의 형태는 참고하지만 드래그 시트 구현은 별도 결정이다. 첫 버전은 페이지 내 고정된 정보 영역으로도 충분하다.

### UI03 — Apple 지도 앱의 장소 카드: 보조 조사

- 원본: [Apple 공식 장소 카드 안내](https://support.apple.com/en-ie/guide/iphone/iph6838243e8/ios), [Apple 공식 마케팅 이미지 지침 PDF](https://business.apple.com/partners/assets/image-best-practices.pdf).
- 확인: 공식 안내의 장소 카드와 관련 동작 설명을 읽었다. PDF는 열람 도구에서 문서가 확인됐으나 브라우저 화면 캡처에는 내용이 표시되지 않았다. 시각 검토 완료로 세지 않는다.
- 적용 후보: 장소의 정체와 행동을 묶는 구조. 상세 시각 근거는 UI01·UI02를 우선 사용한다. 우리 범위에 지도·길찾기·저장을 추가하는 근거는 아니다.

Apple은 콘텐츠와 조작부의 위계를 강조하고, 둥근 컨트롤과 그룹 구성을 설명한다. 우리는 이 원칙을 참고한다. Liquid Glass를 그대로 재현하는 결정은 하지 않았다. [Apple 공식 디자인 소개](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/).

## 4. 다음 시안의 화면별 뼈대

아래는 제안이다. SCREENS의 경로·지원 범위를 유지하며 시각 표현을 구체화한다.

| 화면 | 구성 제안 | 시각적 우선순위 |
| --- | --- | --- |
| H 홈 | 작은 경복궁 제목·현재 맥락, 짧은 안내, 대표 사진, 주요 행동, 호기심 카드 최대 하나 | 일반 390×844 화면에서 주요 행동이 첫 화면에 들어오도록 사진·제목 높이 조절. 홍보용 거대 제목 없음 |
| V 부분 선택 | 큰 사진, 누른 위치와 선택 테두리, 아래에 둥근 확인 영역과 크롭 미리보기 | 사진의 선택 부분을 가리지 않는다. 누르기 전 모든 정답 영역을 노출하지 않는다. 전체 건물 행동은 별도 유지 |
| A 설명 | 선택 크롭·명칭, 2~3문장 설명, 출처, 관련 질문 행 | 답을 먼저 읽게 하고 관련 질문은 보조 행동으로 낮춘다. 붉은 포인트를 필수 버튼에 경쟁적으로 쓰지 않는다 |

시작값 후보: 흰 배경 `#FFFFFF`, 보조 면은 무채색 또는 아주 옅은 차가운 회색. 큰 정보 영역 반경 20~24px, 작은 사진 12~16px, 주요 버튼은 캡슐형. 둥근 모서리를 맞추려고 사진의 중요 부분을 자르지 않는다. 원형 아이콘 버튼은 단독 뒤로·닫기 같은 짧은 조작에만 사용하고 접근 가능한 이름을 제공한다.

본문은 읽기 편한 고딕 계열 16~18px, 제목은 약 24~28px, 좌우 여백은 약 20px를 출발점으로 삼는다. 이 수치와 글꼴은 미확정이다. 플랫폼 기본 글꼴은 허용하며, ‘AI 같지 않게’ 보이려는 이유만으로 낯선 장식 글꼴을 넣지 않는다.

색 역할(2026-10-16 갱신): 주요 행동·선택은 먹청색, 보조 면은 흰색·무채색, 주홍은 작은 아이콘·문양 포인트에 사용한다. 연녹색·민트 UI는 제외한다. 이전 청록 중심 적용안은 대체했으며 상품 자체의 색 관찰은 참고 기록으로 유지한다. 최종 HEX는 원본 사진의 조명색을 그대로 추출해 확정하지 말고 대비를 확인해 결정한다. 본문과 배경은 최소 4.5:1을 목표로 확인한다. [WCAG 2.2 대비 기준 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). 현재 대비 검사·실기기 검증은 미실행이다.

## 5. 인계와 갱신

다음 시안에는 UI01/UI02와 G01/G02/G03 중 사용한 근거를 명시한다. 시안 선택 후 DESIGN에 정확한 토큰·적용 규칙을 기록하고 P02에서 구현한다. 자료를 추가할 때는 `ID / 원문 / 확인일 / 관찰한 특징 / 적용할 위치 / 피할 요소 / 열람 한계`를 남긴다.

초기 조사와 방향 합의 이후의 구현은 아래 추가 조사와 실제 파일에 연결한다. 참고 자료만으로 최종 시안 승인·현장 가독성 검증을 주장하지 않는다.

## 6. 2026-10-15 모바일 앱·모션 재설계 조사

사용자가 기존 화면의 단색 초록 버튼과 웹 안내 페이지 같은 구성을 수정하고, 큰 사진·전통 배색·Liquid Glass·탄성 반응·3D 이야기를 요청했다. 기존 문구와 S1~S3의 콘텐츠 연결은 유지한다. 홈은 큰 사진의 2안과 3D 이야기의 1안을 메뉴 또는 진행자 설정에서 비교한다. 아래 수치와 적용 방식은 구현 선택이다.
