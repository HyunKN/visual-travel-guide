# 관찰 실행 안내 — S1~S5

사용자가 읽고 작성할 때는 [HTML 테스트 안내와 기록지](TEST_GUIDE.html)를 사용한다. 브라우저에서 직접 열고 점선 안에 작성한 뒤 HTML로 저장하거나 인쇄할 수 있다. 이 Markdown은 개발·절차 관리용 원본이다.

목적: 준비된 사진·후보·질문으로 사용 흐름을 관찰하고 Product Backlog·User Story의 근거를 남긴다. 2026-10-17부터 하나의 앱에서 홈·로컬 검색·전체 사진 탐색·설명을 자유롭게 오가며 아래 과제 순서를 관찰한다. 실제 인식·GPS·촬영·외부 검색·LLM·추천 성능 검사가 아니다. 기능·기기 판정은 [검증 기록](../../prototype/VERIFICATION.md), 원칙은 [TESTING](TESTING.md), 빈 기록지는 [관찰 기록 양식](OBSERVATION_RECORD.md)을 따른다.

2026-10-17 현황: PC 첫 사용 협조자 R01, 방문을 가정한 스마트폰 사용자 R02, 환경 미기록의 세 번째 인터뷰 R03을 접수하고 [결과·백로그 근거](OBSERVATION_RESULTS.md)로 정리했다. 실제 참여 기록과 실기기 품질 통과는 다르다. 확대·선택 결과 가시성·하단 공간·선택 범위·질문과 비교 목적의 혼동은 보고·보충된 발견이며 수정 후 통과 결과가 아니다.

재사용 방법과 1차 조사 근거는 [QA 방법 원본](QA_METHOD.md), 사람이 읽는 버전은 [QA 방법 HTML](QA_METHOD.html)이다. 사용자 요청으로 HTML 테스트지는 날짜·참여자·기기, 자유 탐색, S1~S5, 마지막 의견의 8개 기록 칸으로 간소화했다. 시작 화면을 준비하는 경로와 목표만 보여주며, 상세 기능 검사·문제 재현·백로그 분류는 이 실행 안내와 QA 방법에서 별도로 관리한다. 이번에는 앱 내부 사진만 사용한다.

## 시작 조건

- R01·R02·R03 기록은 위 결과 문서를 따른다. 다음 회차는 접속·터치·스크롤·회전 상태부터 확인하며, 조작을 방해하는 문제가 있으면 기술 확인과 사용성 관찰 결과를 구분한다.
- 진행자1명·첫 사용 참여자1명. 제작자의 리허설과 첫 사용 관찰을 분리한다. 익명 요약 메모의 목적·동의를 먼저 확인하고 녹음/영상은 기본으로 하지 않는다.
- 앱 커밋과 `contentVersion=2026-10-16-scenes.3`, 기기/OS/브라우저, 사진형/3D형 홈·상황 순서·후보 순서를 기록한다. [P01 정답표](content-preparation/FACILITATOR.md)는 진행자만 확인한다.
- 외부 화면이나 인쇄 사진 없이 앱에 준비된 사진을 사용한다. S1/S2/S4의 사진을 미리 열어 주는 준비 도움과 이후 조작 도움을 구분한다. 앱 사진 고르기를 촬영·인식 성공으로 집계하지 않는다.
- 앱 홈에서 시작하고 과제마다 preset을 바꾸지 않는다. 같은 참여자 내 홈 이동·검색·사진 선택은 같은 실행이며 새로고침·새 테스트는 새 실행이다.
- `#test`는 진행자의 별도 글자 확대·자료 누락·불투명 재질 검사에만 쓴다. 보통 관찰에서는 설정 화면을 거치지 않는다. 홈의 작은 호기심 카드와 전체 사진 목록은 어느 과제에서도 열 수 있다.

## 실행·종료

저장소의 `prototype/`에서:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

일반 관찰 PC 주소는 `http://127.0.0.1:4173/`다. `#test`는 별도 기술 점검에만 사용한다. 개발 중에는 `npm.cmd run dev`와 5173을 사용한다. 종료는 해당 터미널 Ctrl+C다. 실제 시작 주소를 확인한다. 포트 충돌 시 기존 프로세스를 임의 종료하지 않고 실제 Vite 설정·출력에 따라 주소를 확인한다. 필요하면 `npm.cmd run preview -- --port 4174`로 별도 검사 서버를 연다.

## 다음 스마트폰 접속 확인 — LAN을 사용하는 경우

R02의 실제 스마트폰 사용 기록은 접수되었다. 아래는 선택적인 로컬 네트워크 접속 절차이며, R02가 이 절차를 사용했다고 확인한 기록이 아니다. 배포 주소를 사용하는 경우에는 해당 주소의 접근 가능 여부를 확인한다.

같은 신뢰하는 Wi-Fi의 스마트폰에서 접근하려면 PC에서 로컬 네트워크 제공을 선택적으로 시작해야 한다. loopback 주소는 스마트폰에서 PC를 가리키지 않는다.

1. PC의 일반 preview를 자신이 시작했다면 Ctrl+C로 종료한 뒤 `npm.cmd run preview:lan`을 실행한다. 이것은 `0.0.0.0`에 바인딩해 같은 네트워크에 정적 앱을 제공하는 명령이다. 이 작업에서는 실행하지 않았고 공개 배포·방화벽 변경도 하지 않았다.
2. Vite가 출력한 Network URL 또는 PC의 실제 LAN IPv4로 `http://<PC-LAN-IPv4>:4173/?preset=S1&design=photo`를 스마트폰에서 연다. 코드에 IP를 고정하거나 공용 기록에 개인 네트워크 주소를 올리지 않는다.
3. 사진 로드→전체/부분 터치→설명→뒤로→사진 확대/내부 스크롤→가로 회전→S4 후보/해당 없음→S5 다음 관람을 확인한다. 기종/OS/브라우저·실패 동작을 기록한다. iOS Safari의 유리 재질은 네이티브 Liquid Glass가 아니다.
4. 접속이 안 되면 같은 Wi-Fi/게스트 격리/VPN/포트 상태를 확인한다. 방화벽/공유기 설정은 자동 변경하지 않는다. 연결 실패를 사용성 실패로 집계하지 않는다.
5. 끝나면 해당 터미널 Ctrl+C. 스마트폰 확인 전에는 실기기 통과라고 표시하지 않는다.

## 상황 순서와 진행문

| 순서 | 준비와 중립적 진행문 | 관찰·기록 |
| --- | --- | --- |
| S1 | 진행자가 홈→사진으로 찾기→연못 앞의 장면까지 준비. 사진 선택 화면에서 ‘이 사진 속 건물의 이름과 어떤 곳인지 궁금해졌어요. 앱에서 알아봐 주세요.’ | 준비 도움과 이후 조작 도움, 대상·설명 이해. 출처·질문은 첫 시도 후 보조 점검 가능 |
| S2-a | 진행자가 홈→사진으로 찾기→넓은 앞마당의 장면까지 준비. 먼저 ‘사진을 보며 궁금한 부분이 있나요? 있다면 앱에서 알아봐 주세요.’ | 자발적 관심 대상/질문, 지정 시도, 미지원 영역도 그대로 기록 |
| S2-b | 자발적 관찰 뒤에만 바닥 등 준비된 부분을 지정해 알아보게 함 | 지정 과업임을 별도 기록. 전체·부분 수정, 질문0/1개·미지원 복구 |
| S3 | 굴뚝 카드가 있는 홈. ‘특별히 찾는 질문 없이 이 주변을 둘러본다고 생각하고 자유롭게 봐도, 지나가도 됩니다.’ | 카드 발견/무시, 본문을 연 이유, 사진 재관찰. 탭만으로 관심 증가라 하지 않음 |
| S4 | 진행자가 홈→사진으로 찾기→넓은 돌단 위 긴 전각까지 준비. ‘이 사진의 건물이 어떤 곳인지 궁금해졌어요. 화면의 사진과 특징을 비교해 확인해 주세요. 맞는 것이 없다고 생각하면 그렇게 선택해도 돼요.’ | 후보 순서 A사정전/B수정전 고정. 정답/선택 이유/확신을 분리. 자동 교정·확률·분석 없음 |
| S5 | 경회루 설명을 읽게 한 뒤 다음 행동을 기다림. 필요 시 ‘이제 무엇을 하려고 하나요?’ | 같은 사진/다른 대상/N/다음관람/종료 의도와 실제 이동. 이미 본 수정전의 최초 발견 효과로 해석하지 않음 |

시나리오 순서는 S1→S2→S3→S4→S5로 제안하지만 앱이 기능·사진을 잠그지 않는다. 참여자가 다른 대상으로 이동하면 막지 않고 경로·사전 노출을 기록한다. S5에서 수정전을 이미 보았으면 최초 발견 효과로 해석하지 않는다. 순서·학습·대상 차이의 영향은 남는다.

후보 재비교/해당 없음/새 탐색을 자연스럽게 사용하지 않았다면 자유 행동을 마친 뒤 보조 과업으로 확인한다. 자발적 발견과 지시받은 수행을 합치지 않는다. 사진 출처를 열어 건물명을 읽었거나 현판/계절로 골랐다면 그 선택 이유를 그대로 기록한다. 정확한 칸수 세기나 작은 한자 현판 독해를 필수 성공 기준으로 삼지 않는다.

질문은 준비된 목록을 선택한다. 진행자는 설명 전 궁금증·설명 후 남은 점을 듣고 기록할 수 있지만 즉석 검색·자유 답변으로 성공을 만들지 않는다. 내용이 없으면 미지원으로 남긴다. 중단·관심 없음도 결과다.

## 종료와 백로그 반영

개입은 I0도움없음/I1과업 재설명·의도 확인/I2위치·단서 제공/I3직접 조작·정답 제시로 구분한다. 약20~30초 망설임은 의도를 물을 참고 시점이며 실패 제한시간이 아니다.

간단 HTML에서는 도움을 줬다면 각 과업 메모에 한 줄 남긴다. 결과 분석 시 이 기록을 I0~I3와 연결하며, 직접 순서를 알려 준 수행도 I3에 포함한다. 이름 검색·질문 미지원·사진 실패 등 추가 기능 검사는 제작자가 별도로 진행하고 일반 체험에 몰래 섞지 않는다.

기록지의 관찰 사실→해석→유지/수정/보류→User Story/AC→미검증 사항을 연결한다. 한 명의 관찰로 성공률·시간 단축·AI 정확도·문화 관심 증가를 주장하지 않는다. 기존 제품 요구도 관찰하지 않았다는 이유만으로 백로그에서 삭제하지 않는다. 익명 회차 요약은 [기존 P08 Issue](https://github.com/HyunKN/visual-travel-guide/issues/13)에 모으며 발견 항목마다 새 Issue를 만들지 않는다. 실제 참여 전에는 기록지를 결과로 채우거나 P08을 완료 처리하지 않는다.
