# 관찰 실행 안내 — S1~S5

목적: 준비된 사진·후보·질문으로 사용 흐름을 관찰하고 Product Backlog·User Story의 근거를 남긴다. 실제 인식·GPS·촬영·검색·LLM·추천 성능 검사가 아니다. 기능·기기 판정은 [검증 기록](../../prototype/VERIFICATION.md), 원칙은 [TESTING](TESTING.md), 빈 기록지는 [관찰 기록 양식](OBSERVATION_RECORD.md)을 따른다.

## 시작 조건

- 현재 판정은 PC/브라우저 에뮬레이션 리허설 준비이며 실제 스마트폰·사용자 최종 콘텐츠 확인·참여자 관찰은 별도다. 스마트폰 관찰은 아래 접속·터치·스크롤·회전 확인 후 시작한다.
- 진행자1명·첫 사용 참여자1명. 제작자의 리허설과 첫 사용 관찰을 분리한다. 익명 요약 메모의 목적·동의를 먼저 확인하고 녹음/영상은 기본으로 하지 않는다.
- 앱 커밋과 `contentVersion=2026-10-16-scenes.3`, 기기/OS/브라우저, 사진 표시 방식·순서·후보 순서를 기록한다. [P01 정답표](content-preparation/FACILITATOR.md)는 진행자만 확인한다.
- 큰 화면에 같은 장면을 준비한다. 사진이 촬영 입력을 대신한다는 것을 안내하며 앱 사진 고르기를 검색/촬영 성공으로 집계하지 않는다.
- 매 상황 전에 `#test`를 열어 preset을 고르고 오류=정상, 글자=기본, 재질=기본을 선택해 ‘새 테스트 시작’. 같은 참여자 내 홈 이동은 초기화가 아니다. 새로고침·새 테스트는 새 실행이다.
- preset 변경 시 기본 맥락·카드를 함께 맞춘다. S1은 방문 전·카드없음, S2/S4/S5는 구역·카드없음, S3은 구역·카드있음이다. 별도 맥락/카드 변형은 주 관찰 뒤 보조 리허설로만 사용한다.

## 실행·종료

저장소의 `prototype/`에서:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

PC 주소는 `http://127.0.0.1:4173/?preset=S1&design=photo#test`다. 개발 중에는 `npm.cmd run dev`와 5173을 사용한다. 종료는 해당 터미널 Ctrl+C다. 실제 시작 주소를 확인한다. strictPort가 켜져 있어 포트 충돌 시 기존 프로세스를 임의 종료하지 않는다. 필요하면 `npm.cmd run preview -- --port 4174`로 별도 검사 서버를 연다.

## 스마트폰 접속 확인 — 아직 미실행

같은 신뢰하는 Wi-Fi의 스마트폰에서 접근하려면 PC에서 로컬 네트워크 제공을 선택적으로 시작해야 한다. loopback 주소는 스마트폰에서 PC를 가리키지 않는다.

1. PC의 일반 preview를 자신이 시작했다면 Ctrl+C로 종료한 뒤 `npm.cmd run preview:lan`을 실행한다. 이것은 `0.0.0.0`에 바인딩해 같은 네트워크에 정적 앱을 제공하는 명령이다. 이 작업에서는 실행하지 않았고 공개 배포·방화벽 변경도 하지 않았다.
2. Vite가 출력한 Network URL 또는 PC의 실제 LAN IPv4로 `http://<PC-LAN-IPv4>:4173/?preset=S1&design=photo`를 스마트폰에서 연다. 코드에 IP를 고정하거나 공용 기록에 개인 네트워크 주소를 올리지 않는다.
3. 사진 로드→전체/부분 터치→설명→뒤로→사진 확대/내부 스크롤→가로 회전→S4 후보/해당 없음→S5 다음 관람을 확인한다. 기종/OS/브라우저·실패 동작을 기록한다. iOS Safari의 유리 재질은 네이티브 Liquid Glass가 아니다.
4. 접속이 안 되면 같은 Wi-Fi/게스트 격리/VPN/포트 상태를 확인한다. 방화벽/공유기 설정은 자동 변경하지 않는다. 연결 실패를 사용성 실패로 집계하지 않는다.
5. 끝나면 해당 터미널 Ctrl+C. 스마트폰 확인 전에는 실기기 통과라고 표시하지 않는다.

## 상황 순서와 진행문

| 순서 | 준비와 중립적 진행문 | 관찰·기록 |
| --- | --- | --- |
| S1 | 경회루 사진. ‘이곳을 보다가 어떤 건물인지 궁금해졌다고 생각해 주세요. 이 화면으로 알아볼 수 있는지 해보세요.’ | 시작 행동, 대상 이해, 설명/출처, 원래 궁금증과 해소. 다음 행동은 우선 기다림 |
| S2-a | 근정전 사진. 먼저 ‘이 장면을 보며 무엇이 궁금한가요?’라고 묻고 특정 부분을 가리키지 않음 | 자발적 관심 대상/질문, 지정 시도, 미지원 영역도 그대로 기록 |
| S2-b | 자발적 관찰 뒤에만 바닥 등 준비된 부분을 지정해 알아보게 함 | 지정 과업임을 별도 기록. 전체·부분 수정, 질문0/1개·미지원 복구 |
| S3 | 굴뚝 카드가 있는 홈. ‘특별히 찾는 질문 없이 이 주변을 둘러본다고 생각하고 자유롭게 봐도, 지나가도 됩니다.’ | 카드 발견/무시, 본문을 연 이유, 사진 재관찰. 탭만으로 관심 증가라 하지 않음 |
| S4 | 입력 사진. ‘이 건물이 무엇인지 화면의 사진과 특징을 비교해 확인해 보세요. 맞는 것이 없다고 생각하면 그렇게 선택해도 됩니다.’ | 후보 순서 A사정전/B수정전 고정. 정답/선택 이유/확신을 분리. 자동 교정·확률·분석 없음 |
| S5 | 경회루 설명을 읽게 한 뒤 다음 행동을 기다림. 필요 시 ‘이제 무엇을 하려고 하나요?’ | 같은 사진/다른 대상/N/다음관람/종료 의도와 실제 이동. 이미 본 수정전의 최초 발견 효과로 해석하지 않음 |

S1/S2는 C01/C02만, S3은 기존 세 장면만 허용하므로 굴뚝과 후보 정답의 사전 노출을 줄인다. S4 전 C04~C06을 따로 보여주지 않는다. S5는 S4 이후다. 순서·학습·대상 차이의 영향은 남는다.

후보 재비교/해당 없음/새 탐색을 자연스럽게 사용하지 않았다면 자유 행동을 마친 뒤 보조 과업으로 확인한다. 자발적 발견과 지시받은 수행을 합치지 않는다. 사진 출처를 열어 건물명을 읽었거나 현판/계절로 골랐다면 그 선택 이유를 그대로 기록한다. 정확한 칸수 세기나 작은 한자 현판 독해를 필수 성공 기준으로 삼지 않는다.

질문은 준비된 목록을 선택한다. 진행자는 설명 전 궁금증·설명 후 남은 점을 듣고 기록할 수 있지만 즉석 검색·자유 답변으로 성공을 만들지 않는다. 내용이 없으면 미지원으로 남긴다. 중단·관심 없음도 결과다.

## 종료와 백로그 반영

개입은 I0도움없음/I1과업 재설명·의도 확인/I2위치·단서 제공/I3직접 조작·정답 제시로 구분한다. 약20~30초 망설임은 의도를 물을 참고 시점이며 실패 제한시간이 아니다.

기록지의 관찰 사실→해석→유지/수정/보류→User Story/AC→미검증 사항을 연결한다. 한 명의 관찰로 성공률·시간 단축·AI 정확도·문화 관심 증가를 주장하지 않는다. 기존 제품 요구도 관찰하지 않았다는 이유만으로 백로그에서 삭제하지 않는다. 익명 회차 요약은 [기존 P08 Issue](https://github.com/HyunKN/visual-travel-guide/issues/13)에 모으며 발견 항목마다 새 Issue를 만들지 않는다. 실제 참여 전에는 기록지를 결과로 채우거나 P08을 완료 처리하지 않는다.
