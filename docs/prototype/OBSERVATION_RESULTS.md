# 세 사용자 테스트 결과와 Product Backlog 반영 근거

정리일: 2026-10-17. **R01·R02·R03 기록과 사용자 보충 설명의 분석 정리본**이다. 세 HTML 원문과 후속 보충을 통합하고 Astra의 읽기 전용 재검토를 대조해 §9에 반영했다. AI 검토는 참여자 관찰을 추가한 것이 아니다. 코드 수정·결함 재현·팀 우선순위 합의·제출용 Product Backlog 완성의 기록이 아니다.

현재 단계는 프로토타입 사용 관찰을 바탕으로 제품 요구사항을 구체화하는 단계다. 다음 주 Sprint 0 착수와 구분하며, 프로토타입 P01~P08을 제품 Sprint나 제품 Story 완료로 환산하지 않는다. 기준 범위는 [PRODUCT](../PRODUCT.md), 기존 사용자 이야기 U01~U12는 [설계 시작점](README.md), 관찰 방법은 [QA_METHOD](QA_METHOD.md)를 따른다.

2026-10-19 후속 기준 확인: 이 문서의 ‘다음 주’·‘미정’·‘제출용 백로그 확정 전’ 표기는 10/17 분석 작성 당시 기준이다. 이후 「PPT 구성 이어가기」에서 4차 Product Backlog와 12개 개별 US를 수정·검수했다. 최신 우선순위·SP·Sprint·DoD는 [4차 작성본 공개 요약](../PRODUCT_BACKLOG_DRAFT.md)을 따른다. 아래 초기 B01~B06 제안은 관찰에서 요구사항으로 옮기는 과정의 기록이며 최종 US 번호·우선순위표를 대체하지 않는다. 실제 제품 착수·AC 통과·성능은 여전히 별도 검증 대상이다. 수행·종료 근거는 [상위 Issue](https://github.com/HyunKN/visual-travel-guide/issues/4)와 [관찰·백로그 Issue](https://github.com/HyunKN/visual-travel-guide/issues/13)를 따른다.

**사용자가 지정한 주요 검토사항 — 첫 진입에서 도움을 이해하고 첫 결과에 도달하기:** 처음 들어온 사람이 이 앱이 어떤 상황에서 도움이 되는지, 무엇을 하면 어떤 결과를 얻는지 알아차릴 수 있어야 한다. R03의 현장 도움에 대한 의문과 S05의 제작자 개인 경험을 근거로 우선 조사한다. 홈의 시각적 매력·사용법 안내·실제 유용한 결과·계속 쓸 의향은 각각 구분해서 확인한다. 첫 경험 개선이 재사용을 높인다는 효과는 아직 입증하지 않았다.

원본 HTML은 사용자가 보관한 입력 자료다. 이 문서에는 익명 요약만 남기며 원본 HTML·발언 전문·개인 정보·로컬 보관 경로를 공개 저장소나 앱 배포물로 복사하지 않는다. 근거의 세부 위치는 아래의 `R01 자유 탐색`, `R02 S4` 같은 양식 항목으로 추적한다.

이전 제작자 PC 검사와 참여자의 실제 모바일 사용은 다른 근거다. **모바일 사용 기록이 접수된 것은 확인했지만 실기기 품질을 통과했다고 판정한 것은 아니다.** R01·R02는 기기·질문지·홈 경험이 다르고 R03의 환경은 미기록이며, 세 회차가 같은 버전인지 확인하지 못했으므로 비교 실험으로 취급하지 않는다. 과업 칸에 의견이 있다는 사실만으로 해당 과업의 독립 완료를 인정하지 않는다.

## 4. Product Backlog에 사용할 User Story 후보

B01~B06은 이 분석의 추적용 후보 ID다. 정식 US ID를 추가 발행한 것이 아니다. 기존 같은 목적의 항목에 먼저 통합한다. 도메인 묶음은 `대상 탐색·확인`, `설명·이해`, `관람 탐색 이어가기`를 제안하며 화면 이름을 Epic으로 삼지 않는다.

아래 수용 조건은 **10/17 분석 당시의 후보**다. 당시 SP·담당·배치 Sprint와 MoSCoW는 미정·제안이었으며, 후속 4차본에서 채택한 현재 계획은 위 링크를 따른다. 현재 프로토타입의 6장면·7대상을 미래 제품 범위로 확정하지 않는다.

### B01. 전체 또는 부분의 대상 확인 — U01·U02·U03·U06

- 근거: F01. 우선순위 제안: Must.
- User Story: 이름을 모르는 방문객으로서, 건물 전체 또는 궁금한 부분을 선택해 내가 알고 싶은 대상의 설명에 도달하고 싶다.
- Given 지원 사진을 연 상태 / When 전체 또는 부분 알아보기를 시작 / Then 두 경로의 목적을 구분해 선택하며 전체 설명을 위해 부분 지정을 강요받지 않는다.
- Given 지원 부분을 선택한 상태 / When 선택을 확인 / Then 선택 표시·대상 이름·기본 설명이 같은 대상을 가리킨다.
- Given 확대된 사진에서 지원 부분을 선택한 상태 / When 선택 결과가 갱신 / Then 현재 보이는 영역에서 선택 완료 여부와 설명을 여는 다음 행동을 확인한다. 화면 아래 변화만으로 선택을 알리지 않는다.
- Given 지원하지 않는 위치를 선택한 상태 / When 다음 안내를 확인 / Then 지원 한계와 같은 사진에서 재선택하는 경로가 제시되고 무관한 설명은 나오지 않는다.

### B02. 설명 맥락과 복귀 — U04·U09

- 근거: F02·F09. 우선순위 제안: Must.
- User Story: 설명을 읽는 방문객으로서, 현재 대상과 설명 단계를 알고 이전 사진·설명으로 돌아가 탐색을 계속하고 싶다.
- Given 기본 설명에서 관련 질문을 연 상태 / When 답변을 확인 / Then 현재 대상 이름과 선택한 질문이 함께 표시된다.
- Given 준비된 관련 질문을 제공하는 상태 / When 질문 영역을 확인 / Then 제시된 질문을 눌러 답변을 보는 방식임을 알 수 있고 제공하지 않는 자유 입력을 요구하는 안내가 없다.
- Given 검색 결과 또는 사진 선택에서 설명에 들어온 상태 / When 직전 화면으로 복귀 / Then 해당 진입 경로의 검색어·대상·선택 맥락이 정해진 복원 규칙대로 유지된다.
- Given 홈 이동 수단을 제공한 화면 / When 해당 수단을 선택 / Then 일관되게 홈으로 이동한다. 로고를 홈 진입으로 채택하면 실제로 작동하고 조작부로 식별된다.

### B03. 낯선 대상의 의미 이해 — U04·U05

- 근거: F03·S04. 우선순위 제안: 의미 이해는 Must, 개별 상세 주제의 수록 범위는 자료 확보·팀 결정 전 미정.
- User Story: 역사 지식이 적은 방문객으로서, 대상의 쓰임과 낯선 용어를 쉬운 설명으로 이해하고 눈앞의 모습과 연결하고 싶다.
- Given 품계석처럼 낯선 대상을 설명하는 화면 / When 설명을 열어 확인 / Then 해당 대상의 사진 위치와 쉬운 용어 풀이를 함께 확인한다.
- Given 핵심 설명을 읽는 상태 / When 상세 설명을 펼쳤다가 접음 / Then 같은 대상의 핵심 설명과 탐색 맥락을 유지한다.
- Given 연혁·생활·쓰임·재료·구조·배치 이유 중 출처가 확보된 상세 주제 / When 해당 주제를 선택 / Then 대상의 어느 모습·시기와 연결되는 설명인지 확인한다. 건립 연혁은 창건·중건·복원 시점을 구분하고 경과 연수의 기준 시점을 밝힌다. 6·25전쟁 이야기는 해당 대상과의 관련 근거를, 목재 종류는 선택한 부위의 재료 근거를 확인하며 미확인 내용을 사실처럼 채워 넣지 않는다.
- Given 설명의 근거를 확인하려는 상태 / When 출처를 선택 / Then 해당 설명의 근거 자료에 접근하고 돌아와 원래 설명을 계속 볼 수 있다.

화면 조건 통과와 실제 이해는 별도로 확인한다. 후속 관찰에서는 참여자가 품계석의 쓰임을 자기 말로 설명하고 사진에서 대상을 가리킬 수 있는지 살핀다. 자료를 외웠거나 답을 안내받은 수행과 구분한다.

### B04. 불확실한 후보 비교 — 기존 후보 확인 흐름

- 근거: F04. 기존 [후보 확인 설계](FLOW_EXTENSION_DESIGN.md)와 연결. 우선순위 제안: 불확실성 안내·복구는 기능 채택 시 Must, 후보 비교 UI의 유지·형태는 재검토.
- User Story: 대상을 확신하지 못한 방문객으로서, 결과의 불확실성과 확인 가능한 단서를 이해하고 판단을 보류하거나 다른 방법으로 확인하고 싶다.
- Given 결과를 확정할 수 없어 후보를 제시하는 상태 / When 비교 화면을 열음 / Then 비교가 필요한 이유와 아직 확정되지 않았음을 안내한다. 선택을 완료해야만 계속 이용할 수 있게 강요하지 않는다.
- Given 후보를 비교하는 상태 / When 원래 사진과 후보를 대조 / Then 입력 사진과 참고 사진이 구분되고 같은 기준의 특징 및 해당 사진 위치를 확인한다.
- Given 후보를 선택한 상태 / When 다른 후보로 변경 / Then 대상 이름·설명·참고 사진이 모두 변경한 후보와 일치한다.
- Given 어느 후보도 확신하지 못하는 상태 / When 해당 없음 또는 원래 사진 보기를 선택 / Then 목적에 맞는 화면으로 돌아가며 후보를 자동 확정하지 않는다.

실제 제품에서 불확실한 인식 결과를 다루기로 하면 핵심 복구 흐름이다. R03의 단일 사진 제안은 화면 부담을 줄이는 후보로 보존하되 불확실한 결과를 단일 정답으로 보이는 방식으로 채택하지 않는다. 후보 비교 유지 여부는 사용자가 비교 목적과 단서를 이해하는지로 판단한다. 구현 기술과 식별 성능은 이번 관찰로 결정하지 않는다.

### B05. 설명 뒤 원하는 탐색 이어가기 — U07·U08·U09

- 근거: F02·F08. 우선순위 제안: 새 검색·복귀는 핵심 조건, 다음 관람 제안은 Should.
- User Story: 설명을 읽은 방문객으로서, 같은 사진을 더 살피거나 다른 대상을 찾아 관심에 따라 탐색을 이어가고 싶다.
- Given 설명을 읽는 상태 / When 같은 사진의 다른 부분을 선택 / Then 현재 사진으로 돌아가 새로운 대상을 선택한다.
- Given 설명을 읽는 상태 / When 새 대상 찾기 경로를 선택 / Then 검색·새 사진 등 표시된 목적과 일치하는 탐색을 시작하고 원래 설명에도 돌아갈 수 있다.
- Given 다음 장소 제안이 있는 상태 / When 제안을 확인하거나 건너뜀 / Then 장소의 위치 맥락·연결 이유를 확인할 수 있으며 무시하고 검색하거나 종료할 수 있다.

새 검색·복귀와 선택적 장소 제안은 최종 백로그에서 필요에 따라 기존 항목별로 통합한다. 한 스토리의 서로 다른 우선순위를 혼합한 채 확정하지 않는다.

### B06. 첫 진입에서 도움과 시작 방법 이해 — U01·U06·U11

- 근거: F08·F10. 사용자 지정 주요 검토사항. 우선순위 제안: 첫 행동·예상 결과 이해는 Must, 구체적인 첫 경험 UI는 조사 후 결정. 기존 검색·첫 진입 Story에 통합한다.
- User Story: 처음 사용하는 방문객으로서, 이 앱이 내 관람에 어떤 도움을 주며 무엇을 하면 원하는 결과를 얻는지 이해하고 첫 탐색을 시작하고 싶다.
- Given 처음 진입해 목표한 대상이나 궁금증이 있는 상태 / When 홈의 안내와 주요 행동을 확인 / Then 지원 범위와 시작할 행동, 그 행동으로 얻을 결과가 연결되어 제시된다.
- Given 첫 탐색을 시작한 상태 / When 지원 대상을 선택하거나 검색 / Then 선택한 행동에 맞는 대상·설명으로 이어지고 방문 상황에서 어떻게 활용하는지 확인할 수 있다. 예시 결과는 실제 인식·현장 결과와 구분한다.
- Given 지원 범위 밖 또는 결과가 없는 검색어 / When 검색 / Then 빈 결과와 가능한 탐색 대안을 제시하고 무관한 결과를 정답처럼 보여주지 않는다.
- Given 예시 체험 또는 제한된 자료를 제공하는 상태 / When 결과를 확인 / Then 제한된 예시를 전체 지원 범위·실제 인식·실제 위치 결과로 오인시키지 않는다.

후속 관찰에서는 조작 순서를 먼저 알려주기 전에 참여자가 `어떤 도움을 받을 수 있는지 / 무엇부터 하면 되는지 / 누르면 어떤 결과가 나올지` 자기 말로 설명하고 시작할 수 있는지 살핀다. 화면 요소의 존재만으로 이해를 통과 처리하지 않는다. 결과를 본 뒤 느끼는 유용성과 이후 실제 재사용은 별도 확인한다. 목표 시간·성공률은 근거 없이 정하지 않는다.

## 7. 후속 작업과 제출 문서 연결

현재 기록만으로 백로그 구체화는 시작할 수 있다. 누락된 기기 정보·정확한 터치 위치·개입 수준은 미상으로 두며, 기억을 추측해 채우거나 모든 칸을 추가 작성할 것을 요구하지 않는다. 선택 제한과 확대 조작의 의미는 사용자의 후속 설명으로 보완했다.

후속 상태: [백로그 공개 요약 부록 A](../PRODUCT_BACKLOG_DRAFT.md)에 연구 1편·Apple 지침·Google Lens 공식 절차·Duolingo의 회사 보고를 대조한 제한된 초기 조사가 있다. 기업 앱의 현재 설치 화면 관찰·관광앱 전수 조사·우리 앱의 개선 효과 실험까지 수행한 것은 아니다. 아래 계획 전체를 완료했다고 표시하지 않는다.

- **첫 행동과 결과 예측:** 처음 쓰는 사람이 서비스의 도움·시작 행동·예상 결과를 어떻게 이해하는지 다룬 UX 연구. 원문 방법·대상·과업·한계를 확인한다.
- **실제 기업의 첫 경험:** 관광·지도·시각 검색과 관련 서비스의 첫 진입→첫 결과 흐름을 공식 자료와 실제 화면으로 비교한다. 기능 소개, 예시 체험, 상황에 맞춘 안내, 바로 탐색 중 무엇을 쓰는지 살피고 우리 방문 전·현장 상황에 맞는지 평가한다.
- **효과 데이터:** 기업의 채택 사실과 효과 입증을 구분한다. 성과 수치가 있으면 측정 지표·비교 조건·표본·기간·실험 여부를 확인한다. 공개 효과 데이터가 없으면 미공개로 기록하고 성공 사례로 단정하지 않는다.
- **우리 제품의 확인 기준:** 가치 이해, 첫 행동 발견, 예상과 실제 결과의 일치, 첫 궁금증 해소를 각각 관찰한다. 체류 시간 증가만으로 도움을 받았다고 해석하지 않는다. 재사용 의향과 실제 재사용도 구분한다.

산출물은 적용 후보별 근거·반례·적용 조건·작은 확인 방법이다. 긴 튜토리얼, 로고 시작 화면, 3D, 강제 온보딩 중 어느 것도 조사 전 필수 해법으로 정하지 않는다. 조사 목적은 사용자가 원하는 첫 결과에 쉽게 도달하도록 돕는 것이다.

### 제출용 백로그로 연결하는 순서

아래는 분석 당시 제시한 순서의 보존 기록이다. 백로그·US 작성·검수는 후속 4차본에 반영됐으며, 모바일 수정·재관찰·실제 기술 검증까지 완료됐다는 뜻은 아니다.

1. **현재 기록을 기준으로 요구사항 정리:** B 후보를 제출한 문제정의서 §2.3 개발 범위·§2.4 달성 지표 및 기존 전체 요구사항과 대조한다. 이 분석에 없는 기존 요구를 삭제하지 않는다.
2. **핵심 조작 문제의 제작자 확인:** 확대/페이지 이동·선택 후 결과 가시성·하단 행동 접근·관련 질문 안내·3D 유지 시 재생을 확인한다. 이번 문서 정리에서 재현·수정한 것으로 기록하지 않는다.
3. **보완 뒤 짧은 재관찰:** 가능하면 실제 무가이드 관람 경험·계획이 있는 신규 참여자에게 건물 전체 찾기→자유로운 부분 선택→설명 이해→같은 사진 복귀를 관찰한다. 질문 영역에서 무엇을 할 수 있는지, 비교를 왜 보여준다고 이해하는지도 중립적으로 확인한다. 기존 참여자는 회귀 확인에 활용하며 다시 첫 사용으로 세지 않는다. 추가 인원 확보를 백로그 문서화의 필수 관문으로 삼지 않는다.
4. **제출용 백로그 확정:** 양식5의 Epic·US·Given/When/Then 수용 조건·MoSCoW·팀 합의 SP를 채우고 용량·일정에 따라 Sprint를 배치한다. 맨 위 항목부터 상세화한다. 문제정의서 정합성·팀 합의·SP·Sprint 배치는 이번 분석 정리로 완료하지 않았다.

본 문서는 제출용 전체 Product Backlog가 아니라 그 입력 근거다. 팀 합의 전의 제안을 완료 요구사항이나 합의한 일정으로 표현하지 않는다. 실제 추적은 [기존 프로토타입 Issue](https://github.com/HyunKN/visual-travel-guide/issues/4)와 [기존 관찰 Issue](https://github.com/HyunKN/visual-travel-guide/issues/13)를 우선 사용한다. 이번 정리에서 Issue 게시·생성·종료는 수행하지 않았다.

## 8. 발표에 사용할 수 있는 결론과 한계

발표 표현 초안: **세 차례의 프로토타입 테스트·인터뷰에서 부분 탐색·시각 자료의 긍정 단서와 함께 대상 선택·설명 이해·복귀·확대 조작의 문제가 반복됐다. 세 번째 기록에서는 질문 방식과 후보 비교 목적을 이해하지 못한 사례, 서비스의 도움을 확신하기 어렵다는 평가도 확인했다. 이를 기존 요구사항과 수용 조건을 구체화하는 근거로 정리했다.**

- 참여자 세 명의 기록으로 일반 방문객의 성공률·만족도·시간 단축·제품 수요를 산출하지 않는다. 반복 발견은 개선 필요의 근거이지 모집단 발생률이 아니다.
- R02·R03이 같은 의견을 여러 항목에 적은 것을 여러 명의 요구로 세지 않는다. 세 번째 인터뷰 R03과 제작자 보충 화면 S03은 서로 다른 근거다.
- 준비된 사진·후보·답변의 이용은 실제 촬영·업로드·자동 인식·GPS·현장 이동의 검증이 아니다.
- 카드·3D 선택은 문화 관심 증가·재방문·현장 행동 변화의 증거가 아니다.
- 실제 설명 이해·자발적인 다음 관람 선택·기존 안내 방식 대비 효과는 미확인이다.
- 결함 원인·수정 완료·수정 후 품질, 최종 백로그 및 팀 합의는 별도 증거가 필요하다.

## 9. Astra 재검토 — 분석에서 과도하게 단정하지 않을 것

2026-10-17 사용자 요청으로 세 원문과 통합 보고서를 다시 대조했다. 아래는 기존 분석에 대한 판단 보완이며 새로운 참여자 관찰·팀 우선순위 확정이 아니다.

**재검토 결론:** 부분을 골라 궁금증을 해결하는 방향에는 유지할 단서가 있다. 그러나 현재 흐름이 그 가치를 충분히 전달했다는 증거는 부족하다. 대상 지정→선택 결과 인지→이해 가능한 설명→계속 탐색 또는 복귀를 함께 핵심 요구로 구체화한다. 후보 비교 UI의 존재 자체를 완료 목표로 삼지 않는다.

현재 근거로 Product Backlog 작성을 진행할 수 있다. 추가 확인이 필요하면 확대·선택 결과·하단 접근의 제작자 확인, 대표 설명 한두 개의 이해 확인, 비교 화면 목적·보류 경로의 이해 확인으로 좁힌다. 모든 프로토타입 결함 수정이나 추가 참가자 모집을 백로그 작성의 선행 완료 조건으로 추가하지 않는다.
