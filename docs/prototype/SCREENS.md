# 화면·상태·상호작용 설계

보완 계약: [보완 개발 설계 3·5·6절](FLOW_EXTENSION_DESIGN.md). P02에서 N·홈/이력, P03에서 C 건물 후보 확인을 구현했다. 질문 0개·다음 관람 보완은 P04/P05다. 부분 영역 중첩 후보는 보류하며 C는 S4의 두 건물 비교다.

상태: [설계안 0.1](README.md)의 구현 제안. 아래 문구와 수치는 첫 시안의 시작값이며 확정된 디자인 시스템·검증 결과가 아니다.

## 1. 화면 목록

| ID | 화면 | 진입 | 주요 행동 | 보조 행동 |
| --- | --- | --- | --- | --- |
| H | 홈 | 시작, 홈 복귀 | 궁금한 부분 알아보기 | 호기심 카드 최대 하나 |
| V | 장면에서 대상 지정 | H 주요 행동, 대상 수정 | 사진의 위치 선택 → 선택 확인 | 전체 보기, 텍스트로 대상 고르기 |
| C | 준비된 건물 후보 확인 | S4 입력 V의 명시적 행동 | 이름·참고 사진·구별 근거를 읽고 후보 하나 선택 | 해당 없음, 입력 사진 재시도, 후보 재비교 |
| Q | 관련 질문 | A의 관련 질문 더 보기 | 준비된 질문 선택 | 기본 설명, 대상 수정, 찾는 질문 없음 |
| A | 설명 | V/C에서 대상 확정, Q 선택, H 카드 | 설명 읽기 | 출처, 관련 질문, 대상 수정, 홈 |
| N | 다른 대상 알아보기 | A의 같은 이름 버튼 | 현재 장면을 제외한 준비 사진 최대 3개 → V | 뒤로 원래 설명, 현재 장면 홈. 사진 없으면 빈 상태 |
| E | 준비된 설명 없음 | 미지원 대상·질문, 자료 누락 | 대상/질문 다시 선택 | 홈 |
| X | 테스트 설정 | 별도 테스트 경로 | 장면·방문 맥락 설정 / 초기화 | 참여자 화면으로 복귀 |

A의 다음 관람 카드는 설명·출처·관련 질문·새 탐색 뒤 최대 1개다. `availableContinuation`이 현재 대상·허용 목적지·검수 답변/관계 출처를 확인한 경우만 표시한다. 큰 사진→대상 이름→소개 한 문장→살펴보기 순서이며 중첩 버튼은 없다. nearby/related 문구와 구역 모사 안내를 구분한다. 선택하면 목적지 기본 설명으로 이동하고 뒤로는 원래 설명·카드 버튼으로 돌아온다. 선택하지 않고 종료하는 것도 정상이다.

X는 제품 홈 메뉴에 노출하지 않는다. 테스트 링크의 설정 경로로 접근한다. 테스트 제어는 보안 권한 시스템이 아니며 비밀정보를 넣지 않는다. 초기에는 한 기기의 한 브라우저 탭에서 동작한다.

## 2. 기본 레이아웃

첫 시안 기준: 화면 폭 360~430 CSS px 중심, 320px에서도 주요 행동 잘림 없음. 본문 16px 이상, 터치 영역 최소 44×44px를 목표로 한다. 본문 폭 최대 약 480px로 중앙 배치하고 데스크톱에서도 조작 가능하게 한다. 흰 바탕·둥근 형태·기와 먹색·짙은 남색 주 강조와 작은 주홍 포인트를 사용한다. 누런 배경은 제외하고 장식보다 사진과 설명을 우선한다. [실제 참고와 배치 제안](VISUAL_REFERENCES.md), [제외 예시](ANTI_SLOP.md)를 보고 시안을 선택한 뒤 P02에서 정확한 색·간격을 토큰으로 구현하고 대비를 확인한다.

```text
H: 홈                            V: 대상 지정
┌────────────────────┐          ┌────────────────────┐
│ 경복궁              │          │ ←  궁금한 곳 고르기 │
│ 예시로 둘러보기      │          │                    │
│                    │          │   [준비된 장면]     │
│ [궁금한 부분 알아보기]│          │   선택 위치 표시    │
│                    │          │                    │
│ [사진] 짧은 질문     │          │ 선택한 부분 미리보기 │
│        더 알아보기   │          │ [이 부분 알아보기]  │
│                    │          │ 글로 대상 고르기     │
│ 테스트용 안내        │          │ [준비된 목록 펼치기] │
└────────────────────┘          └────────────────────┘

Q: 질문                          A: 설명
┌────────────────────┐          ┌────────────────────┐
│ ← [선택 부분 썸네일] │          │ ← [선택 부분 썸네일] │
│ 관련 질문           │          │ 대상 이름 / 부분명   │
│ [준비된 질문 1]     │          │ 짧은 기본 설명       │
│ [준비된 질문 2]     │          │ [더 읽기]           │
│ 찾는 질문이 없어요   │          │ 출처 / 사진 출처     │
│ 기본 설명으로       │          │ [관련 질문 더 보기] │
│ 대상 다시 고르기     │          │ 대상 수정 · 홈       │
└────────────────────┘          └────────────────────┘
```

홈에 지도, 주변 목록, 인기 콘텐츠 묶음, 탭바, 로그인, 전체 대화 이력을 추가하지 않는다. 위치 권한 팝업이나 첫 화면 전체 튜토리얼 없이 시작한다. 상단 맥락은 ‘예시로 둘러보기’ 또는 진행자가 고른 구역명이다. 실제 위치를 알아냈다는 인상을 주는 거리·방향·GPS 아이콘은 쓰지 않는다.

## 3. H — 홈

- 주 행동: `궁금한 부분 알아보기`. 현재 테스트 장면으로 V에 진입한다.
- 카드: 이미지, 짧은 질문 한 문장, `더 알아보기`. 카드 전체를 하나의 링크/버튼으로 만들고 중첩 클릭 영역을 만들지 않는다.
- 카드의 대상은 현재 장면에서 찾을 수 있어야 한다. 정확한 시선·촬영 대상을 추정했다는 표현은 하지 않는다.
- 방문 전에는 `경복궁을 미리 둘러보기`, 구역 설정 시에는 `<구역명>에서 살펴보기`로 맥락만 바꾼다. 카드 선택도 동일한 데이터 계약을 사용한다.
- 사용할 카드가 없으면 빈 카드나 로딩 표시 없이 주요 행동만 남긴다.
- 테스트 안내: `준비된 사진과 설명으로 체험하는 프로토타입입니다.` 작은 글자로 숨기지 않되 주요 행동을 가리지 않는다.
- 단순성과 발견 행동을 관찰하기 위해 카드 표시 여부는 실행 전 X에서 정한다. 사용 중 임의 변경하지 않는다.

2026-10-15 홈 재설계: 2안은 근정전 대표 사진을 화면 폭으로 펼치고 흰 텍스트 면으로 연결한다. S3 하단에는 별도의 굴뚝 탐색 사진을 둔다. 주 행동 아래에서 실제 탐색할 장면을 안내한다. 1안은 흰 배경의 정면 3D 일러스트와 재생·정지·다음 장면을 둔다. 메뉴와 X에서 두 안을 고른다. 동작 감소를 기본 존중하고 사용자 선택을 메모리에만 유지한다. 약 19.5초 이야기는 자동 종료한다. 기존 주요 문구와 S1~S3 흐름을 유지하며 실제 촬영·GPS·AI 기능으로 표현하지 않는다.

H/V/A에서 같은 사진을 쓰는 전환만 같은 요소로 연결하고 비율을 유지한다. 대표 사진과 실제 선택 사진이 다르면 서로 변신시키지 않는다. 선택·답변 상태는 즉시 전환하며 모션 종료를 기다리지 않는다. 설명 본문은 흰 면, 유리 효과는 조작부에 적용한다. [재질·입력 반응 분류](../design/INTERACTION_MATERIALS.md)와 [추가 조사](VISUAL_REFERENCES.md)를 따른다.

## 4. V/C — 전체와 부분 지정

1. V에는 사진을 가리지 않는 짧은 안내 `궁금한 곳을 눌러보세요`를 둔다. 아직 모든 정답 영역을 강조해 보여주지 않는다.
2. 사용자가 누른 위치에 즉시 표식을 보인다. 준비된 부분 영역 하나와 일치하면 해당 영역을 강조하고 미리보기+`이 부분 알아보기`를 표시한다. 단계별 자동 이동 없이 확인할 기회를 준다.
3. 실제 선정 자료에서 두 세부 대상을 같은 터치로 구분해야 할 때만 C를 구현한다. 해당 자료가 없다면 영역을 정리하고 C는 보류한다. 구현한 경우 최대 3개를 사진·중립적인 구분 단서로 표시한다. 전체 건물은 별도 행동으로 선택하므로 세부 영역과 경쟁시키지 않는다.
4. C의 `해당 없음`은 E의 ‘선택한 곳에 준비된 설명이 없음’으로 연결하고 다시 지정할 수 있게 한다. 빈 후보 상태와 다른 결과로 기록한다.
5. 세부 영역이 없는 곳을 누르면 임의로 가장 가까운 대상으로 보정하지 않는다. 좌표 표식은 남기고 `이 부분은 아직 준비된 설명이 없어요` 및 `건물 전체 알아보기` / `다시 고르기`를 제공한다.
6. 건물 전체는 명시적인 별도 행동 `건물 전체 알아보기`로 선택할 수 있다. 배경을 눌렀다고 건물 전체로 자동 판단하지 않는다.
7. `글로 대상 고르기`를 펼치면 같은 지원 대상의 버튼 목록이 나타난다. 키보드·스크린리더로도 모든 지원 대상에 도달한다. 이 경로는 보조받은 선택으로 관찰할 수 있게 구별한다.
8. 대상 확인 후 A에서 이름·기본 설명을 보여준다. 궁금증이 남으면 사용자가 `관련 질문 더 보기`로 Q에 진입한다. 질문 선택을 기본 설명의 선행 단계로 강제하지 않는다.

영역 좌표 계산은 [DATA](DATA.md)를 따른다. 사진의 여백을 누른 것은 사진 선택으로 처리하지 않는다. 구현에는 사진 2배 보기 버튼과 확대 사진 안의 스크롤을 넣었다. 핀치 전용 조작·드래그 영역 그리기·세밀한 다각형 편집은 범위 밖이다. 텍스트 대안은 같은 대상 ID로 연결한다. 십장생굴뚝 사진에는 자경전 건물 전체가 없으므로 전체 건물 행동을 표시하지 않는다.

## 5. Q — 준비된 관련 질문

- 선택 부분 썸네일, 대상 이름, 해당 대상의 질문 목록을 표시한다. 자연스럽게 떠올린 질문은 관찰자가 먼저 듣고, 준비된 질문 선택과 구분해 기록한다.
- 사용자는 기본 설명만 읽고 끝낼 수 있다. 관련 질문은 A의 `관련 질문 더 보기`를 선택한 경우에만 나타난다.
- 목록에서 질문 하나를 고르면 A에 그 질문과 답을 함께 보여준다. `기본 설명으로`를 통해 원래 개요로 돌아갈 수 있다.
- `찾는 질문이 없어요`는 E로 이어진다. 기본 설명 복귀·대상 수정·홈 경로를 제공한다. 없는 질문에 가장 비슷한 답을 자동 연결하지 않는다.
- 검수된 질문이 0개이면 A에 `아직 준비된 추가 질문이 없어요`와 미지원 표현 행동을 제공하고 Q 진입을 숨긴다. 오래된 Q 이력은 같은 빈 상태와 기본 설명·새 탐색 복귀를 제공한다. `reviewedQuestions`가 대상/답변/출처가 맞는 검수 질문만 고른다.
- 자유 입력, LLM 응답, 답변 대기 화면, 진행자 응답 큐를 구현하지 않는다. 관찰에서 나온 미지원 질문을 다음 설계 판단에 사용한다.

## 6. A/E — 답변과 복구

- A 순서: 선택 사진/부분 → 대상 이름 → 질문 답변일 경우 해당 질문 → 짧은 설명 → 선택적인 `더 읽기` → 설명 출처 → 사진 출처 → 관련 질문/대상 수정. 기본 설명이면 질문 제목을 억지로 붙이지 않는다.
- 짧은 설명은 첫 답을 파악할 수 있는 2~3문장 정도로 작성한다. 문장 수를 맞추려고 근거에 없는 내용을 넣지 않는다.
- 답변에는 해당 질문을 설명하는 근거가 있어야 한다. 위치·명칭 출처만으로 문양 의미·역사적 이유를 만들어 설명하지 않는다.
- 카드에서 진입한 경우 카드의 질문과 대상이 A에 그대로 이어진다. 질문 선택 화면으로 되돌아가게 강제하지 않는다.
- 설명·필수 출처가 누락되면 그 답변 본문은 표시하지 않고 E로 보낸다. 검수된 다른 질문으로 이동 가능하다.
- 사진 로드 실패 시 대체 텍스트, 재시도, 텍스트 선택 경로를 제공한다. 잘못된 크롭이나 빈 영역 표식을 표시하지 않는다.
- 출처 링크는 의미 있는 제목을 갖는다. 새 탭으로 열면 링크 이름에 이를 알리고 돌아왔을 때 질문·선택을 유지한다. 외부 사이트 연결 실패는 앱의 답변 재생성으로 처리하지 않는다.
- E는 원인을 분리한다: 미지원 부분 / 후보 중 해당 없음 / 미지원 질문 / 설명 누락 / 출처 누락. 사용자 문구는 짧게, 테스트 기록은 원인별로 한다.

## 7. 상태 전환과 초기화

| 사건 | 유지 | 초기화 / 다음 상태 |
| --- | --- | --- |
| 같은 사진의 새 위치 선택 | scene, context | target, question, answer 초기화 → V/C |
| 대상 다시 고르기 | scene, context | 확정 target 이후 값 초기화 → V |
| 같은 대상의 관련 질문 선택 | scene, target | question, answer를 해당 질문으로 변경 → A |
| 기본 설명으로 | scene, target | question 초기화, overviewAnswer 표시 → A |
| A → 뒤로 | 이전 화면의 유효한 상태 | 실제 직전 화면으로 복귀. A의 종류만으로 목적지를 추정하지 않음 |
| Q → 뒤로 | Q 진입 전 설명 | 기본 설명 또는 카드로 들어온 설명으로 복귀 |
| 홈으로 | scene, context, 설정 | target, question, answer 초기화 → H |
| 테스트 장면/맥락 교체 | 설정에서 선택한 새 값 | 사용자 선택·질문·응답 전체 초기화 → H |
| 브라우저 새로고침 | 검증된 URL 설정 | 사용 상태·질문은 메모리에서 사라짐 → H |
| 잘못된 URL/자료 ID | 안전한 기본 설정 또는 없음 | 오류 안내 후 유효한 홈/테스트 설정으로 복구 |

뒤로 가기는 화면에 보이는 버튼과 브라우저 뒤로 가기가 같은 의미를 갖게 한다. 사용자 이동은 시간순 기록을 따르며 `기본 설명으로`도 새 이동으로 기록한다. 예를 들어 `V → A(기본) → Q → A(질문) → A(기본)` 뒤 뒤로는 A(질문)이다. `H → A(카드) → Q → A(질문)`에서 두 번 뒤로는 A(카드)다. 화면 종류에 따라 중간 기록을 건너뛰지 않는다.

X에서 새 실행 시작과 새로고침은 이전 여정을 무효화한다. 홈은 현재 장면 H를 같은 실행의 이력에 추가하므로 뒤로 직전 설명을 복원한다. X를 일반 뒤로 경로에 섞지 않는다. 오래되거나 허용 장면/참조가 다른 항목은 시작 H로 교체한다. 유효한 같은 실행의 뒤로/앞으로는 선택·스크롤·사진 확대/내부 위치·가능한 원래 조작부 포커스를 복원한다. URL은 실행 시작 설정을 유지한다.

## 8. 접근성과 표시 기준

- 버튼·카드·출처·텍스트 대상 목록은 실제 시맨틱 요소로 구현한다. 키보드 Tab 순서가 화면 순서와 맞고 focus-visible이 보인다.
- 이미지의 선택 위치와 선택 대상은 테두리+텍스트로 표현한다. 색만으로 구분하지 않는다.
- 새 화면은 제목 또는 적절한 시작점으로 포커스를 이동한다. 펼치기/닫기는 원래 버튼으로 복귀하고, 상태 변경 안내는 과도하지 않게 읽힌다.
- 200% 글자 확대에서 수평 스크롤 없이 주요 행동이 접근 가능해야 한다. 스마트폰에서도 선택·뒤로·복구 행동을 누를 수 있어야 한다.
- 첫 시안은 애니메이션 없이도 이해되게 한다. 전환을 추가하면 reduced-motion을 존중한다.
- X 진입/복귀와 자료 오류를 포함한 실제 수동 확인은 [TESTING](TESTING.md)의 F 항목으로 기록한다.
