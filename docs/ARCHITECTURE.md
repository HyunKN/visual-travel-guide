# 구조와 데이터 흐름

상태: 구현 전 제안. 플랫폼, 프레임워크, 저장소, API, 인식 모델은 미정이다. 아래 책임 구분은 논리적 경계이며 별도 서버·패키지·파일을 요구하지 않는다.

## 첫 흐름의 책임과 연결

| 책임 | 입력 | 출력 | 지켜야 할 관계 |
| --- | --- | --- | --- |
| 준비된 자료 제공 | 선택한 사진 | 사전 연결한 후보 목록 | 사진과 후보 연결은 확인 가능한 자료로 유지 |
| 선택 관리 | 현재 사진, 후보 선택 | 선택한 대상 또는 선택 없음 | 사진 변경 시 이전 선택 초기화 |
| 설명 조회 | 선택한 대상 | 명칭·설명·출처 또는 누락 상태 | 서로 다른 대상의 정보가 섞이지 않음 |
| 화면 표시 | 후보·선택·설명 상태 | 비교·선택·설명 화면 | 표시 규칙은 DESIGN을 따름 |

```text
준비된 사진·후보·설명 자료
  → 사진 선택
  → 후보 목록
  → 사용자 대상 선택
  → 해당 대상의 설명·출처 표시
```

첫 구현에서는 사전 연결 데이터로 처리한다. 사진 분석 서비스·데이터베이스·서버는 필요가 확인되기 전까지 전제하지 않는다. 실제 구현 이후 이 문서에 담당 파일·공개 인터페이스를 연결한다.

## 구조를 바꿀 때

1. 변경할 책임, 입력·출력, 소비자를 적는다.
2. 기존 상태 전환과 설명의 대상 일치 규칙에 미치는 영향을 확인한다.
3. 실제 데이터 전송·보관 또는 외부 서비스가 생기면 경계와 실패 시 동작을 추가한다.
4. 되돌리기 어렵고 대안 간 중요한 절충이 있었던 결정은 맥락·선택·이유를 `docs/adr/NNNN-short-title.md`에 기록한다. 현재 ADR은 없다.

작은 독립 구현 단위는 이 경계를 가로질러 사용자가 확인할 수 있는 흐름으로 나눈다. 관련 용어는 [GLOSSARY](GLOSSARY.md), 동작 판정은 [QUALITY](QUALITY.md)가 기준이다.
