# 궁금한 궁 Product Backlog 검토 초안

작성일: 2026-10-17 · 공개 전 점검: 2026-10-19 · 버전: v0.1 · 상태: 요구사항 검토용, 제출 확정 전.

경복궁 방문객이 가진 단서로 대상을 찾고, 눈앞의 건물이나 부분에 대한 궁금증을 출처 있는 설명으로 해결하도록 요구사항을 정리한다. 문제정의서의 전체 개발 범위에 세 사용자 관찰을 연결했다. 우선 검토할 것은 **첫 진입에서 도움과 시작 방법을 이해하고 첫 유용한 설명에 도달하는 경험**이다.

이 문서는 양식 5의 0~8절 순서를 따른 제출 초안이다. 제품 구현 현황이나 Sprint 진행표가 아니다. 모든 MoSCoW·순위는 제안이며 SP·담당·Sprint 배치는 미정이다. 양식에서 요구하는 팀 추정과 승인까지 완료한 제출본으로 표시하지 않는다. 사용자 검토 뒤 Word 양식으로 옮기며, 상세 User Story는 양식 5-1의 원칙에 따라 한 건당 한 파일로 분리한다. 현재는 검토 중 중복 수정을 줄이기 위해 본문과 부록에 모았다.

## 1 Product Vision and Success Metrics

### 1.1 Product Vision

경복궁을 가이드 없이 둘러보며 건물과 세부 요소가 궁금한 방문객을 돕는다.<br>
이름을 모르거나 여러 자료를 대조하기 번거로워 궁금증을 지나치는 상황을 다룬다.<br>
방문객이 가진 이름·사진·위치 단서에서 탐색을 시작하도록 한다.<br>
대상을 확신하기 어려우면 구별 근거와 다른 확인 방법을 제공한다.<br>
확인한 대상은 공식 명칭·위치·쉬운 설명·출처로 연결한다.<br>
처음 사용하는 사람도 무엇을 하면 어떤 도움을 받는지 이해하도록 한다.<br>
필요한 설명을 본 뒤 같은 장면을 더 살피거나 원하는 다른 탐색으로 이어가도록 한다.

장기 대상은 국내·외 자유 관람객이다. 이번 한국어 소수 관찰은 외국인 사용성·언어 지원·현장 수요를 입증하지 않는다. 첫 지원 건물·부분·언어의 실제 목록은 데이터와 개발 여력을 확인해 정한다.

### 1.2 Success Metrics

문제정의서 §2.4의 네 행 중 식별 성능의 Top-1과 Top-3을 나눠 **다섯 지표**로 옮겼다. 아래 수치는 모두 기존 목표이며 측정 성과가 아니다.

| ID | 지표 | 기존 목표 | 측정 방법·시점과 보완할 정의 | 관련 Story |
| --- | --- | --- | --- | --- |
| M1 | 사진·위치 기반 건물 식별 Top-1 정확도 | 80% 이상 | 구현 후 학습에 쓰지 않은 경복궁 건물 사진으로 평가. 정답 건물 ID가 첫 후보인 건수/평가 사진 수. 거리·방향·촬영 조건별로 보고. 지원 건물·분할·표본 수는 평가 전 고정 | US-05·06 |
| M2 | 서로 다른 상위 3개 건물 후보의 정답 포함률 | 90% 이상 | 구현 후 정답 건물이 최대 3개의 서로 다른 건물 후보에 포함된 건수/평가 사진 수. 같은 건물의 사진 3장을 Top-3으로 세지 않음. 사진만/사진+위치를 같은 평가셋에서 비교 | US-05·06·07 |

평가 공통 조건: 실행 버전·지원 범위·환경·표본·제외 기준·도움 수준을 남긴다. M1·M2의 학습/평가 장면 누출을 막고 미지원 사진의 오답·보류는 별도로 보고한다. M4는 두 조건의 성공 과제 구성이 다른 경우 단일 평균만으로 개선을 주장하지 않고 대응 가능한 과제·조건을 함께 제시한다. 평가 설계가 바뀌면 원래 목표와 변경 이유를 Revision History에 남긴다.

**첫 경험의 보조 관찰:** 도움의 이해, 첫 행동 발견, 예상 결과와 실제 결과의 일치, 첫 궁금증 해소를 각각 기록한다. 새로운 성공률·목표 시간을 임의로 추가하지 않는다. 화면 도달은 설명 이해와 다르며 사용 의향은 실제 재사용과 다르다. 세 테스트에는 동일 조건·완료 판정·시간·수치 평점이 충분히 갖춰져 있지 않으므로 M1~M5의 달성률을 계산하지 않는다.

문제정의서 §2.3 표에는 코어 4개와 부가 1개가 있으나 명시적인 ‘제외’ 행은 확인되지 않았다. 따라서 §4.1의 Won't를 이미 제출본에서 합의한 제외 항목이라고 표현하지 않고 **이번 학기 제외 제안**으로 둔다.

## 3 개별 Epic의 User Story와 핵심 수용 조건

공통 메타데이터: 모든 Story의 SP·담당·배치 Sprint는 `미정`, 제품 상태는 `초안·검토 전`, 모든 AC의 검증 결과·확인일은 `미실행`이다. 아래 수용 조건은 향후 제품에 적용할 조건이며 현재 프로토타입이 통과했다는 뜻이 아니다. 각 Story는 공통 품질·DoD도 함께 적용한다. 서술의 ‘지원’ 범위는 실제 데이터·기술 검토 뒤 명시할 대상과 환경을 뜻한다.

### E1 관광 대상 탐색

#### US-01 첫 진입에서 도움과 시작 방법 이해

- **As a** 처음 사용하는 경복궁 방문객으로서, **I want** 어떤 도움을 받을 수 있고 무엇부터 하면 되는지 알고 첫 탐색을 시작하고 싶다. **So that** 사용법을 추측하느라 시간을 쓰지 않고 눈앞의 궁금증을 해결할 수 있다.
- Priority: **Must 제안**. 근거: F08·F10, B06, U01·U11, R03 자유·마지막 및 S05. S05는 제작자의 회고이며 추가 참여자가 아니다.
- 범위·의존: 지원 범위 안내와 첫 행동에서 설명으로 이어지는 연결. 대표 콘텐츠와 US-02 또는 US-05, US-08의 결과 계약 필요. 로고 화면·긴 튜토리얼·3D는 구현 조건이 아니다.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 01-1 | 처음 진입했고 궁금한 대상 또는 질문이 있음 | 첫 화면의 안내와 행동을 확인 | 경복궁 내 지원 범위, 시작할 행동, 그 행동의 예상 결과가 연결되어 제시됨 |
| 01-2 | 지원하는 첫 행동을 선택함 | 검색·사진 등 표시된 경로를 진행 | 해당 대상의 이름·설명으로 연결되며 관련 없는 튜토리얼 완료나 가입이 결과 접근의 필수 조건이 되지 않음 |
| 01-3 | 방문 전 예시 체험을 제공함 | 예시 결과를 확인 | 예시라는 표시와 실제 사용에서 필요한 입력을 구분하고 실제 인식·현재 위치 결과로 표현하지 않음 |
| 01-4 | 사전 조작 설명을 듣지 않은 첫 사용자가 대표 과제를 받음 | 시작 전 도움·첫 행동·예상 결과를 자기 말로 설명하고 탐색 | 세 이해 항목과 실제 첫 결과를 관찰표에 각각 기록. 첫 행동을 찾지 못하거나 결과를 오해한 경우 개선 대상으로 남김 |

01-4는 관찰 기록 조건이다. 화면 문구 존재만으로 ‘사용자가 이해함’을 통과 처리하지 않는다. 표본·목표 시간·일반 성공률은 이 초안에서 만들지 않는다. 부록 A의 조사·짧은 확인을 이 Story에 연결한다.

#### US-02 알고 있는 이름이나 단어로 대상 찾기

- **As a** 대상 이름이나 일부 단서를 아는 방문객으로서, **I want** 이름·별칭·설명 단어로 검색해 대상을 고르고 싶다. **So that** 사진을 새로 찍지 않고 원하는 설명을 찾을 수 있다.
- Priority: **Must 제안**. 근거: §2.3 코어 1, 기존 한글·영문 이름 구상, F08·B06. 원문에 없는 전 언어 검색까지 약속하지 않음.
- 의존: 지원 대상 ID·명칭·별칭·검색 범위·US-08 연결. 검색 대상 필드는 구현 전에 확정.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 02-1 | 지원 대상에 공식명·등록 별칭이 있음 | 해당 전체 이름 또는 합의한 부분 문자열을 검색 | 일치 대상과 소속 구역을 표시하고 공식명으로 구별함 |
| 02-2 | 한글명과 검수한 영문 별칭이 같은 ID에 등록됨 | 어느 표기로 검색 | 같은 대상 ID의 설명으로 연결됨 |
| 02-3 | 검색어가 비었거나 공백뿐임 | 검색을 실행하거나 입력을 지움 | 전체 검색 결과처럼 오인시키는 무관한 답 대신 시작 안내·명시된 기본 목록을 표시함 |
| 02-4 | 지원하지 않는 이름·다른 궁궐·일치하지 않는 단어임 | 검색을 실행 | 0건과 현재 지원 범위·다른 탐색 경로를 표시하고 임의 결과를 정답으로 제시하지 않음 |
| 02-5 | 검색 결과에서 대상을 열었음 | 설명에서 뒤로 이동 | 직전 검색어와 결과 맥락을 복원함 |

#### US-03 지도에서 건물 직접 선택

- **As a** 위치와 주변 배치로 대상을 찾는 방문객으로서, **I want** 지도에서 건물을 골라 설명을 보고 싶다. **So that** 이름을 모르거나 촬영이 어려워도 탐색을 이어갈 수 있다.
- Priority: **Should 제안**. 근거: §2.3 코어 1. 기존 코어 묶음의 경로이므로 학기 필수 여부 재확인 필요. 테스트에서 언급되지 않았다는 이유로 삭제하지 않음.
- 의존: 검수한 지도·좌표·대상 ID·US-08. 길찾기·실내 정밀 위치는 별도 범위.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 03-1 | 지원 건물이 배치된 지도임 | 건물 표시를 선택 | 해당 건물 이름과 설명 진입을 표시하고 선택 지점과 대상 ID가 일치함 |
| 03-2 | 위치 권한이 없거나 위치를 모름 | 지도를 열고 수동 탐색 | 자동 현재 위치 없이도 지원 지도를 탐색·선택함 |
| 03-3 | 미지원 지점·지도 자료 로딩 실패임 | 선택 또는 지도를 열기 시도 | 미지원·실패를 구분해 안내하고 이름 검색 등 다른 경로를 제공함 |

#### US-04 현재 구역의 참고 사진에서 건물 찾기

- **As a** 현장 모습으로 건물을 알아보려는 방문객으로서, **I want** 선택한 구역의 참고 사진과 이름을 보고 대상을 고르고 싶다. **So that** 촬영이나 자동 인식이 없어도 원하는 설명에 도달할 수 있다.
- Priority: **Should 제안**. 근거: §2.3 코어 1, U11·U12, F08. 실제 구역 사진 경로와 현재 테스트용 장면 목록을 구별.
- 의존: 구역·사진·대상 연결과 이용 조건, US-08. GPS는 수동 구역 선택의 필수 조건이 아님.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 04-1 | 지원 구역을 수동 선택함 | 참고 사진 목록을 열기 | 선택 구역과 일치하는 대상의 이름·사진을 표시하며 실제 현장 촬영 결과로 표현하지 않음 |
| 04-2 | 참고 사진에서 지원 건물을 고름 | 설명 열기 | 선택한 사진의 대상 ID와 설명·명칭이 일치함 |
| 04-3 | 해당 구역 자료가 없거나 사진을 불러오지 못함 | 목록 확인 | 빈 상태·자료 오류와 검색·구역 변경 경로를 표시하며 다른 구역 자료를 현재 구역처럼 채우지 않음 |

### E2 대상 식별과 확인

#### US-05 찍은 사진으로 건물 후보 찾기

- **As a** 눈앞 건물의 이름을 모르는 방문객으로서, **I want** 사진을 찍거나 사용할 사진을 선택해 건물 후보를 찾고 싶다. **So that** 건물 이름을 먼저 알아내기 위해 여러 자료를 직접 뒤지지 않아도 된다.
- Priority: **Must 제안**. 근거: §2.3 코어 1·2, B01. 실제 사진 입력·식별은 이번 세 관찰로 구현·성능 검증되지 않음.
- 의존: 지원 건물·실제 이미지 입력·식별 방식·US-07·08의 결과 계약. 서버/브라우저/기기 내 처리와 모델은 미선정. 상세 흐름은 부록 B.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 05-1 | 지원 입력 환경에서 카메라 사용을 선택 | 촬영하고 사용을 확인 | 사용할 사진을 미리 확인·다시 고를 수 있고 취소한 사진은 식별 요청에 포함되지 않음 |
| 05-2 | 지원 형식의 사진과 검수한 건물 자료가 있음 | 식별 실행 | 입력 사진과 연결된 서로 다른 건물 후보·처리 상태를 반환하며 준비된 정답으로 바꿔치기하지 않음 |
| 05-3 | 카메라 권한 거부·촬영 취소·파일 오류 중 하나임 | 입력 시도 | 원인에 맞는 안내와 재입력 또는 이름 검색 경로를 제공함 |
| 05-4 | 미지원 대상이거나 판별 근거가 부족함 | 식별 종료 | 확정하기 어렵거나 지원 밖임을 알리고 보류·재촬영·다른 탐색으로 연결. 첫 후보를 자동 정답 처리하지 않음 |
| 05-5 | 실행 버전과 학습에 사용하지 않은 평가 사진을 고정함 | 정량 평가 | M1·M2의 정답 건물 기준 결과와 조건·실패·미지원 결과를 남김. 목표 미달을 달성으로 보고하지 않음 |

05-5는 평가 수행·보고 조건이다. M1·M2의 **제품 목표 충족 여부**는 별도 판정하며, 평가 실행만으로 제품 완료를 주장하지 않는다. 지원 형식·크기·실행 기기·실패/시간 초과 기준은 추정 전에 좁혀야 한다.

#### US-06 위치를 보조 단서로 후보 좁히기

- **As a** 현장에서 사진으로 건물을 확인하는 방문객으로서, **I want** 사용할 수 있는 현재 위치를 보조 단서로 활용하고 싶다. **So that** 비슷한 건물 후보 중 현재 상황에 맞는 대상을 찾는 데 도움을 받을 수 있다.
- Priority: **Must 제안**. 근거: §2.3 코어 2. 위치 허용 자체를 필수로 강제한다는 의미가 아님.
- 의존: US-05, 건물 좌표·위치 품질 처리·동의/취급 결정. 위치를 쓰기 전 사진만 결과와 비교하는 기술 Task 필요.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 06-1 | 위치 기능을 사용할 행동을 선택 | 위치 권한 요청 | 후보 탐색에 사용하는 목적을 알리고 허용 여부를 선택하게 함 |
| 06-2 | 유효한 위치와 사진이 있음 | 후보 산출 | 위치 적용 여부를 구분하고 가까운 건물이라는 이유만으로 사진 대상 확정을 하지 않음 |
| 06-3 | 권한 거부·위치 미수신·낮은 정확도임 | 사진 탐색을 계속 | 위치 한계를 알리고 사진만 탐색·수동 구역 선택 등 가능한 대체 경로로 이어짐 |
| 06-4 | 같은 평가 사진과 정답·위치 조건이 고정됨 | 사진만/사진+위치를 비교 | 정확도와 잘못 제외된 정답 사례를 함께 기록. 위치가 성능을 높였다고 미리 단정하지 않음 |

#### US-07 불확실한 결과의 근거를 보고 확인 또는 보류

- **As a** 후보를 확신하지 못하는 방문객으로서, **I want** 불확실한 이유와 구별 단서를 알고 확인하거나 판단을 보류하고 싶다. **So that** 모르는 정답을 억지로 고르거나 잘못된 설명을 믿는 상황을 피할 수 있다.
- Priority: **Must 제안**. 근거: §2.3 코어 3, F04·B04, R01~R03 S4. 필수는 신뢰·복구이며 비교 화면의 고정 형태가 아님.
- 의존: 후보 ID·대표 사진·검수된 차이 단서·US-08. 모델의 확신값을 곧바로 사용자 신뢰도로 부르지 않음.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 07-1 | 식별 결과를 확정하지 못한 상태임 | 결과 확인 | 아직 확정되지 않았고 무엇을 확인하려는지 알림. 퀴즈 정답 선택을 요구하지 않음 |
| 07-2 | 여러 후보를 제공함 | 비교 내용을 확인 | 입력 사진과 참고 사진을 구별하고 현판·외관·위치 등 확인 가능한 단서를 사진 위치와 함께 제시함 |
| 07-3 | 확인 가능한 후보를 사용자가 선택함 | 설명으로 이동·후보를 변경 | 선택한 후보 ID에 맞춰 이름·사진·설명이 모두 갱신되고 이전 후보의 내용이 섞이지 않음 |
| 07-4 | 어느 후보도 확신할 수 없음 | 해당 없음·판단 보류·다시 찾기를 선택 | 후보를 확정하지 않고 원래 사진·재입력·수동 탐색 중 표시된 목적의 경로로 복구함 |
| 07-5 | 비교 목적을 미리 설명받지 않은 사용자가 결과를 받음 | 왜 이 결과를 보여주는지·확신 없을 때 할 일을 설명 | 비교 목적·보류 경로에 대한 이해를 별도 기록. 버튼을 눌렀다는 이유만으로 이해했다고 처리하지 않음 |

#### US-10 궁금한 부분을 지정하고 설명 확인

- **As a** 건물의 일부가 궁금한 방문객으로서, **I want** 건물 전체와 특정 부분을 구분해 표시하고 필요하면 고치고 싶다. **So that** 이름을 모르더라도 실제로 관심 있는 부분의 의미를 알아볼 수 있다.
- Priority: **Should 제안, 상향 검토**. 근거: §2.3 부가 5, U02·U03, F01·F03·F05, B01·B03, S04. 제한된 부분 탐색의 긍정과 미지원·이해 문제를 함께 반영.
- 의존: 지원 부분의 자료·선택 범위·건물 ID·US-08·09. 자유로운 부분 자동 인식과 준비된 일부 부위 선택은 다른 구현 수준.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 10-1 | 건물 전체와 지원 부분 탐색을 제공함 | 알아보기 시작 | 두 목적을 구분하며 건물 전체 설명을 보기 위해 부분 선택을 강요하지 않음 |
| 10-2 | 사진에서 지원하는 부분을 선택 | 선택을 확인·수정 | 현재 보이는 영역에서 선택 반응과 다음 행동을 확인하고 표시·이름·설명이 같은 부분을 가리킴 |
| 10-3 | 확대 상태 또는 잘못된 선택임 | 확대를 종료하거나 다시 선택 | 사진과 탐색 맥락으로 복귀하고 이전 선택 표시가 다른 대상 설명에 남지 않음 |
| 10-4 | 미지원 부위 또는 자료 없는 목재·문양 등을 선택 | 설명 요청 | 한계와 재선택 경로를 알리고 수종·의미를 추측해 다른 부위의 설명으로 채우지 않음 |

### E3 대상 설명과 이해

#### US-08 대상의 기본 설명과 근거 확인

- **As a** 대상을 확인한 방문객으로서, **I want** 공식 명칭·위치·핵심 쓰임과 출처를 함께 보고 싶다. **So that** 지금 보고 있는 것이 무엇인지 신뢰할 수 있는 정보로 이해할 수 있다.
- Priority: **Must 제안**. 근거: §2.3 코어 4, U05·U10·U12, F02·F03, B03. 설명은 인식 결과 뒤에 붙이는 부가 장식이 아님.
- 의존: 검수한 대상·설명·출처 계약. 검색·지도·인식 모두 같은 대상 ID를 사용. 실제 이해와 화면 구현 검사를 구분.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 08-1 | 지원 대상 ID가 확인됨 | 기본 설명을 열기 | 그 대상의 공식 명칭·위치 맥락·짧은 핵심 설명·출처를 표시함 |
| 08-2 | 품계석 등 낯선 말이 포함됨 | 설명을 확인 | 쉬운 말 풀이와 사진 속 대상의 위치를 연결해 확인하며 이름만 반복하지 않음 |
| 08-3 | 출처를 확인하려고 함 | 근거 자료를 열고 복귀 | 해당 설명의 출처에 접근하고 원래 대상·설명 위치로 돌아옴 |
| 08-4 | 설명 또는 출처 자료가 누락·불일치함 | 대상 설명 요청 | 확인되지 않은 내용을 생성해 채우지 않고 누락 상태와 다른 탐색·복귀 경로를 표시함 |
| 08-5 | 참여자가 처음 보는 대표 설명을 읽음 | 쓰임을 자기 말로 설명하고 사진에서 대상을 가리킴 | 설명 재현·대상 연결·남은 질문을 기록하고 화면 도달과 내용 이해를 별도로 판정함 |

#### US-09 필요한 만큼 맥락 설명과 관련 질문 보기

- **As a** 기본 설명 뒤에도 궁금한 점이 남은 방문객으로서, **I want** 더 읽거나 관련 질문을 골라 구체적인 설명을 보고 싶다. **So that** 긴 글을 모두 읽지 않아도 관심 있는 쓰임·연혁·생활·건축 맥락을 이해할 수 있다.
- Priority: **Must 제안**. 근거: §2.3 코어 4, U04~U06, F03·F09, B02·B03, R03·S04. 개별 상세 주제의 수록 범위는 미정.
- 의존: US-08, 대상별 검수된 추가 설명·질문·답변. 질문은 현재 선택형 방향이며 자유 입력·LLM 채택을 뜻하지 않음.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 09-1 | 기본 설명과 더 읽기가 있음 | 상세를 펼쳤다가 접기 | 같은 대상의 핵심 설명·사진·탐색 맥락을 유지함 |
| 09-2 | 준비된 질문 목록을 제공함 | 질문 영역과 특정 질문을 선택 | 선택형임을 드러내고 현재 대상 이름·고른 질문·해당 답변을 함께 표시함 |
| 09-3 | 질문·답변이 준비되지 않았거나 연결이 없음 | 해당 부분을 열기 | 제공 한계를 알리고 기본 설명·다른 질문으로 복귀하며 자유 입력란을 찾아야 한다는 잘못된 안내를 하지 않음 |
| 09-4 | 연혁·전쟁 이력·재료·생활·배치 이유의 검수 자료가 있음 | 해당 상세 내용을 확인 | 대상·부위·시기와 출처를 연결. 창건·중건·복원을 구분하고 경과 연수 기준을 명시. 근거 없는 전쟁 이력·목재 수종을 단정하지 않음 |

#### US-16 글을 읽기 어려울 때 설명 듣기

- **As a** 현장에서 긴 글을 읽기 어려운 방문객으로서, **I want** 선택한 대상의 검수된 설명을 소리로 듣고 싶다. **So that** 화면을 계속 읽지 않아도 필요한 설명을 확인할 수 있다.
- Priority: **Could 제안**. 근거: R02 자유·마지막의 음성 제안. 여러 칸의 같은 의견을 여러 사람의 요구로 세지 않음.
- 의존: US-08·09, 음성 자료·언어·이용 조건. 어려운 글을 읽어주기만 하면 이해 문제가 해결된다고 가정하지 않음.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 16-1 | 현재 대상의 검수된 음성 설명이 있음 | 사용자가 재생 선택 | 해당 대상의 음성을 재생하고 재생·정지 상태를 확인함 |
| 16-2 | 음성이 재생 중임 | 중지하거나 다른 대상으로 이동 | 기존 음성이 멈추고 다른 설명과 겹치지 않음 |
| 16-3 | 음성 없음·재생 실패 또는 소리를 쓰기 어려움 | 설명 확인 | 텍스트와 출처에 접근하고 음성을 강제로 재생하지 않음 |

### E4 관람 탐색 이어가기

#### US-11 설명 뒤 같은 장면과 다른 탐색으로 이동

- **As a** 설명을 읽은 방문객으로서, **I want** 같은 사진의 다른 부분을 살피거나 새 탐색을 시작하고 돌아오고 싶다. **So that** 관심 흐름이 끊기거나 이전 내용을 잃지 않는다.
- Priority: **Must 제안**. 근거: U09, F02·F05·F08, B02·B05. 로고 홈은 채택 가능한 이동 수단 중 하나.
- 의존: 진입 경로·대상·사진·선택·검색어 복원 규칙. 추천·카드와 독립된 기본 이동.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 11-1 | 사진에서 설명으로 진입 | 같은 사진으로 돌아가기 | 원래 사진·대상과 합의한 선택 맥락을 복원하고 다른 부분을 고름 |
| 11-2 | 관련 질문 답변을 보는 중임 | 직전 설명으로 이동 | 그 대상의 기본 설명과 질문 맥락으로 복귀하고 다른 건물 내용과 섞이지 않음 |
| 11-3 | 설명에서 다른 대상 찾기를 선택 | 표시된 검색·새 사진 경로 실행 | 행동 이름과 일치하는 탐색을 시작하고 정한 이력 규칙에 따라 이전 설명에도 복귀함 |
| 11-4 | 홈 이동 수단이 제공됨 | 해당 수단을 누름 | 일관되게 홈에 도달. 로고를 조작부로 쓰면 식별·키보드 접근이 가능하며 실제 동작함 |

#### US-12 관심이 있을 때만 호기심 카드 열기

- **As a** 아직 구체적인 질문이 없는 방문객으로서, **I want** 작은 발견 제안을 보거나 지나치고 싶다. **So that** 새로운 관람 포인트를 찾되 내 탐색을 방해받지 않는다.
- Priority: **Could 제안**. 근거: U07·U08·U11, 기존 홈 방향. R03 S3는 사진 탐색 진입이므로 이 카드의 효과 근거로 쓰지 않음.
- 의존: US-08·09, 검수된 카드·대상 관계. 설명 뒤 다음 장소 제안과 다른 기능.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 12-1 | 홈에 호기심 카드를 제공함 | 처음 홈을 확인 | 카드가 주 탐색을 막지 않고 검색·사진 탐색을 바로 선택함 |
| 12-2 | 카드에 관심이 있음 | 카드를 선택 | 카드에 제시한 대상·질문과 일치하는 설명·출처로 연결됨 |
| 12-3 | 카드에 관심이 없거나 방문 전 예시임 | 건너뛰거나 예시를 확인 | 별도 완료 없이 직접 탐색하고 예시를 현재 위치 기반 추천으로 오인시키지 않음 |

#### US-13 다음에 볼 한 장소와 연결 이유 확인

- **As a** 한 대상의 설명을 본 방문객으로서, **I want** 다음에 볼 수 있는 장소의 위치와 연결 이유를 알고 선택하고 싶다. **So that** 다음 관람을 판단할 때 맥락을 얻을 수 있다.
- Priority: **Should 제안**. 근거: F08·B05, R01 S1·R03 마지막, 기존 관람 흐름 구상.
- 의존: 검수한 장소 관계·위치 맥락·US-08·11. 개인화 코스·실시간 길찾기·혼잡 최적화와 구분.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 13-1 | 다음 장소 제안 자료가 있음 | 제안을 확인 | 장소 이름·상대 위치 맥락·연결 이유를 제시함 |
| 13-2 | 제안을 선택하거나 무시함 | 설명 열기 또는 새 탐색 | 선택 목적에 맞게 이동하며 제안을 선택해야만 계속 사용할 수 있게 하지 않음 |
| 13-3 | 실제 위치·경로 계산 없이 고정 제안만 있음 | 안내 확인 | 고정된 관계 제안임을 구분하고 실시간 최단 경로·소요 시간·혼잡 완화를 약속하지 않음 |

#### US-14 시간과 관심사에 맞는 관람 코스 검토

- **As a** 남은 관람 시간을 고려하는 방문객으로서, **I want** 현재 구역·남은 시간·관심사에 맞는 코스 후보를 보고 싶다. **So that** 한정된 시간에 다음 관람 대상을 고를 때 참고할 수 있다.
- Priority: **Could 제안**. 근거: 문제정의서 §2.2.3 부가 구상. R03의 관람 순서 제안은 추가 단서이며 효과 증거가 아님.
- 의존: 장소·이동/관람 시간 자료·정책·입력 범위 확정. 큰 Story 후보이므로 채택 시 가장 작은 한 코스로 축소·재추정.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 14-1 | 지원 구역·시간·관심 조건과 검수된 코스 자료가 있음 | 조건을 선택 | 적용한 조건과 코스의 장소 순서·제안 이유를 확인함 |
| 14-2 | 자료가 없거나 시간 조건을 충족하는 코스가 없음 | 제안 요청 | 없음과 수동 탐색 대안을 제시하고 부정확한 코스를 조건에 맞는 것처럼 표시하지 않음 |
| 14-3 | 시간·경로가 추정값임 | 코스를 확인 | 추정의 기준·한계를 표시하고 실제 관람 완료·혼잡 분산 효과로 주장하지 않음 |

#### US-15 경복궁 관심을 종로의 관련 장소로 연결

- **As a** 경복궁 관람 뒤 관련 경험을 찾는 방문객으로서, **I want** 관심 주제와 연결된 종로 장소의 정보와 근거를 보고 싶다. **So that** 관람 뒤 무엇을 더 볼지 선택할 수 있다.
- Priority: **Could 제안**. 근거: 문제정의서 §2.2.3·발표자료의 부가 범위. 이번 세 테스트의 신규 요구로 표현하지 않음.
- 의존: 검수된 장소·주제 관계·출처. 전국 추천·상업 예약·결제는 포함하지 않음.

| AC | Given | When | Then |
| --- | --- | --- | --- |
| 15-1 | 관련 장소 자료가 있음 | 관심 주제의 연계 정보를 확인 | 장소 이름·지역·연결 이유·정보 출처를 표시함 |
| 15-2 | 연계 장소를 선택 | 정보 열기 | 선택한 장소의 정보로 이어지고 경복궁 설명으로 복귀함 |
| 15-3 | 검수한 연계 자료가 없거나 외부 정보 연결 실패임 | 결과 확인 | 준비되지 않았음을 알리고 무관한 추천·광고로 채우지 않음 |

### 4.2 보존하되 채택하지 않은 대안

긴 튜토리얼, 로고 중심 시작 화면, 3D 중심 홈은 US-01의 해법 후보다. F07·S01·S02의 시각적 선호와 첫 유용한 결과 도달 효과를 구분한다. 3D를 유지한다면 재생·로딩·실패·대체 경로는 품질 조건으로 확인한다. 이 제안만으로 새 제품 Story를 만들지 않는다.

정규 영어 해설 일정·기존 Odii/공식 자료 안내는 아이디에이션의 대안으로 보존한다. 필요할 때 원래 과업으로 돌아갈 수 있는 외부 안내로 검토하며 별도 알림·예약 시스템으로 확대하지 않는다. 영문 이름 검색과 전체 다국어 UI는 서로 다른 범위다.

- [ ] 팀/개인 추정 방식을 사실대로 기록하고 DoD·우선순위를 승인했다.
- [ ] 채택한 상세 Story를 양식 5-1에 한 건당 한 파일로 옮기고 예시·작성 가이드를 제거했다.
- [ ] 제출 Word의 표지·역할·개인 정보·최종 일정과 교수 안내를 확인했다.
- [ ] 최종 제출 자료를 승인·제출했다. 로컬 작성·문서 검사와 구분한다.

위 미완료 항목 때문에 현재 문서를 ‘최종 제출본’ 또는 ‘Sprint Ready’라고 표시하지 않는다. 추정이 없는데도 DEEP 전체를 충족했다고 체크하지 않는다.

### 8.2 사용자가 검토할 핵심 판단

1. **선별된 부분 탐색의 학기 우선순위:** 제출본 부가를 유지하는 Should와, 현재 서비스 중심 경험으로 제한된 부위만 Must로 올리는 안 중 결정. 자동 수종·모든 문양 인식과는 구별한다.
2. **첫 릴리즈의 탐색 경로:** 이름 검색·사진 식별은 Must 제안. 지도와 구역 사진은 보존하되 각각 학기 필수인지 판단한다. 모든 경로를 동시에 완성할 용량은 아직 확인하지 않았다.
3. **불확실한 결과 확인 방식:** 불확실성·근거·보류·다른 탐색은 Must로 두고 비교 화면 자체는 목적 이해를 보고 조정하는 안을 검토한다.
4. **설명 범위와 부가 기능:** 핵심 설명·출처·단계형 맥락은 Must, 연혁·생활·재료의 실제 수록 목록은 자료를 보고 결정. 음성·코스·종로·3D는 첫 결과에 주는 도움과 용량을 보고 채택한다.

첫 경험의 가치 이해를 우선하는 방향은 사용자 지정사항으로 반영했다. 구체적인 홈 UI와 온보딩 방식까지 승인된 것으로 넓히지 않는다. 위 범위 판단 후 실제 가용 시간과 SP를 정하고 제출본을 확정한다.

## 부록 B 상위 Story를 상세 양식으로 옮길 내용

공통 정보: 작성 지원일 2026-10-17, 최종 작성자·승인자는 제출본에서 확인. SP·담당·Sprint 미정, 상태는 검토 전 초안, AC 검증·일자는 전부 미실행. §3의 AC를 같은 ID로 재사용한다. DoD는 §6의 체크 항목 전체를 적용한다. 아래 Task에는 담당·시간·완료 결과를 임의로 채우지 않는다. 양식의 2~12시간 Task 분할은 실제 Sprint Planning에서 한다.

### B.1 US-01 상세 초안 Simple 구성 후보

Description: 방문 전 예시와 현장 탐색을 구분하고 현재 제공하는 도움·첫 행동·예상 결과가 이어지게 한다. 첫 결과는 이름만 출력하는 상태가 아니라 선택한 대상의 설명을 확인하는 상태다. 앞단 UI만 만들고 이해 검증을 생략하지 않는다.

Task 후보: 대표 사용자 상황·첫 결과 정의 → 안내/행동 이름과 결과 화면 연결 → 예시/실제 구분·빈 상태 → 기능 검사와 첫 이해 관찰 기록. 각 Task 완료 기준은 차례로 승인된 상황·결과 계약, 동작하는 한 경로, 오인 없는 상태 표시, 버전·행동·도움 수준이 남은 결과다.

Out of Scope: 강제 긴 튜토리얼, 별도 로고 대기, 회원가입, 3D 필수화, 재방문율 개선 주장.

Demo: 지원 밖 이름으로 범위·대안을 확인 → 지원 대상 첫 탐색 → 기대한 기본 설명 → 예시 표시와 실제 입력 방법 구분. 별도 첫 사용 관찰에서는 도움·행동·예상 결과를 먼저 설명하도록 한다.

INVEST 검토: 사용자 가치·테스트 방식은 서술됨. 대표 콘텐츠·시작 경로·UI 결과 계약과 추정이 남아 있으므로 Estimable·Small·Ready 전체 통과로 체크하지 않는다.

### B.2 US-08 상세 초안 Simple 구성 후보

Description: 하나의 대상 ID에 공식 명칭·위치·핵심 설명·사진에서의 대상 위치·출처를 연결한다. 건물과 세부 부위의 설명이 섞이지 않도록 한다. 대표 설명의 이해를 제작자 검수와 별도로 확인한다.

Task 후보: 대상·출처·사진 이용 조건 검수 → 기본 설명·용어 풀이 → 출처 열기/복귀와 누락 처리 → AC·이해 관찰. 완료 기준은 대상-출처 연결 목록, 대표 설명 표시, 누락·복귀 재현, 검증/관찰 기록이다.

Out of Scope: 자유 생성 답변, 모든 상세 주제, 출처 없는 전쟁·수종 추정, 전체 다국어 UI.

Demo: 설명 없는 대상의 누락·복귀 → 지원 대상 명칭·위치·쓰임 → 용어 풀이 → 출처 열기·복귀. 이해 관찰에서는 쓰임을 자기 말로 설명하고 해당 부분을 가리키는지 별도 확인한다.

INVEST 검토: 한 대상의 읽기 흐름으로 축소해 시연 가능. 콘텐츠 검수·표시 계약·지원 언어를 정하고 추정한 뒤 Small을 판정한다.

### B.3 US-02 상세 초안 Simple 구성 후보

Description: 지원 대상의 공식명·등록 별칭·선택한 검색 필드를 탐색하고 설명으로 연결한다. 전체/부분 일치·공백 처리·영문 별칭의 검색 규칙은 Sprint 착수 전 고정한다. 외부 웹 전체 검색이 아니다.

Task 후보: 검색 필드·일치 규칙/픽스처 확정 → 결과·0건·빈 입력 → 대상 설명·뒤로 복원 → 정상/오류 검사. 완료 기준은 고정된 입력-대상 기대값, 빈/0건의 구별, 설명 ID·검색어 복원, AC 증거다.

Out of Scope: 전 세계 장소, 자동 번역 검색, 별칭 자동 생성, 외부 검색 엔진 구축.

Demo: 빈 입력 → 한글 전체/부분 검색 → 검수 영문 별칭 → 없는 이름·다른 궁 → 설명 열기·검색 복귀.

INVEST 검토: 이름 검색의 가치와 예외는 정의됨. 부분 문자열·설명 단어 범위가 미확정이므로 아직 완전한 추정 가능 상태가 아니다.

### B.4 US-05 상세 초안 Full 구성 후보

Business Value: 건물 이름을 몰라도 사진으로 설명을 찾는 핵심 경로. 사용자가 직접 자료를 대조하는 부담을 줄일 가능성을 검증한다.

Domain State Change: 입력 사진 대기 → 사용 확인 → 식별 요청 중 → 후보/확정 어려움/실패 → 사용자 확인 또는 다른 탐색. 건물·해설 원본은 조회 중 변경하지 않는다. 사진·요청의 영속 저장 여부는 미정이다.

Preconditions: 지원 건물·식별 결과 계약·실행 환경·권한/입력 방식·사진 취급 정책이 정해져 있음. 위치 권한과 로그인은 기본 전제에 넣지 않음.

Main Flow:

1. 방문객이 사진 탐색을 선택한다.
2. 시스템이 필요한 입력과 사용 목적을 안내한다.
3. 방문객이 촬영하거나 지원 사진을 고르고 미리 본 뒤 사용을 확인한다.
4. 시스템이 처리 중 상태와 취소/실패 처리를 제공하고 실제 식별을 실행한다.
5. 시스템이 해당 입력과 연결된 후보 또는 확정하기 어려운 상태를 전달한다.
6. 방문객은 근거로 확인하거나 보류·다른 탐색을 선택한다. 확인한 대상은 US-08로 연결한다.

Alternate/Exception: 권한 거부·취소 → 검색·다른 입력, 파일 형식/크기 오류 → 허용 조건과 재선택, 로딩/연결/시간 초과 → 실패 상태·재시도, 지원 밖/근거 부족 → 확정하지 않고 보류·다른 탐색. 늦게 도착한 이전 요청이 새 사진의 결과를 덮어쓰지 않도록 요청-사진 ID를 연결한다.

Postconditions: 사용자가 확인한 대상 또는 미확정/실패 상태가 분명하며 입력과 관계없는 설명을 보여주지 않음. 취소·보류를 성공으로 집계하지 않음.

Task 후보: 지원 건물·평가셋·누출 방지 규칙 → 입력/결과/오류 계약 → 식별 기준 방식 비교 → 사진 입력과 화면 상태 통합 → 예외·정량 평가. 각각 목록·분할 근거, 명세와 기대값, 같은 데이터 조건의 결과, 실행 가능한 한 경로, AC·평가 보고를 완료 기준으로 삼는다. 모델 비교 자체를 사용자 Story 완료와 동일시하지 않는다.

Persistence Rule: 사진·요청 ID·후보 대상 ID의 관계를 유지한다. 실제 사용자 사진의 전송·보관·삭제·로그 범위는 도입 전 정하고 명시한다. 현재 프로토타입의 메모리 저장을 제품 정책으로 자동 채택하지 않는다. 원본 사진·GPS·비밀정보를 공개 기록에 넣지 않는다.

Out of Scope: 모든 건물/부분 자동 인식, 자유 질문 생성, 위치로 강제 정답 결정, 실제 기기 미검증 상태의 온디바이스 성능 주장.

Demo: 권한 거부·수동 탐색 → 정상 사진 입력·사용 확인 → 후보와 근거 → 미지원·판단 보류 → 입력 취소·재시도. M1·M2 평가는 별도 고정 평가셋으로 보고한다.

INVEST 검토: 기술 불확실성이 커서 현재는 즉시 착수 가능한 작은 Story로 확정하지 않음. 지원 건물·입력·실행 환경을 좁혀 추정하고 13 SP를 넘으면 사용자 가치가 남는 흐름으로 분할한다. Full 형식 선택이 13 SP 확정을 뜻하지 않는다.

### B.5 US-07 상세 초안 Simple 구성 후보

Description: 후보 수를 늘려 사용자의 정답 지식을 시험하지 않는다. 어떤 결과가 불확실한지·참고 사진과 입력의 관계·구별 단서를 알리고 보류·재입력·수동 탐색을 열어 둔다. 한 결과만 보이는 안도 불확실성을 숨기면 채택하지 않는다.

Task 후보: 대표 모호 사례·후보/단서 검수 → 목적·불확실성 안내 → 입력/참고 구별·후보 변경 → 보류/복구·이해 관찰. 완료 기준은 확인 가능한 단서 목록, 확정/미확정 표현 구분, 대상 무결성, 보류 동작·목적 이해 기록이다.

Out of Scope: 항상 비교 화면 노출, 선택 강요, 모델 유사도를 정답 확률로 단정, 모든 후보의 설명 자동 생성.

Demo: 후보 없는 상태 → 비교 필요 이유·입력/참고 사진 → 근거 확인·후보 변경 → 어느 것도 모를 때 보류·새 탐색. 사용자가 목적과 보류 방법을 어떻게 이해하는지는 클릭 성공과 따로 기록한다.

INVEST 검토: 준비된 후보 fixture로 UI를 독립 검사할 수 있으나 이는 실제 AI 검증이 아님. 제품 통합의 결과 계약·대표 단서·추정이 남음.

## 부록 C 보고서와 발표로 이어갈 구조

기존 Word 아이디에이션 보고서의 문제 원인→문제 정의→아이디어→수렴→프로토타입 구조를 참고하되, 이번 제출은 양식 5를 본문 순서로 삼는다. 최신 문제정의서는 작성 내용이 들어 있는 PDF를 확인했으며, 빈 `[양식 4] 문제정의서 양식.docx`를 제출한 보고서로 간주하지 않는다.

발표 구성 후보: 기존 문제·개발 범위 → 무엇을 만들고 어떤 조건에서 세 관찰을 했는지 → 반복된 불편과 해석 한계 → Epic·상위 Story·대표 GWT → 우선순위의 이유와 보존/제외 판단 → 미정 추정·Sprint 0 준비·후속 검증. 첫 경험은 이 흐름에서 중요한 개선 판단으로 설명한다.

PPT는 백로그의 목록을 그대로 붙이기보다 대표 상황 하나와 수정된 수용 조건을 보여주는 방향을 제안한다. 대본은 짧고 자연스러운 정중체로 작성하고 실제 성과와 제안을 구분한다. 발표 시간·슬라이드 수는 미정이며, 현재 초안의 범위 판단 후 확정된 내용으로 제작한다.
