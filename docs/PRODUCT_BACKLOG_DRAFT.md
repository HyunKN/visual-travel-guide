# Product Backlog — 4차 작성본 공개 요약

기준: 사용자가 작성·수정한 Product Backlog 4차 작성본과 「PPT 구성 이어가기」에서 최종 검수한 12개 개별 User Story. 공개 요약 갱신일: 2026-10-19.

이 문서는 초기 AI 검토 초안을 대체한다. 기존 링크와 Wiki 주소를 유지하기 위해 파일명 `PRODUCT_BACKLOG_DRAFT.md`와 페이지명 `Product-Backlog-Draft`를 유지하지만, 아래 Story ID·우선순위·배치는 **4차 작성본 기준**이다. 초기 4 Epic·16 Story·SP 미정 상태를 현재 계획으로 사용하지 않는다. 이전 내용은 [초기 초안의 Git 이력](https://github.com/HyunKN/visual-travel-guide/blob/21ecc3c95907ee03905ea248c650f86171c0c74a/docs/PRODUCT_BACKLOG_DRAFT.md)에서 확인한다.

원본 Word와 개별 US 제출 문서는 비공개 작업 자료로 보존한다. 이름·학번·연락처·개인 경로·작성자 메타데이터·참여자 원문은 이 공개 요약에 포함하지 않는다. 아래에는 제품 범위, Story·GWT, 추정·배치, 운영 기준만 옮겼다. 제출 서식 전체와 개별 US의 상세 Task·Demo를 대체하지 않는다.

## 기준과 적용 경계

- 4차본과 개별 US는 US-08 누락 보완, US-05 AC-02 위치 조건 일치, 12개 문서의 공통 DoD 통일을 거쳐 발표자료의 내용 기준으로 채택됐다. 개발 계획을 불필요하게 미확정으로 되돌리지 않는다.
- SP는 **상대 추정 가안**, Sprint 배치는 현재 계획이다. 전체 46 SP 중 Must 39 SP를 배치했고 Should 7 SP는 미배치다. SP를 시간으로 환산하거나 아직 없는 velocity를 실적으로 표시하지 않는다.
- DoD 채택은 운영 규칙의 확정이다. 개별 Story의 완료 체크는 구현·검증 후 수행하며, 실패·미실행 AC가 남으면 Done으로 표시하지 않는다.
- [세 사용자 관찰](prototype/OBSERVATION_RESULTS.md)은 탐색적 사용성 근거다. 실제 AI·GPS·현장 성능·일반 성공률·재사용 효과의 검증 결과가 아니다. P01~P08 프로토타입 과업을 제품 Story 완료로 환산하지 않는다.
- 실제 진행·종료 근거는 [프로토타입 상위 Issue #4](https://github.com/HyunKN/visual-travel-guide/issues/4)와 [P08 Issue #13](https://github.com/HyunKN/visual-travel-guide/issues/13)에 기록한다. 제품 구현·제출·발표 완료 여부는 각각의 실제 증거로 판단한다.

## 1. 제품 가치와 Success Metrics

경복궁을 자유 관람하는 방문객이 처음 진입했을 때 어떤 도움을 받고 무엇부터 하면 어떤 결과를 얻는지 이해하도록 한다. 이름·지도·구역 사진·직접 촬영 등 가진 단서에 맞게 시작하고, 사진 중심의 식별과 선택적 위치 보정을 통해 건물 후보를 확인한다. 불확실하면 구별 근거와 재탐색 경로를 제공하고 공식 명칭·위치·출처 있는 설명에서 자유 관람으로 이어간다.

아래 수치는 **향후 제품 평가 목표**다. 세 명의 모의 관찰로 달성한 수치가 아니다.

| 번호 | 지표 | 목표치 | 측정 방법 · 시점 |
| --- | --- | --- | --- |
| 1 | 사진·위치 기반 건물 식별 성능(정량) | Top-1 ≥ 80%; 정답이 Top-3 후보에 포함 비율 ≥ 90% | 학습에 쓰지 않은 건물 사진을 거리·방향·조명별로 확보하여 평가합니다. 위치 결합 전후도 따로 비교합니다. 다만 이는 실제 AI 구현 후 측정합니다. |
| 2 | 대상 탐색 과제 성공률(정량) | ≥ 85% | 실제 건물 확인→근거 있는 해설 도달 여부를 검색·지도·사진·후보 비교 과제에서 기록합니다. 도움 여부와 실패를 구분합니다. |
| 3 | 대상 설명 도달 시간 감소율(정량) | 기존 지도·검색 방식 대비 평균 ≥ 30% 단축 | 유사 난이도·서로 다른 대상을 이용해 사용 순서를 교차 배치합니다. 성공한 과제 시간과 전체 실패율을 함께 기록합니다. |
| 4 | 현장 궁금증 해결 유용성(정량·정성) | 5점 척도 평균 ≥ 4.0 | 실제 대상과 정보 연결 및 해설 도움 여부를 5점 척도와 짧은 인터뷰로 평가합니다. 모의 관찰 3명으로 달성 여부를 주장하지 않습니다. |

## 4. User Story와 수용 조건

다음 Story·GWT·근거는 4차 작성본의 본문이다. 각 AC는 앞으로 실행할 제품 수용 조건이며, 현재 프로토타입의 통과 기록이 아니다.

### US-01  첫 진입에서 서비스 가치 체감과 탐색 시작

Epic: E1 관람 시작과 대상 탐색 · Priority: Must · 추정: 3 SP (가안)

- As a: 경복궁에서 앱을 처음 이용하는 방문객으로서
- I want: 현장에서 이 앱으로 해결할 수 있는 궁금증과 얻을 수 있는 결과를 확인하고 곧바로 탐색해 보고 싶습니다.
- So that: 실제 관람에 어떤 도움이 되는지 빠르게 판단하고 관심 있는 대상을 스스로 찾아보기 위해서입니다.

| AC ID | Given (상황) | When (행동) | Then (결과) |
| --- | --- | --- | --- |
| AC-01 | 처음 서비스를 방문한 상태 | 첫 화면을 확인하면 | 경복궁에서 해결할 수 있는 대표 궁금증과 탐색 후 얻는 결과를 연결해 볼 수 있습니다. |
| AC-02 | 현재 이용 가능한 탐색 경로와 예시가 구분되어 표시된 상태 | 관심 있는 시작 경로를 선택하면 | 현재 지원하는 탐색으로 진입하며 미구현 경로와 예시 결과를 실제 제공 기능으로 오해하지 않습니다. |
| AC-03 | 첫 건물 또는 명시된 예시 결과를 확인한 상태 | 결과를 살펴보면 | 대상의 명칭과 현재 제공되는 설명을 확인하고, 이용 가능한 다음 탐색 경로를 알 수 있습니다. |

근거: 4주차 §2.3 코어1; R02·R03 F10·B06, S05. 첫 도움 체감·추가 탐색 의향은 추후 별도 사용성 평가

### US-02  알고 있는 건물 이름으로 검색

Epic: E1 관람 시작과 대상 탐색 · Priority: Must · 추정: 3 SP (가안)

- As a: 건물 이름이나 일부 명칭을 알고 있는 방문객으로서
- I want: 알고 있는 이름으로 경복궁의 지원 건물을 찾아보고 싶습니다.
- So that: 사진을 찍지 않아도 관심 있는 건물의 정보를 빠르게 확인하기 위해서입니다.

| AC ID | Given (상황) | When (행동) | Then (결과) |
| --- | --- | --- | --- |
| AC-01 | 지원 건물 정보가 등록된 상태 | 정확한 건물 이름으로 검색하면 | 해당 건물의 명칭·대표 사진과 설명으로 들어가는 경로가 나타납니다. |
| AC-02 | 지원 건물 명칭의 일부를 알고 있는 상태 | 일부 명칭으로 검색하면 | 일치하는 지원 건물을 보여주고 무관한 결과를 정답처럼 표시하지 않습니다. |
| AC-03 | 경복궁 같은 구역 명칭 또는 덕수궁 같은 지원 범위 밖 명칭을 검색한 상태 | 검색 결과를 확인하면 | 구역 탐색과 범위 밖 안내를 상황에 맞게 구분하고 사용할 수 있는 대체 탐색 방법을 제시합니다. |

근거: 4주차 §2.3 코어1; R01·R02 F08. 타 궁궐·전체 관광지로 검색 범위 확대하지 않음

### US-03  지도·구역 사진에서 건물 탐색

Epic: E1 관람 시작과 대상 탐색 · Priority: Must · 추정: 5 SP (가안)

- As a: 건물 이름을 모르지만 주변 위치나 외관을 단서로 찾는 방문객으로서
- I want: 경복궁 지도와 구역별 대표 사진을 통해 관심 있는 건물을 선택하고 싶습니다.
- So that: 카메라를 쓰지 않더라도 눈앞의 위치·외관 단서를 이용해 탐색을 시작하기 위해서입니다.

| AC ID | Given (상황) | When (행동) | Then (결과) |
| --- | --- | --- | --- |
| AC-01 | 지원 구역·건물 위치·대표 사진이 등록된 상태 | 지도 또는 구역 사진 목록을 열면 | 건물의 명칭·사진·위치 관계를 살펴볼 수 있습니다. |
| AC-02 | 지도나 구역 사진 목록에서 건물을 고른 상태 | 상세 정보를 선택하면 | 선택한 건물과 일치하는 명칭·대표 사진·설명으로 이동합니다. |
| AC-03 | 현재 위치가 없거나 부정확한 상태 | 지도 또는 사진 목록을 이용하면 | 구역을 직접 골라 탐색할 수 있으며 검증되지 않은 위치를 현재 위치처럼 표시하지 않습니다. |

근거: 4주차 §2.3 코어1, TO-BE 시나리오 4; R01 F08. GPS 없을 때 수동 구역 선택 가능

개별 US의 상세 Task·Demo에서는 다음 경계도 유지한다. US-05는 요청 오류·무응답과 낮은 신뢰도를 구분하고 재입력하도록 한다. US-06은 선택 후보와 동일한 건물 ID의 US-08 설명으로 연결하며 사용자 선택을 AI가 검증한 정답처럼 표시하지 않는다. US-12의 미지원 영역은 선택 상태를 만들지 않고 지원 범위를 안내한다.

## 5. 이번 학기 제외 범위

1. 사용자 촬영 사진의 임의 세부 부위 자동 인식. US-04·05는 건물 단위, US-12는 등록 사진의 사전 지정 요소를 다룬다. 수종 자동 식별도 채택하지 않았다.
2. 취향·잔여 시간·혼잡 기반 자동 코스 최적화. US-10의 기본 탐색 연결과 구분한다.
3. 경복궁 이후 종로 연계, 전국 문화유산·다른 궁궐 전면 지원.
4. 자유 질문 LLM·RAG, 자동 음성, 상세 3D. 사용자 의견은 필요성 단서이며 기술·콘텐츠 품질 검증이나 채택 완료를 뜻하지 않는다.

설명 뒤 관련 장소를 연결 이유·위치와 함께 제시하는 경험은 후속 검토 후보다. 현재 US-10의 복귀·탐색 보장과 구별하고, 별도 Story 채택은 사용자 판단과 콘텐츠·사용자 검증 뒤 결정한다.

## 7. 공통 Definition of Done

아래 여섯 항목은 4차본과 개별 US에서 **사용하기로 정한 기준**이다. 이 목록을 채택한 것과 개별 Story가 통과한 것은 다르다.

1. 관련 GitHub Issue에 범위·담당·작업 결과를 기록하고, 본인이 PR 변경 내용을 검토한 뒤 관련 Commit과 함께 기본 브랜치에 반영합니다.

2. 해당 로직의 자동 테스트를 실행하고 통과 여부를 확인합니다. 자동화가 어려운 카메라·GPS·모바일 화면 및 건물 ID·출처 데이터는 수동 검증 증거를 남깁니다.

3. 해당 Story의 모든 AC를 Given/When/Then 기준으로 실행해 통과 증거를 남깁니다. 실패하거나 실행하지 않은 AC가 남으면 Done으로 표시하지 않습니다.

4. 모바일 웹에서 정상 흐름과 해당 Story에 관련된 예외 흐름(입력 취소·권한 거부·미확정·오류·복귀 등)을 확인합니다.

5. 미구현 기능을 제공 중인 것처럼 표시하지 않습니다. 사진과 관련성이 확인되지 않은 위치는 보정에 사용하지 않고, 미확정 결과나 검증되지 않은 설명을 정답처럼 표시하지 않습니다.

6. 시연 방법, 지원 건물 범위, 출처·알려진 제한, 테스트 근거를 Issue 또는 문서에 갱신합니다. 제품 전체 성능·사용성 목표는 별도 평가하여 미측정 상태를 달성과 혼동하지 않습니다.

다음 확인은 첫 사용 과제의 기기·버전·지원 대상을 고정해 가치 이해, 행동 발견, 결과 예측 일치, 궁금증 해소를 각각 기록한다. 새로운 참여자는 첫 경험 관찰에, 기존 참여자는 수정 후 회귀 확인에 사용한다. 표본이 작으면 사례로 보고하며 A/B 효과나 재사용 증가율을 계산하지 않는다. 실제 재사용은 별도의 이후 이용 기록·조건이 필요하다. 백로그 문서화는 이 추가 모집·실험 완료를 선행 조건으로 요구하지 않는다.
