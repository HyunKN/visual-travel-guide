# 코드 작성과 리뷰 기준

상태: 기술 스택과 무관한 초기 판단 기준. 스택별 형식·명령은 아직 정하지 않았다. 코드 작성·리뷰 시 읽고 반복된 판단을 공통 규칙으로 채택할 때 갱신한다.

- 이름은 [GLOSSARY](GLOSSARY.md)의 개념과 맞춘다. 후보와 선택한 대상의 차이가 코드에서도 드러나야 한다.
- 책임과 공개 입력·출력을 이해할 수 있게 구성한다. 파일 수보다 변경이 영향을 주는 경계의 명확성을 우선한다.
- 사전 연결 자료와 향후 인식 결과의 출처를 구분할 수 있게 한다. 테스트용 자료를 실제 인식 성능처럼 노출하지 않는다.
- 선택한 대상과 명칭·설명·출처의 관계를 한 경로에서 유지한다. 화면마다 따로 복제한 상태로 서로 다른 대상을 보여주지 않게 한다.
- 누락·빈 상태·오류는 호출자와 사용자가 구분할 수 있게 전달한다.
- 추상화와 의존성은 실제로 해결할 문제가 있을 때 도입하고 선택 이유를 설명한다.
- 기존 사용자 변경을 보존하고 요청 범위 안의 차이를 만든다.

기계적으로 검사할 수 있는 포맷·타입·금지 패턴은 스택 결정 후 도구 설정으로 관리한다. 이 문서에는 도구만으로 판정하기 어려운 기준을 남긴다. 명세 충족과 검증 증거는 [QUALITY](QUALITY.md)를 함께 확인한다.
