# 화면과 디자인 규칙

상태: 첫 흐름의 설계 초안. 색상·글꼴·간격 값과 시각 시안은 미정이며, 검증된 디자인 시스템이 아니다. UI 변경 전에 읽고 공통 규칙·화면 흐름·상태가 바뀔 때 갱신한다.

## 흐름과 상태

| 단계 | 보여줄 내용 | 사용자의 행동과 결과 |
| --- | --- | --- |
| 준비된 사진 선택 | 선택 가능한 사진과 현재 선택 상태 | 사진을 선택하면 해당 후보 목록으로 이동 |
| 후보 비교 | 후보별 이미지·명칭·구분에 필요한 단서 | 후보를 선택하면 그 대상의 설명 표시 |
| 설명 확인 | 선택한 대상, 명칭, 짧은 설명, 출처 | 후보 비교로 돌아가 선택 변경 가능 |

- 선택 상태는 색상 외에 텍스트·아이콘·테두리 등으로도 식별한다.
- 사진을 바꾸면 이전 사진에서 선택한 대상과 설명을 초기화한다.
- 후보 비교로 돌아갈 때 현재 사진을 유지한다.
- 사전 연결된 후보를 실제 인식 결과나 검증된 확률처럼 표현하지 않는다.
- 후보가 없으면 빈 상태와 사진을 다시 고르는 경로를 제공한다. 설명·출처가 없으면 확인할 수 없는 항목임을 표시한다.
- 로딩·오류·재시도는 실제 비동기 처리 도입 시 정의한다. 존재하지 않는 처리를 가짜 진행률로 표현하지 않는다.

## 공통 상호작용

- 스마트폰의 좁은 화면에서 후보와 설명이 잘리거나 주요 행동이 가려지지 않아야 한다.
- 버튼과 선택 항목에는 의미 있는 이름을 제공한다. 웹 구현 시 키보드 접근과 보이는 포커스를 지원한다.
- 설명을 읽는 중에도 선택한 대상의 정체를 확인할 수 있게 한다.
- 공통 컴포넌트의 기본·선택·비활성·포커스 상태를 함께 설계한다.

## 시안 단계에서 결정할 항목

| 항목 | 기록할 내용 | 현재 상태 |
| --- | --- | --- |
| 색상 | 배경·텍스트·강조·오류·선택의 역할과 값 | 미정 |
| 타이포그래피 | 글꼴, 제목·본문 크기, 행간 | 미정 |
| 레이아웃 | 화면 여백, 간격 체계, 콘텐츠 폭 | 미정 |
| 컴포넌트 | 후보 카드, 버튼, 설명, 출처 링크의 형태와 상태 | 흐름만 정의 |
| 표현·동작 | 아이콘, 모서리, 그림자, 필요한 전환 | 미정 |

첫 시안을 선택한 뒤 이 표를 실제 규칙으로 구체화한다. 구현에서 토큰을 관리하게 되면 그 정의 파일을 연결하고, 여기에는 사용 목적·조합·예외를 유지한다. 검증 조건은 [QUALITY](QUALITY.md)를 따른다.
