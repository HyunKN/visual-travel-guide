### 2026-11-03 Android 디자인 도구 적용

- [k-style-ui-ux](https://github.com/vmc-inner-circle/k-style-ui-ux)를 디자인 규칙 참고에만 쓰지 않고, 원본 컴포넌트 CSS·토큰 생성기·화면 구성 및 검사 도구를 실제 재사용하는 출발점으로 삼는다. 그 위에 아래 프로젝트 규칙을 적용한다. HTML 시안과 React Native 제품 구현은 구분한다.

- 기본 이모티콘과 Fluent Emoji 일러스트를 사용하지 않는다. 조작에는 일관된 벡터 아이콘을 사용하고, 장소를 보여줄 때는 해당 장소의 검수된 실제 사진을 사용한다.

- 기존 흰 바탕·먹청색 방향을 유지한다. 원본의 자동 팔레트·기본 서체 선택이 기존 사용자 결정을 덮어쓰지 않게 한다. 구체 수치는 시안 검토 후 조정한다.

- 기본 탐색·설명과 공개된 방문자 이야기는 내 기록 없이 이용한다. 공개 이야기의 열람 경계는 아래 「방문자 이야기의 탐색과 공개」를 따른다. 세부 시각 조정은 후반에 하되 이동·오류·접근성은 기능 구현 시 함께 확인한다.
- 로딩은 Skullet의 표현·동작을 기준으로 검토한다. 웹용 라이브러리의 React Native 직접 사용은 미확인이다. 원본 k-style 도구가 이 요구를 이미 구현한 것으로 취급하지 않는다.

로컬 원본은 Git 제외 경로 `.codex-build/ui-reference/upstream/`에 준비했다. 내려받은 174개 파일(4,080,642 bytes)은 Git blob 해시와 대조했으며 버전·범위는 `.codex-build/ui-reference/upstream.json`에 기록했다. 이 폴더는 다른 checkout에 자동 제공되지 않는다. 원본 [토큰 생성기](https://github.com/vmc-inner-circle/k-style-ui-ux/blob/a5b1955bd628657b2fbb18c4b05c9aff58d2284d/plugins/k-style-ui-ux/core/foundation/derive.py)를 다음과 같이 실행할 수 있다(저장소 루트 기준).

```powershell
python .codex-build/ui-reference/upstream/plugins/k-style-ui-ux/core/foundation/derive.py --brand '#243247' --tone neutral --radius 8,12,16 --density normal --out .codex-build/ui-reference/generated/tokens.css
```

이 명령으로 시험용 토큰을 생성하고 생성기 자체의 대비 검사를 통과했다. `generated/components.css`는 원본과 SHA-256이 일치하는 재사용 사본이며 MIT 고지를 함께 둔다. 색·모서리·간격 값은 도구 실행 확인용이며 최종 디자인 수치가 아니다. 생성기가 기본으로 내보내는 Pretendard 선언은 기존 서체 결정의 변경 승인이 아니다. 전체 화면 생성·시장 조사·`selfcheck.py`·`audit.py`는 아직 실행하지 않았고, Android UI에도 아직 연결하지 않았다.

근거와 화면별 적용 제안은 [실제 UI·전통 굿즈 참고](prototype/VISUAL_REFERENCES.md), 제외한 시안과 검토 기준은 [AI slop 방지·Worst 예시](prototype/ANTI_SLOP.md)에 둔다. 이전 미색 시안은 구현 기준이 아니다.

## 방문자 이야기의 탐색과 공개

2026-11-04 공간 메시지 방향: 사용자는 리뷰 리스트·카드 넘기기보다 다크소울의 메시지처럼 장소 안의 흔적을 발견해 여는 경험을 선택했다. [공통 장소 메시지 구현 설계](design/PLACE_MESSAGES.md)에 공통 사진 좌표·텍스트 저장·화면 치수·터치 겹침·읽기/작성 상태와 검증 기준을 정리했다. 위치를 고르는 세부 방식과 수치는 구현 초안이며, 실제 부위의 의미를 보증하는 주석이나 AR 좌표가 아니다.

2026-11-04 사용자 합의: 공개된 방문자 이야기는 메인에서도 전체를 열어 읽을 수 있다. 이전의 「같은 장소에 내 기록을 남긴 뒤 다른 사람의 흔적 열람」 제한을 대체한다.

- 메인에서 공개 이야기를 발견하고 해당 이야기 전체와 연결된 장소로 이동할 수 있다. 내 기록 작성을 열람 조건으로 요구하지 않는다. 메인의 구체적인 배치와 노출 순서는 미정이다.
- 내 기록을 남긴 뒤에는 같은 장소의 공개 이야기를 이어서 탐색할 수 있게 한다. 이는 열람 권한을 해제하는 절차가 아니다.
- 내 기록의 저장과 공개 동의를 구분한다. 비공개 기록은 본인만 볼 수 있고 메인이나 다른 사람의 탐색에 노출하지 않는다.
- 장소의 검수된 해설과 방문자의 경험·감상을 구분해 보여준다. 방문자의 글을 검증된 역사적 사실처럼 제시하지 않는다.

이 합의는 제품의 탐색 방향이다. 실제 사용자 간 공유 구현·권한 검증 완료나 백엔드 선정, Sprint 범위·추정 변경을 뜻하지 않는다. 후속 확인에서는 기록하지 않은 사용자의 공개 이야기 열람, 기록 후 같은 장소 탐색, 비공개 기록의 타인 미노출을 확인한다.

### 사진 위 리퀴드 글래스 쪽지와 추천

2026-11-04 후속 대화 기록:

- **사용자 확정 방향:** 장소 사진이 뒤에 크게 보이는 상태에서 사진 위로 메시지 쪽지를 띄운다. 쪽지는 연한 회색 또는 흰색을 섞은 반투명 리퀴드 글래스로, 뒤의 사진이 자연스럽게 투과되어 보이게 한다. 앞서 제안한 불투명한 흰 읽기 패널을 대체한다. 하단바는 불투명하게 유지한다.
- **2026-11-14 읽기 높이 결정:** 사진이 쪽지에 가려지지 않도록 읽기 창은 사진 영역 높이의 절반으로 고정한다. 본문 길이에 따라 창을 키우지 않고 본문만 스크롤하며 닫기·관리 행은 유지한다. 상세 수치·기기 검증은 [Sprint 1 명세](design/APP_SPRINT1_SPEC.md)를 따른다.
- **사용자 제안 기능:** 첨부한 게임 메시지 화면처럼 추천수를 함께 보여주는 방향을 검토한다. 작은 추천 버튼·숫자는 본문보다 낮은 시각 비중으로 배치하는 안이다. 추천 취소·중복 방지·집계·노출 순서는 후속 설계 대상이다.
- **어시스턴트 제안, 미확정:** 쪽지 안쪽에 약한 배경 흐림과 가장자리 빛·그림자를 적용하고, 사진의 복잡도에 따라 바탕 불투명도를 조절한다. 쪽지 밖 사진은 유지한다. 추천이 많은 흔적과 새 흔적을 섞는 노출 방식도 제안이며 비율·알고리즘은 정하지 않았다.
- **다음 구현 제안:** Android 앱에서 장소 한 곳의 큰 사진·흔적 선택·유리 쪽지·추천 전후 상태·닫기/원위치 복귀를 먼저 시연한다. 글과 추천수는 개발용 예시로 구분하고, 실제 공유·추천 집계 완료로 표시하지 않는다. 화면 확인 후 위치 선택·자유 텍스트 작성을 연결한다.
- **K-style 적용 경계:** 현재 도면은 원본 앱바 코드와 일부 토큰을 사용한 기술 도면이다. 전체 화면 구성·검사 흐름과 리퀴드 글래스는 아직 적용하지 않았다. 다음 앱 시안에서 원본 규칙·구성 요소를 출발점으로 재사용하고 공간 메시지와 유리 쪽지를 확장한다.

확인할 것은 사진의 현장감, 밝거나 복잡한 배경에서의 글 가독성, 흔적 터치, 긴 글·큰 글자·닫기 복귀다. 재질·불투명도·블러 수치는 시안 검토 후 정하며 효과나 성능을 검증한 것으로 기록하지 않는다. 상세 기록은 [메시지 설계](design/PLACE_MESSAGES.md)의 최신 변경 및 구현 순서를 따른다.

### 자유 텍스트 기록과 사진 보관

2026-11-04 사용자 결정: 기록은 정해진 항목 없이 텍스트를 자유롭게 쓰는 공간으로 제공한다. 제목·질문별 답변·사진 첨부를 요구하지 않는다.

- 사용자가 같은 장소를 보는 공통 화면에서 글을 남긴다. 개인 촬영 사진을 기록의 배경이나 영구 보관 대상으로 요구하지 않는다. 구현 초안은 변경되지 않는 공통 사진의 sceneId와 0..1 위치에 글을 연결한다. 구체 구도·표식 모양·노출 밀도는 [메시지 설계](design/PLACE_MESSAGES.md)로 검토한다.
- 기록에는 자유 텍스트와 연결 대상 등 필요한 정보를 보관한다. 사용자 사진 자체는 기록 데이터로 저장하지 않는다. 인식용 사진의 임시 처리는 영구 기록과 구분한다.
- 사진 보관을 제공한다면 사용자가 명시적으로 선택할 때 휴대폰 갤러리에 저장하는 방식으로 검토한다. 자동 저장이나 갤러리 저장 기능 구현 완료를 뜻하지 않는다.
- 기본 비공개 저장과 별도 공개 선택을 유지한다. 자유 작성은 자동 공개를 뜻하지 않는다. 기존 계획의 50자 제한을 최신 작성 규칙으로 자동 채택하지 않으며 글자 수 상한은 후속 명세에서 확인한다.

후속 확인은 자유 텍스트 저장·재열람, 연결 장소 유지, 사진 영구 복사 없이 기록 가능, 비공개 미노출을 포함한다. 갤러리 저장을 구현하면 해당 권한 거부·실패와 글 저장을 독립적으로 처리하는지 확인한다.

## 말투와 이야기 작성

2026-11-03 사용자 합의: 기본 말투는 **잘 아는 사람이 옆에서 차분하게 들려주는 해요체**다. 아래는 작성 방향의 합의이며 실제 콘텐츠 적용·사용자 검증 완료를 뜻하지 않는다.

- 버튼·저장 결과·오류 안내는 사용자의 행동과 결과를 짧고 정확하게 표현한다. 장난스러운 오류 표현이나 과도한 경어를 쓰지 않는다.
- 장소 이야기는 사람·상황·이유를 자연스럽게 연결한다. 문장은 쉽게 쓰되, 이해에 필요한 맥락까지 줄이지 않는다. 모든 이야기를 같은 도입이나 구성으로 반복하지 않는다.
- 질문·감탄·유행어로 관심을 강요하지 않는다. 구체적인 장면과 확인된 사실로 호기심을 만든다. 사용자가 느낄 감정을 대신 정하지 않는다.
- 사실·전승·해석을 구분하고 출처를 확인한다. 말투 비교용 가상 예문을 역사 콘텐츠로 옮기지 않는다.
- 태그라인·조작법 도움말·보조 레이블 제거 원칙을 유지한다. 친근함을 위해 설명용 문구를 추가하지 않는다.

조사 참고: [토스 UX Writing](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md), [당근 Writing](https://seed-design.io/foundations/writing), [Apple Writing](https://developer.apple.com/design/human-interface-guidelines/writing). 각 서비스의 규칙 전체를 그대로 채택하지 않으며, 짧은 UI 문구의 원칙을 이야기 본문의 일률적인 분량 제한으로 사용하지 않는다.

## 참고와 실제 사용의 경계

- 단청·전통 문양 자체는 디자인 소재로 활용할 수 있다. 전통 요소를 직접 그리거나 우리 화면에 맞게 표현하는 것을 금지하지 않는다.
- 굿즈에서는 색 조합과 전통 요소를 추려 표현하는 방식을 참고한다. 해당 업체가 만든 상품 사진·상세 페이지 이미지·상품 일러스트를 앱의 장식이나 콘텐츠로 가져다 쓰지 않는다. 상품 사진에서 문양을 잘라내 자산으로 쓰는 것도 포함한다.
- 참고 자료는 원본 링크로 유지한다. 실제로 외부 이미지를 사용해야 한다면 별도로 이용 조건을 확인하고 [DATA의 Asset 계약](prototype/DATA.md)에 출처·표시 조건 등을 기록한다. 전통 소재를 담았다는 이유만으로 그 사진이나 현대적 상품 도안까지 사용 가능한 자료로 취급하지 않는다.

이 기준은 전통 문양 활용을 막기 위한 것이 아니라, 참고한 굿즈 이미지를 그대로 앱 자산으로 가져오는 일을 방지하기 위한 것이다.

## 실제 제품의 첫 진입과 첫 결과 설계 초안

2026-10-22: 사용자 관찰 F10·B06과 US-01을 [실제 제품 구조 §2.2](ARCHITECTURE.md#22-핵심-흐름-1--첫-진입에서-첫-유용한-결과까지)에 연결한다. 아래는 검토할 화면 동작이며 현재 앱에 적용하거나 사용성 효과를 검증한 결과가 아니다. [기존 UX 조사와 한계](PRODUCT_BACKLOG_DRAFT.md#부록-a-첫-유용한-결과를-위한-조사와-적용-후보)를 근거로 한다.

- 처음 보이는 영역에서 대표 사진·짧은 궁금증·행동 이름으로 받을 도움을 연결한다. 예: 건물 사진과 ‘이 건물은 어떤 곳일까요?’ → ‘사진으로 건물 알아보기’. 문구는 검토안이며 실제 지원 건물·제공 설명과 맞춘다.
- 직접 탐색을 주 경로로, ‘예시로 살펴보기’를 선택적인 작은 경로로 둔다. 첫 방문 여부나 현장/방문 전 상황을 설문으로 먼저 고르게 하지 않는다. 기존 검색 중심의 주 탐색 위계와 작은 호기심 카드 원칙을 유지하며 구체 배치는 검토한다. 사진이 없어도 예시로 결과를 볼 수 있고, 사진이 있으면 예시를 거치지 않는다.
- 첫 화면에 기능 소개·설명 카드를 늘리지 않는다. 예시 표시·버튼 이름·필요한 실패 안내는 유지한다. 카메라·위치 요청과 모델 준비는 필요한 행동에서 처리하고 홈 열람을 막지 않는다.
- 첫 결과는 입력한 대상의 명칭·질문에 답하는 짧은 설명·출처·현재 가능한 다음 행동을 연결한다. 예시 표시를 유지하고 미확정 결과는 확정 설명처럼 포장하지 않는다. 역사·관람 포인트는 검수 콘텐츠와 해당 기능이 제공될 때만 약속한다.
- 예시에서 실제 사진 탐색, 잘못된 결과에서 재입력, 설명에서 이전 화면으로의 이동을 막지 않는다. 검색·지도 등은 해당 제품 기능이 구현된 뒤 제공한다. 지원하지 않는 버튼이나 자동 부위 인식 약속을 먼저 노출하지 않는다.
- 예시 화면이나 3D를 본 것만으로 서비스 가치를 이해했다고 판단하지 않는다. [첫 진입 검증](QUALITY.md#첫-진입과-첫-유용한-결과-검증)에서 도움 이해·행동 발견·예상과 결과의 일치·질문 해소를 각각 확인한다.

## 흐름과 상태

구현할 화면·문구·이동·예외·와이어프레임은 [프로토타입 화면 설계](prototype/SCREENS.md)가 상세 원본이다. 아래는 공통 원칙이다.

| 단계 | 보여줄 내용 | 사용자의 행동과 결과 |
| --- | --- | --- |
| 홈 | 주요 행동 하나, 호기심 카드 최대 하나 | 직접 알아보기 또는 카드의 설명으로 진입 |
| 대상 지정 | 준비된 사진, 전체·부분 지정, 선택 미리보기 | 확인한 대상의 기본 설명 표시 |
| 모호한 대상 확인 | 선택 위치에 해당하는 후보·구분 단서 | 확인 또는 해당 없음·재선택 |
| 설명 확인 | 선택한 대상, 명칭, 짧은 설명, 출처 | 필요하면 관련 질문 선택 또는 대상 수정 |

- 선택 상태는 색상 외에 텍스트·아이콘·테두리 등으로도 식별한다.
- 장면을 바꾸면 이전 대상·질문·설명을 초기화한다. 대상을 바꾸면 이전 질문·설명을 초기화한다.
- 대상 수정으로 돌아갈 때 현재 사진을 유지한다. 후보 비교는 필요한 경우에만 표시한다.
- 사전 연결된 후보를 실제 인식 결과나 검증된 확률처럼 표현하지 않는다.
- 미지원 부분, 후보 중 해당 없음, 준비된 질문 없음, 설명·출처 누락을 구분하고 대상 수정·기본 설명·홈으로 돌아가는 경로를 제공한다.
- 로딩·오류·재시도는 실제 비동기 처리 도입 시 정의한다. 존재하지 않는 처리를 가짜 진행률로 표현하지 않는다.

## 발견을 돕는 정보량

[질문을 몰라도 볼거리를 발견하기](PRODUCT.md#가치-가설-질문을-몰라도-볼거리를-발견하기)를 화면·콘텐츠 설계에서 확인한다. 아래는 2026-10-25에 정리한 설계 원칙이며 새 화면을 구현했다는 뜻은 아니다.

- 방문객이 찾으러 온 기본 정보를 먼저 보여준다. 관심을 끌 관람 포인트는 짧게 제시하고, 상세 이야기·추가 질문·출처 상세는 원하는 경우 펼쳐볼 수 있게 한다. 기본 출처 표시와 예시·미확정 등 필수 상태 안내는 숨기지 않는다.
- 기본 설명·후보 비교·관련 질문·다음 관람 추천을 한꺼번에 펼치지 않는다. 후보 비교는 불확실하고 방문객이 비교를 선택한 경우에 제공한다.
- 짧은 관람 포인트 하나를 첫 실험안으로 삼을 수 있지만 개수·위치·노출 시점을 확정 규격으로 취급하지 않는다. 안내를 건너뛰거나 닫고 기존 탐색·관람을 이어갈 수 있어야 한다. 퀴즈 정답이나 설명 완독을 진행 조건으로 두지 않는다.
- 정보량을 늘렸다는 이유로 개선으로 판단하지 않는다. [비교 관찰](QUALITY.md#발견과-정보-부담의-비교-관찰)에서 새로운 발견과 함께 읽기 부담·혼란·관람 방해를 확인한다.

## 공통 상호작용

재질과 입력 반응을 재사용할 때는 [재질·입력 반응·전환 분류](design/INTERACTION_MATERIALS.md)를 읽는다. Apple 공식 근거, 웹에서의 근사 범위, hover·pressed·focus·cancel·disabled·동작 줄이기 상태, 코드 토큰과 사용 예시를 관리한다.

유리는 볼록한 외곽 14px만 굴절시키고 중앙은 평평하게 유지한다. 2026-10-17 사용자 요청으로 최대 샘플 변위를 각 축5→7px로 높였다(scale14). 하이라이트는 1px 테두리다. 앱·재질 비교 화면은 같은 CSS + SVG 필터를 사용하며 유리용 Canvas는 사용하지 않는다. 탄성 효과 수정은 사용자 요청으로 후속 작업에 남기며 이번에 spring·motion 코드를 바꾸지 않는다. 실제 표시·지원 범위는 재질 문서 11절과 검증 기록을 따른다.

홈 조정: 1안은 흰 배경, 정면을 중심으로 옆면과 지붕 윗면이 조금 보이는 구도로 시작한다(2026-10-16 사용자 이미지 반영). 2안은 근정전 대표 사진과 S3 굴뚝 탐색 사진을 화면 폭으로 표시한다. 사진의 큰 둥근 카드 테두리는 제거하고 흰 텍스트 면으로 이어진다. 상단 대표 사진과 실제 탐색 장면이 다르면 다음 장면을 안내한다. 유리 조작부 내부에 돌출된 유리 아이콘을 중첩하지 않는다.

브랜드 로고는 먹색 지붕·적갈색 목재·흰 돌기단으로 구성한다. 3D 일러스트의 넓은 연녹색 창호도 적갈색 목재로 조정했다. 실제 건축물 사진의 녹색은 보존하고, 모형의 짙은 녹색은 작은 처마 부재에 한정한다. 시안의 HEX 값은 문화유산의 공식 색상표나 고증값이 아니다.

공식 3D 에셋 승인 대기 중에는 직접 제작한 일러스트를 사용한다. 처마 곡선·서까래 끝·기둥 받침·옆면 창살·난간과 그림자로 입체감을 보완하되 실제 근정전의 조사·복원 결과로 표현하지 않는다. 외부 원본의 확보·분석·경량화는 미완료이며, 최종 용량을 보장하지 않는다. 세부 형상은 재질별로 합치고 그림자를 만드는 광원은 하나로 제한한다. 실기기 성능은 별도 확인한다.

- 스마트폰의 좁은 화면에서 후보와 설명이 잘리거나 주요 행동이 가려지지 않아야 한다.
- 버튼과 선택 항목에는 의미 있는 이름을 제공한다. 웹 구현 시 키보드 접근과 보이는 포커스를 지원한다.
- 설명을 읽는 중에도 선택한 대상의 정체를 확인할 수 있게 한다.
- 공통 컴포넌트의 기본·선택·비활성·포커스 상태를 함께 설계한다.
