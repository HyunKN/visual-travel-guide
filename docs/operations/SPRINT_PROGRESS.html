Android 검증 보고서 전체 보기 · 서버 없이 열리는 읽기용 문서

다음에 앱 다시 켜는 순서
  1. Android Studio → Device Manager → VTG API 36의 실행 버튼을 누르고 에뮬레이터 부팅을 기다립니다.
  2. PowerShell에서 아래 명령을 순서대로 실행합니다.
cd C:\Users\hi\Desktop\projects_2026\visual-travel-guide
. .\scripts\use-android-tools.ps1
adb reverse tcp:8081 tcp:8081
cd mobile
npm run start:emulator
  1. Waiting on http://localhost:8081이 나오면 에뮬레이터에서 Visual Travel Guide 앱 → 최근 서버 http://127.0.0.1:8081을 선택합니다.
  2. PowerShell 창은 앱을 사용하는 동안 열어둡니다. 종료할 때는 Ctrl+C로 Metro를 끕니다. 일반적인 JavaScript 수정은 자동 반영되며 native 의존성·설정 변경은 별도 재빌드가 필요할 수 있습니다.

Failed to connect가 나오면 Metro 실행 상태와 adb reverse를 확인합니다. 이 절차는 설치된 개발 APK를 다시 실행하는 방법이며 제품 기능 검증이나 native 재빌드 절차가 아닙니다.

판정 기준과 관리 방식

퍼센트가 뜻하는 것

  1. Story 완료율: 모든 AC와 공통 DoD를 통과한 Story의 SP만 합산합니다. 모델 연결·APK 생성만으로 Story를 완료 처리하지 않습니다.
  2. 착수율: 부분 진행·막힘·완료 Task 수 ÷ 전체 Task 수입니다. 난이도·공수·남은 기간을 뜻하지 않습니다.
  3. AC 통과율: 실제 검사를 통과한 조건만 셉니다. 코드·명령 검사와 제품 AC를 섞지 않습니다.
  4. 남은 시간: 별도 재추정이 필요합니다. 실제 시간 기록 없이 Burndown·velocity·완료 예측을 만들지 않습니다.

계속 같은 화면에서 확인

  1. 이 채팅의 작업 보고 시 기존 Task의 상태·확인일·증거를 이 화면에 반영합니다.
  2. 파일을 갱신한 뒤 새로고침하면 바뀐 현황을 볼 수 있습니다. 열린 화면이 스스로 GitHub를 조회하거나 작업을 수행하지 않습니다.
  3. 계획·명세는 기존 문서, 진행·증거는 Issue/PR 또는 PR 전 검증 기록이 원본입니다. 이 화면은 사용자 요청으로 만든 조회용 스냅샷입니다.
  4. 원격 Issue와 차이가 있으면 숨기지 않습니다. 현재 #21은 이전 계획 기준이며 이번 로컬 개발 결과를 원격에 갱신하지 않았습니다.
