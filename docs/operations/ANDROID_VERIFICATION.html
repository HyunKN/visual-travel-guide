빌드 오류와 프로젝트 안의 수정

첫 Gradle 빌드는 settings 단계에서 Unexpected JSON token ... JSON input: Active code page: 65001로 실패했다. 이 PC의 HKLM Command Processor AutoRun에 chcp 명령이 있음을 값 노출 없이 확인했고, cmd /c echo JSON_CONTROL에는 시작 문구가 붙지만 cmd /d /c echo JSON_CONTROL에는 붙지 않음을 재현했다.

Expo autolinking 57.0.16의 Os.kt가 Windows 명령에 cmd /c를 붙이는 코드와, 그 표준 출력을 JSON으로 읽는 SettingsManager.kt를 직접 대조했다. postinstall 스크립트가 cmd /d /c로 바꾸도록 했다. /d는 Microsoft 문서의 AutoRun 비활성화 옵션이다. 레지스트리와 전역 사용자 환경은 수정하지 않았다. 실제 재빌드 결과는 위 표에 반영한다.

남은 필수 확인

CPU virtualization·SLAT은 켜져 있지만 HypervisorPresent=False이고 Emulator 가속 드라이버가 없다. Android 공식 권장 경로는 Windows Hypervisor Platform 활성화와 재부팅이다. 관리자 권한·사용자 재부팅이 필요하므로 임의 실행하지 않았다.

Windows feature 자체의 Enabled/Disabled 조회는 관리자 권한 부족으로 실패했다. 위 진단을 feature가 꺼져 있다는 직접 확인으로 확대하지 않는다. 사용자 확인 후 활성화·재부팅과 -accel-check 재검사가 필요하다.

  1. Windows 기능 켜기/끄기에서 Windows 하이퍼바이저 플랫폼을 켜고 사용자 작업을 저장한 뒤 재부팅한다. 또는 USB 디버깅이 켜진 실제 Android를 연결한다.
  2. emulator -accel-check 성공과 adb devices의 device 상태를 확인한다.
  3. APK를 설치하고 Metro 연결 → 시작 화면 → 임시 상세 → 시스템 뒤로가기 → 종료/재실행을 실제 수행한다. UI tree·스크린샷·crash log로 결과를 남긴다.
  4. native 생성 폴더가 없는 상태에서 재생성·빌드·재설치해 T02의 재현성을 확인한다. 실기기 확인은 별도이며 에뮬레이터로 대체하지 않는다.
