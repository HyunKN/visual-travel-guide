## 서로 넘을 수 없는 경계

- `placeId`는 기존 대상 ID다. 별도 장소 카탈로그를 복제하지 않는다. `sceneId`는 공통 사진의 구도를, `photoId`는 사용자 임시 입력을 뜻한다. 서로 바꿔 쓰지 않는다.
- 촬영은 위치를 담은 쪽지를 만들지 않는다. 인식 또는 직접 선택이 placeId를 정한 뒤, 공통 장면에서 Anchor를 고른다. [ADR 0001](../adr/0001-shared-place-photo-anchors.md)을 따른다.
- 위치 기능은 관측값·정확도·시각을 전달한다. 인식 연결부가 적용 가능성을 판단한다. 위치가 없어도 사진 단독·직접 선택은 동작한다. 갤러리 사진에 현재 위치를 자동 연결하지 않는다.
- 모델 담당은 모델 파일·라벨·전처리 규격·평가 근거를 전달한다. 앱 담당은 기기 내 디코딩·전처리 구현·추론 연결·취소·결과 표시를 맡고 규격 일치를 검증한다. [기술 검증 #21](https://github.com/HyunKN/visual-travel-guide/issues/21)은 모델 준비·기술 검증 근거로 유지하고 앱 연결 결과는 #30에 기록한다.
- 내 기록의 로컬 저장과 공개 사본의 서버 저장은 수명·권한·실패가 다르다. #33과 #34를 분리한다. 공개 글 열람에 내 기록을 요구하지 않는다. 공개와 나만 보기의 작성 화면 선택 방식은 착수 전 확정하며 비공개 저장 선행을 의무로 단정하지 않는다.
- #32는 조회 결과를 표시하고 #34는 공개 여부를 서버에서 검증한다. 화면에서 숨기기만 해서 권한을 구현했다고 판단하지 않는다. 서버 응답이 늦으면 현재 scene/request를 확인하고 잘못된 장면에 적용하지 않는다.
- 단위별 테스트는 기능 소유 코드 옆에 둔다. API·DB·기기 동작의 실제 연결은 통합 검사에서 구분한다. 모양·선택자를 그대로 흉내 내는 테스트보다 위치 정합·저장 복원·늦은 결과·권한 같은 실패 조건을 검사한다.

## 구현 상태와 설계안 구분

`PlaceMessagePreview()`는 근정전 고정 예시의 과거 시안으로 보존한다. 제품 경로는 `SceneScreen`·`Editor`·계정별 `store`·`nativeService`이며 공통 사진 읽기, 기기 초안/개인 글 저장, 인증된 공개 공유를 연결했다. `docs/design/place-messages/`의 TypeScript는 참고 코드이며 앱의 실제 좌표·입력 계약은 `mobile/src/features/place-messages/`가 소유한다. 구현과 자동 검사, 사용자 에뮬레이터 확인, 실제 모델·실기기 인수는 각 기능 Issue에서 구분한다.

각 이슈의 예정 함수명은 책임을 설명하는 초안이다. 실제 모듈 배치와 API가 바뀌면 이슈도 같은 변경에서 갱신한다. UI·기기 저장·서버 adapter가 같은 기능 데이터를 다루더라도 서로의 저장소를 직접 수정하지 않는다.

## Sprint와 남은 결정

이 분리는 기존 Sprint 1 기능을 추적하기 위한 것이다. 전체 이름 검색·구역 탐색·후보 상세 비교는 Sprint 2, 세부 요소 탐색은 후순위다. 현재 홈은 등록된 세 장소 이름 필터만 제공한다. 쪽지 추천·취소·집계는 사용자가 후속으로 보류했으며, 검수된 장소 이야기를 홈에 바꾸어 보여주는 기능과 구분한다.

공개/나만 보기는 매번 기본값 없이 선택하고 새 입력·저장·공개는 공백/줄바꿈 포함 Unicode code point 100자로 제한한다. 기존 긴 글은 자동 절단하지 않는다. 가이드는 비로그인, 메모 읽기/작성은 Google·네이버 로그인 후 이용한다. 최신 계약은 [상세 명세](APP_SPRINT1_SPEC.md)를 따르며 전체 SP·시간을 재산정하지 않는다.

## 개발 순서와 진행 관리

- 먼저 연결할 흐름: #28 직접 선택·설명 → #32 공통 장면 → #33 글 보존 → #34 실제 공유.
- 입력 확장: #28 → #29 촬영·갤러리 → #30 인식. #31 위치는 #28 뒤에서 독립 연결하며 인식의 필수 선행으로 만들지 않는다.
- 인수: 각 기능의 완료 확인 → #35 전체 앱·실기기·두 사용자·관찰 검사.

현재 상태·완료 기능 수·지금 할 일은 [상위 이슈 #27](https://github.com/HyunKN/visual-travel-guide/issues/27)에서만 갱신한다. 기능 개수는 공수·시간·SP 진행률이 아니다. 각 이슈의 마지막에는 그 기능의 개발 순서·완료 후 가능한 일·완료 확인 체크 수를 표시하고, 실제 테스트 결과와 커밋/PR이 확인돼야 완료로 처리한다.
