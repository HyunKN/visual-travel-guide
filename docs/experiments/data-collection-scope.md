기록일: 2026-11-03. 사용자 요청으로 이 개발 채팅의 데이터 관련 결정·아이디어·계획을 보존한다. **사용자 방향**, **설계 제안**, **미정 항목**, **기존 확보 기록**을 구분한다. 기록 요청은 모든 제안의 채택이나 새 기능·학습·추가 수집의 실행 승인을 뜻하지 않는다.

## 1. 사용자 방향과 결정의 경계

| 항목 | 내용 | 상태 |
| --- | --- | --- |
| 수집 전 범위 결정 | 필요한 데이터와 구현할 구분 범위를 사용자와 먼저 정한다. AI가 대상·수량·모델·학습 방식을 임의로 확장하지 않는다. | 사용자 지시 |

| 품질과 속도 | 제대로 구현하고 계속 수정한다. Sprint 날짜는 진행을 보는 기준이며 그 날짜까지 개발을 기다리는 지시가 아니다. | 사용자 선호 |

현재 백로그의 장소 단위 흔적과 등록 사진 기반 부분 탐색은 이번 아이디어와 구분한다. 기존 착수 기준은 자기 사진의 비공개 로컬 저장과 공개 동의한 장소·짧은 글의 공유다. 부위별 공유 연결·임의 사진의 자동 영역 인식·공개 사진 업로드를 이미 채택·구현한 것으로 해석하지 않는다. 이 기록으로 Story·SP·Task 상태·AC·Sprint 배치를 변경하지 않는다.

## 2. 사용자가 제시한 경험

| 상황 | 사용자 구상 | 남은 경계 |
| --- | --- | --- |
| 현판을 가까이 촬영 | 현판 설명 후 건물 설명으로 이어가거나 현판에 메모를 남긴다. | 글자가 식별 단서가 될 수 있지만 작은 글씨·흐림·가림에서도 구별된다는 보장은 없다. OCR 등 구체적 수단은 미선정이다. |
| 건물을 전체 촬영 | 건물 설명과 자기 사진의 메모를 제공한다. 현판이 보이는 범위에 있다면 다른 사용자의 현판 메모도 만난다. | 건물 인식만으로 요소의 실제 가시 여부·사진 속 위치가 확인되지는 않는다. 작은 요소·가림·부재 자료가 필요하다. |
| 처마를 가까이 촬영 | 요소 종류를 인식하고 위치·등록 정보로 건물 후보를 좁혀 확인한다. 요소 설명에서 건물 설명 또는 메모로 이어간다. | 후보를 거절했을 때 일반 설명을 먼저 보여줄지, 가까운 후보를 제시할지 미정이다. 확인 화면이 깊어지지 않아야 한다. |

대화의 ‘경복궁 처마’는 메모 식별자로 확정한 표현이 아니다. 실제 자료에서는 궁궐과 개별 건물을 구분하며 ‘처마’의 명칭·라벨 경계도 검수한다.

## 3. 요소 인식 → 소속 후보 축소 → 기록 연결

아래는 검토 흐름이며 구현 계약이나 검증된 파이프라인이 아니다.

1. **사진 단서:** 건물 전체인지, 현판·처마 같은 요소인지 판단한다. 새 학습·기존 특징·탐지·문자 인식의 선택은 미정이다.
2. **등록 정보:** 궁궐 → 건물 → 등록 요소 관계와 위치·배치를 조회한다. 존재와 설명 근거를 확인한 관계만 등록한다.
3. **맥락 단서:** 촬영 위치와 정확도, 확보 가능한 방향·가시 범위·사진 속 글자 등으로 후보를 줄인다. 단서의 사용 여부와 결합 규칙은 실험 후 정한다.
4. **확인·수정:** 불확실하면 사용자가 소속 건물을 확인한다. 자동 판정과 사용자 확인을 구분하며 거절·해당 없음에서도 틀린 건물에 메모를 붙이지 않는다.
5. **설명·메모 조회:** 확인한 건물과 요소의 공통 식별자로 연결한다. 사진 좌표는 그 사진 안의 표시를 위한 값이며 다른 사진에 그대로 복사하지 않는다.

GPS는 촬영자의 위치다. 가까운 건물을 촬영 대상으로 단정하지 않는다. 등록 정보가 있어도 이번 사진에서 무엇을 바라봤는지는 별도 판단이며, 모르는 세부 위치는 미상으로 남긴다.

기존 답변은 사진 간 동일 부위 대응을 지나치게 전제했다. **후보 축소가 중심인 사용자 구상에서는 사진 간 유사도 비교가 필수 단계가 아니다.** 다만 사진의 해당 요소 위에 메모를 표시하려면 그 사진 안의 요소 영역을 찾거나 사용자가 지정해야 한다. 조회할 메모의 결정과 표시 위치의 결정은 구분한다.

## 4. 수집 자료의 여섯 묶음 — 제안

| 자료 | 준비할 내용 | 목적·경계 |
| --- | --- | --- |
| 장소·건물 기본 정보 | 건물 ID·명칭·궁궐 소속·위치·배치·등록 요소·근거 | 소속 후보 조회. 기존 세 건물을 기준으로 검토하며 주변 후보의 등록 수준은 미정이다. |
| 건물 인식 사진 | 여러 방향·거리의 전경·부분 전경, 최신 외관, 혼동 건물 | 지원 건물 판별과 범위 밖 판단. 역사·복원 시기 차이를 기록한다. |
| 요소 종류 사진 | 선택한 요소의 근접·원경·가림, 여러 건물의 동일 종류 사례 | 종류 인식. 특정 건물의 한 모습만 종류 전체의 정답으로 삼지 않는다. |
| 촬영 맥락과 정답 | 촬영 위치·정확도, 가능한 방향, 실제 촬영 대상·확인 근거 | 후보 축소 검증. 대상 좌표와 촬영자 좌표는 별도이며 없는 정보는 채우지 않는다. |
| 설명·근거 | 요소의 일반 설명, 특정 건물·부위 설명, 출처·확인일 | 일반 지식과 장소 고유 사실을 구분한다. 건물 미확정 상태에서 고유 설명을 단정하지 않는다. |
| 메모 연결·표시 자료 | 독립 촬영 사진들에 보이는 요소·영역·가림·부재 정답 | 선택한 메모 단위의 조회·표시 검증. 임의 지점 간 정밀 대응은 별도 범위다. |

**지원 범위와 수집 범위는 다르다.** 다른 건물 사진은 일반 요소 학습과 혼동·범위 밖 검증에 필요할 수 있다. 수집했다고 해당 건물의 설명·메모까지 지원하는 것은 아니다. 주변 지원 밖 건물을 후보로 등록할지, ‘지원 밖/미상’으로 다룰지는 결정이 필요하다.

모든 묶음의 대량 수집·정밀 라벨링을 확정한 것은 아니다. 지원 대상·일반 요소·혼동/범위 밖 사례를 구분하여 준비한다.

## 5. 메모 연결 단위 — 미정

| 단위 | 필요한 구분 | 논의 상태 |
| --- | --- | --- |
| 건물 전체 | 건물 ID | 기존 장소 단위 흔적과 연결되는 수준 |
| 건물 + 요소 종류 | 예: 근정전 / 처마, 근정전 / 현판 | AI가 제안한 첫 검토 범위. 사용자 채택 전 |
| 건물 + 요소 + 면·방향 | 예: 근정전 앞쪽 처마 | 앞뒤가 다른 메모를 구별하려면 추가 정보 필요 |
| 개별 무늬·임의 지점 | 특정 문양·모서리 | 사진 간 정밀 대응 등이 필요한 확장안. 현재 약속할 범위로 채택하지 않음 |

`근정전 / 처마`로 묶으면 다른 면의 처마 메모가 함께 조회될 수 있다. 이것이 원하는 경험인지 먼저 정한다. 사용자가 사진의 특정 점을 찍어 기록하더라도 공유 시 요소 전체에 연결할지 그 점까지 보존할지는 별도 결정이다.

고정 참고 사진에 메모를 모으는 대안도 논의했다. 자기 사진에서 요소별 메모를 보여주는 방식, 임의 지점을 다른 시점에 정확히 옮기는 방식까지 포함해 최종 방식을 선택하지 않았다. 등록 사진의 기존 영역 좌표를 사용자 사진의 정답 좌표로 재사용하지 않는다.

## 6. 라벨·메타데이터 초안

아래 항목은 설명용이며 확정 스키마가 아니다. 보이는 사실·소속 추정·사용자 확인을 구분하고 모르는 값은 미상으로 둔다.

| 구분 | 기록 후보 |
| --- | --- |
| 출처·권리 | 원출처 URL·파일 ID·저작자·이용 조건·확인일·학습/동봉/재배포 검토 상태 |
| 원본·중복 | 파일 해시·원본과 크롭/증강의 관계·재게시 관계·촬영 묶음 |
| 사진 정답 | 지원/지원 밖/미상, 건물 ID, 보이는 요소 종류, 선택된 주대상, 필요한 경우 요소 영역 |
| 소속·세부 위치 | 등록 요소 ID, 면·방향·개별 위치, 확인 근거·미상 여부 |
| 촬영 조건 | 촬영일·외관 시기·거리/구도·작음·흐림·가림·조명 등 확인 가능한 조건 |
| 위치 맥락 | 촬영자 위치·정확도·방향의 출처와 값, 대상 위치, 실제 촬영 대상 정답 |
| 검수·분할 | 검수 근거·보류 이유·라벨 버전·등록/학습/기준 설정/독립 평가 용도 |

예: 사진에서 ‘처마’와 ‘근정전 소속’은 확인했지만 세부 면·촬영 위치는 모르면 요소와 건물만 라벨링한다. 촬영 방향 기반 후보 축소 평가의 정답 자료로 쓰지 않는다.

등록·학습·기준 설정·독립 평가는 촬영 묶음과 원본 계보를 고려해 분리한다. 같은 원본의 크롭·증강·재게시를 다른 세트의 독립 사례로 세지 않는다. 기존 학습 계보를 확인하지 못한 상태에서 최종 독립 평가라고 부르지 않는다. 사용자 사진·위치의 학습 재사용은 이번 논의로 동의받은 것이 아니다.

## 7. 출처 후보와 기존 확보 기록

사용자 제안의 공공 사진 포털·공공기관·학습 데이터 플랫폼·공유 사진·리뷰 서비스를 내부 출처 대장에서 관리한다. 개별 이름·주소·파일 ID·권리 조사·수집 기록은 현재 공개하지 않는다. 아래는 출처를 식별하지 않는 공통 취급 기준이다.

- 3D 점군·일반 객체·전통 문양·랜드마크 자료는 서로 다른 과업이다. 건물 전체/요소 인식 중 어느 역할에 맞는지 실제 항목·샘플을 확인한다. 제목만으로 세 건물·선택 요소의 포함을 단정하지 않는다.
- 공개 열람과 수집·학습·재배포 가능 여부는 별개다. 기존 조사에서 보류한 자료를 이 문서로 승인하지 않는다.
- ‘CLIP 영문 프롬프트’는 이미지–텍스트 비교의 기준선 메모다. 이미지 간 비교나 사진+class ID 학습에 영문 캡션이 항상 필수라는 뜻은 아니다. 실제 학습 방식·텍스트 준비 여부는 미정이다.
- 2026-11-02 수집 기록은 원본 58장·새 외관 후보 22장이다. 당시 분할은 미지정이며 부위 라벨·촬영 맥락 자료의 확보 수가 아니다. 현재 총량을 재집계한 값도 아니다.
- 기존 외관 검수에서 제외된 현판·조각·지붕 근접 사진은 요소 과업에서 재검토할 수 있다. 외관 정답 제외를 모든 과업의 폐기로 해석하지 않는다. 요소 정답·권리·계보는 별도로 확인한다.

## 8. 준비 순서와 검증 계획 — 미실행

수집 장수·합격 수치·시간 제한은 아직 정하지 않았다. 단계 순서가 날짜별 대기를 뜻하지 않는다.

1. **범위 합의:** 지원 요소와 명칭, 메모 단위, 후보 확인·거절 시 경험을 정한다. 현판·처마는 대화 예시이자 첫 후보이며 확정 목록이 아니다.
2. **기본 목록 검수:** 세 건물의 위치·배치·요소·설명 근거와 지원 밖 주변 후보 처리 방식을 정한다.
3. **작은 자료 묶음 점검:** 기존 자료부터 재검토한다. 같은 기준으로 요소·소속·미상을 판단할 수 있는지 확인해 라벨 경계를 보완한다.
4. **부족 조건 보충:** 근접/전체 사진의 작은 요소/다른 면/혼동 건물/가림/부재를 준비한다. 촬영 맥락이 필요한 사례는 별도 확보한다.
5. **기준선 비교:** 요소 종류만 사용하는 경우와 위치·등록 정보를 더한 경우를 비교한다. 방향 등은 확보·신뢰 조건 확인 후 별도 비교한다. 정답 소속을 미리 입력한 실험은 실제 후보 축소 성능과 구분한다.
6. **메모 연결 검증:** 독립 촬영 사진에서 보이는 요소에 맞는 메모를 가져오는지 확인한다. 미확정 요소를 ‘메모 없음’으로 잘못 표시하는지도 본다.
7. **기기·경험 확인:** Android 처리 시간·실패 복구·확인 부담을 측정한다. PC 결과를 기기 성능으로 전용하지 않는다. 범위를 선택한 뒤 백로그·계약·평가 기준에 반영한다.

검증 항목 후보는 요소별 인식·영역, 실제 건물이 후보에 남는 비율·후보 수, 잘못된 건물/요소에 메모를 붙인 비율, 보류와 처리 가능한 비율, 확인·수정 횟수, 기기 지연이다. 모두 보류하는 방식이 좋아 보이지 않도록 오류와 처리 가능한 비율을 함께 본다. 자동 인식과 사용자 확인 후의 결과를 따로 집계한다. 통과 기준은 본 평가 전에 사용자와 정한다.

제품 가치는 ‘자기 사진에서 궁금한 요소의 설명과 관련된 다른 시선을 만나는 수고가 줄어드는가’라는 가설이다. [제품 원칙](../PRODUCT.md#개발-핵심-원칙-사용자가-선택할-이유)에 따라 기존 AI·검색·현장 안내와 비교할 과업을 정하고 설명의 도움·확인 부담·자발적 메모 열람을 확인한다. 이 경험의 우위나 수요는 아직 입증되지 않았다.

## 9. 다음에 결정할 항목

- 처음 지원할 요소와 라벨 의미. ‘지붕/처마’, ‘문양/단청’ 등 경계가 겹치는 경우의 처리.
- 메모가 요소 전체에 관한 것인지, 특정 면·개별 요소·지점까지 구별해야 하는지.
- 소속이 불확실할 때 일반 설명·후보 확인·수정 경로의 순서와 최소 조작.
- 보이는 요소의 메모 표시와 관련 목록 제공 방식, 미확정 상태의 표현.
- 주변 지원 밖 건물의 등록 수준, 수집량·촬영 조건·검수 방식·독립 평가 기준.
- 모델·학습 방식과 기기에서 가능한 처리 범위. 새 학습이 필요한지부터 기준선으로 판단.

위 §1~9는 논의 보존과 문서 연결의 기록이다. 그 저장 시점에는 추가 사진 수집·라벨링·학습·후보 축소 실험·부위별 메모 구현·성능 검증을 수행하지 않았다. 이후 수집 실행은 아래에 별도로 연결한다.

## 10. 후속 실행 기록 — 2026-11-03

문서 저장 후 사용자가 데이터 수집 시작을 요청했다. 기존 세 건물 외관 보강을 진행해 별도 2차 배치로 원본 25장·새 외관 후보 14장을 확보했다. 1차와 누적 원본 83장·외관 후보 36장이며, 교태전 추가 1장은 기존 실험의 재게시라 새 후보로 세지 않았다. 상세 수령·검수·검사는 Git 제외 내부 기록이 원본이다.

## 11. 후속 사용자 결정 — 2026-11-03

- **수집 범위:** 외관과 현판·처마 근접 사진 후보를 함께 수집한다. 이는 수집 후보의 승인으로, 제품의 자동 인식 성능이나 메모 연결 단위를 확정한 것은 아니다.
- **획득 경로:** AI가 바로 다운로드할 수 있는 자료로 한정하지 않는다. 앞서 지정한 출처 전체를 대상으로 로그인·신청·수동 다운로드·원문 확인이 필요한 자료도 목록과 구체적 수령 절차를 관리한다.
- **출처 비공개:** 파일별 출처·저작자·이용조건과 획득 경로를 내부에 보존한다. 사용자가 공개를 허용하기 전까지 상세 출처 대장·수집 도구·사진 갤러리를 Git/외부 게시 대상으로 삼지 않는다. 향후 자료를 공개할 때 필요한 출처표시 검토는 별도 수행한다.
- **남은 결정:** 지원 요소의 정확한 라벨 경계, 메모의 면·개별 지점 구분, 최종 수집량·학습 방식·평가 기준은 계속 미정이다.
