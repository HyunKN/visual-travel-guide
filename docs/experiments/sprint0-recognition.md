# Sprint 0 자료 확보·사진 식별 실험

2026-10-23 사용자 요청으로 조사·실행했다. **공식 사진 확보와 PC 모델 실행은 완료했고, 현재 참조 사진 1장씩 비교하는 방식의 식별 품질은 부족했다.** 제품 모델 선정·학습 완료·브라우저/Android 실행·현장 성능 검증 기록이 아니다. 제출 Word와 발표자료는 이 기록의 확인된 내용만 사용한다.

**후속 결정 · 2026-10-24:** 사용자가 설치형 Android 앱·기기 내 추론을 우선 선택했다. 아래 브라우저 실행 제안은 10월 23일 당시 검토안으로 보존하며 다음 실행 우선순위는 [현재 구조 초안](../ARCHITECTURE.md)을 따른다. MobileNet 우선 후보와 방문객 촬영 사진을 이용한 평가 방향을 논의했으며 새 자료 확보·Android 실행·최종 모델 선정은 아직 완료하지 않았다.

## 1. 조사·실험의 목적과 판정

기준은 [4차 백로그](../PRODUCT_BACKLOG_DRAFT.md)의 Sprint 0, US-04·05·08과 [양식 6 구조 초안](../ARCHITECTURE.md)이다. 모바일 웹에서 사용할 사진 자료가 있는지, 모델이 실행되는지, 대표 사진과 다른 사진을 구별하는 신호가 있는지 확인했다.

사용자 가치 가설은 사진에서 출처 있는 설명까지 가는 수고를 줄이는 것이다. 이번 실행은 데이터·모델의 기술 확인이며 기존 검색·상용 AI보다 편리하다는 근거가 아니다. 첫 사용 경험의 비교는 [QUALITY](../QUALITY.md)의 별도 과업으로 평가한다.

[실행 전 계약과 진단 추가 이력](../../experiments/sprint0-recognition/README.md)에 자료 분리·기준선·지표·통과 조건을 먼저 기록했다. 최초 INT8 실행 뒤 FP32 정밀도 진단, 그 뒤 작은 MobileNet 비교를 추가했으며 각각 별도 결과로 남겼다. 결과를 보고 참조 사진이나 정답·통과 기준을 바꾸지 않았다.

## 2. 확보한 자료

국가유산청 궁능유적본부의 안내 페이지에서 **26장, 총 17,877,358 bytes**를 내려받았다. 23장은 여섯 후보 건물의 외관 사진, 3장은 다른 주대상이 있는 통제 입력이다. 23장을 참조 6장과 개발용 probe 17장으로 구분했다. 사진 해상도는 아래 manifest에 개별 기록했다.

3개 통제 입력은 근정문(5673), 만춘전(5691), 아미산굴뚝 권역(5744)이다. 여러 건물·수목이 함께 보이는 장면도 있으므로 객체가 하나뿐인 엄밀한 음성 평가셋으로 보지 않는다. 입력 전체의 주대상이 지원 건물인지 확인하는 실패 사례로 사용한다.

**선별과 출처 확인:** 안내 페이지의 사진별 한글 캡션을 수집하고 contact sheet를 직접 확인했다. 한 페이지에 근정문·만춘전·천추전·아미산 등 다른 대상도 있어 페이지 제목을 모든 사진의 정답으로 사용하지 않았다. 5720은 야경 캡션과 화면 인상이 달라 낮/밤 집계에서 ambiguous로 분리했다. probe 구성은 낮 9장·야간 7장·모호 1장이다. 정확히 같은 파일은 없지만 근접 중복·같은 촬영 회차 여부는 미확인이다.

**이용 조건:** 여섯 안내 페이지에서 연결하는 KOGL 표지 이미지를 내려받아 `Type 1: Source Indication`을 확인하고, 연결된 [국가유산청 유형 안내](https://www.khs.go.kr/html/popup/koglEngInfo.html)와 [공공누리 제1유형](https://www.kogl.or.kr/info/licenseType1.do)을 대조했다. 기관·제목·원문·사진 URL·표지·SHA-256을 [manifest](../../experiments/sprint0-recognition/manifest.json)에 보존했다. 이번 범위는 출처를 남긴 로컬 연구 실험이다. 사진·가중치 재배포 패키지나 공개 서비스 적용의 검토를 완료했다는 뜻은 아니다.

**수집일과 촬영일은 다르다.** 촬영일은 확인되지 않아 `null`로 두었다. 이번에 다운로드한 사진을 ‘최신 촬영 사진’이라고 표현하지 않는다. 출처 페이지 사본·사진 원본·검토용 contact sheet는 Git 제외 폴더 `.codex-build/sprint0-recognition/`에 보관했다.

### 자료가 충분한가?

작은 실행·실패 진단에는 사용할 수 있으나 **학습·독립 평가 자료 확보 완료 상태는 아니다.** 같은 기관의 소량 사진이며 방문객 눈높이의 촬영 조건을 대표하지 못한다. CLIP/MobileNet의 기존 학습 자료에 이 공개 사진이 포함됐는지도 확인할 수 없다.

추가 확보는 방문객 눈높이의 정면·대각·가림·흐림과 혼동 건물 중심으로 한다. [국가유산 디지털 서비스](https://digital.khs.go.kr/)와 [Wikimedia 교태전 분류](https://commons.wikimedia.org/wiki/Category:Gyotaejeon)를 추가 경로로 확인했지만 이번 실행에는 사용하지 않았다. Commons에는 같은 기관 사진의 재게시도 있어 도메인이 다르다는 이유로 독립 사진으로 세면 안 된다. 개별 파일의 저작자·이용 조건·촬영일·원출처를 확인한 뒤 채택한다. AI Hub의 적합한 학습셋 확보·다운로드는 이번에 확인하지 못했다.

## 3. 실행 방식과 원본

두 후보 모두 미리 학습된 이미지 인코더를 고정했다. 입력 사진을 특징 벡터로 바꿔, 건물마다 준비한 참조 사진 1장의 벡터와 cosine similarity를 비교했다. 모델이 경복궁 건물명을 원래 알고 맞힌 zero-shot 시험이나 추가 학습 실험은 아니다. 이름은 참조 사진에 붙인 내부 건물 ID에서 가져왔다.

| 비교 | 파일·출력 | 출처와 기록 |
| --- | --- | --- |
| 색상 기준선 | RGB 각 8-bin 히스토그램, 24차원 | 모델 없이 색감만 비교. 같은 자료와 cosine 사용 |
| CLIP INT8 | image encoder 512차원, 89,117,001 bytes(84.99 MiB) | [Xenova ONNX 변환본](https://huggingface.co/Xenova/clip-vit-base-patch32), revision `d15189d7028b43f1d3e65039190477f6af591c2a` |
| CLIP FP32 | 같은 revision의 image encoder, 351,685,709 bytes(335.39 MiB) | INT8 결과 확인 후 정밀도 진단용 추가 실행 |
| MobileNetV2 FP32 | ImageNet 분류층 전의 1280차원 특징, 파생본 8,844,641 bytes(8.43 MiB) | [ONNX Model Zoo](https://github.com/onnx/models/tree/c5cae0f1942c8d7727372c7b1f6b485aa39e4421/validated/vision/classification/mobilenet), 원본 `mobilenetv2-12.onnx` 13,964,571 bytes |

MobileNet은 원본의 pooling/reshape 출력 `472`를 추출했다. 동적 reshape의 출력 shape가 없어 최초 ONNX 추출 검사에 실패했고, 분류층 입력과 일치하는 1280차원 출력을 명시해 검사했다. 추출 특징에 원본 분류층 weight/bias를 적용한 결과와 원본 logits의 최대 오차 `2.8610e-06`을 확인했다. 모델 재학습은 하지 않았다. 전처리는 각 원본의 resize/crop/mean/std를 분리했다. 파생 파일을 원본 배포물로 표시하지 않는다.

CLIP INT8와 FP32의 같은 사진 특징 cosine 평균은 `0.9544`, 17개 probe의 1순위 일치는 11개다. 양자화가 이 조건의 결과를 바꾸므로 ‘압축만 하고 정확도는 같다’고 가정할 수 없다. 이것만으로 전체 실패 원인을 양자화 하나로 확정하지도 않는다.

원본 CLIP 저장소는 [MIT 고지](https://github.com/openai/CLIP/blob/main/LICENSE), 선택한 Model Zoo 모델은 위 pinned README의 Apache-2.0 표기를 확인했다. Xenova는 변환 배포자이며 OpenAI 공식 모바일 모델 출시로 표현하지 않는다. MobileCLIP2는 코드와 가중치 약관이 달라 [별도 조사](mobile-web-inference-options.md)의 조건을 확인하고 제품 후보 채택을 보류한다.

## 4. 결과: 실행 성공, 현재 식별 방식은 부족

**아래 17장은 개발용 probe다. 최종 시험 정확도·제품 목표 달성률로 사용하지 않는다.** 참조가 클래스당 1장이고 자료가 불균형하다.

| 비교 | 1순위 정답 | 상위 3개에 정답 포함 |
| --- | --- | --- |
| 색상만 비교 | 3 / 17 | 10 / 17 |
| CLIP INT8 | 2 / 17 | 11 / 17 |
| CLIP FP32 | 5 / 17 | 13 / 17 |
| MobileNetV2 FP32 특징 | 6 / 17 | 11 / 17 |

MobileNet의 건물별 1순위는 근정전 2/4, 경회루 2/4, 사정전 0/1, 수정전 1/2, 강녕전 1/3, 교태전 0/3이다. 이 작은 차이로 MobileNet이 CLIP보다 전반적으로 우수하다고 결론 내리지 않는다. 특정 건물의 예시만 골라 시연하면 실패를 감추게 된다.

**불확실 처리도 남아 있다.** 최근접 방식은 통제 입력 3장에도 여섯 건물 중 하나를 반드시 반환했다. 예를 들어 만춘전은 MobileNet에서 수정전 후보로 cosine 약 0.799를 받았다. 따라서 cosine을 79.9% 정답 확률로 표시하거나 높은 값 하나로 자동 확정하면 안 된다. 이 자료에서 임계값을 골라 보류 성능을 주장하지 않았다.

**실행 비용:** Windows x64, Python CPUExecutionProvider, intra-op 2/inter-op 1 thread 조건이다. 세션 적재와 고정 사진 warm 10회의 추론 시간은 아래 JSON에 기록했다. 재현 정보 보완 후 같은 평가를 다시 실행해 정답 건수의 일치를 확인했으며, 실행 시간은 PC의 당시 부하에도 영향을 받는다. 모델의 일반 속도 우위를 주장하지 않는다. 파일 크기에 비해 실행 시 메모리는 더 들 수 있으나 메모리는 계측하지 않았다. CPU 정보의 시스템 조회가 제한되어 상세 하드웨어 비교는 미수행이다. **PC 시간은 Android·WASM·WebGPU 시간으로 옮겨 쓰지 않는다.**

원자료: [INT8·색상 결과](../../experiments/sprint0-recognition/results.json), [FP32 정밀도 진단](../../experiments/sprint0-recognition/precision-comparison.json), [MobileNet 결과](../../experiments/sprint0-recognition/mobilenet-results.json). 이미지·모델 hash, 라이브러리 버전, 개별 예측, 시간 원자료를 포함한다.

| Android | OS 방향만 합의, 기종 미정 | 실기기·OS 버전·Chrome 버전·지연·메모리 미검증 |
| 브라우저 모델 실행 | 공식 WASM/WebGPU 지원 조사 | 현재 CUA에 브라우저가 없어 실행 미수행. PC Python 성공으로 대체하지 않음 |

[실행 명령과 설치 장애 처리](../../experiments/sprint0-recognition/README.md)를 보존했다. 실험은 제품의 dependency와 분리했고 원본 사진·모델·환경은 기존 Git 제외 폴더에 뒀다. 기존 3D chunk 500kB 초과 경고는 build 실패가 아니며 인식 모델 크기와 별개다. 깨끗한 다른 PC에서의 재설치까지 검증한 것은 아니다.

## 6. 양식 6에 연결할 구조 제안

모델 파일의 **보관/전달 장소**와 사진을 **계산하는 장소**는 다르다. [ORT 공식 배포 안내](https://onnxruntime.ai/docs/tutorials/web/deploy.html)는 JavaScript·WASM·모델 파일을 웹 배포 자산으로 설명한다. 모바일 웹에서도 파일은 정적 서버에서 내려받고 계산은 방문객 폰의 브라우저에서 수행할 수 있다. 서버 추론은 사진을 전송해 서버에서 모델을 실행하는 별도 경로다.

제안은 기존 모바일 웹과 콘텐츠 ID를 유지하고, **교체 가능한 인식 연결부**를 두는 것이다. 실험 후보로 작은 MobileNet 파생 모델의 WASM 실행을 먼저 확인할 수 있다. 제품 모델과 브라우저 추론의 최종 채택은 아직 결정하지 않았다. 이번 식별 성적이면 실행만 성공해도 제품에 바로 붙여 ‘인식 완료’로 처리하면 안 된다.

- 화면/탐색: 현재 JavaScript + Vite를 출발점으로 재사용하는 안. 사진 선택·미리보기·취소는 모델 실험과 독립 구현 가능하다.
- 콘텐츠: 소량 검수 자료는 버전 관리 JSON + ID/참조 무결성 검사로 시작하는 안. 검색/설명 때문에 바로 DB·서버를 필수로 만들지 않는다. 운영 중 편집·대량 자료·동기화 요구가 생기면 재검토한다.
- 브라우저 실행: 정적 모델 전달 → Worker 내 전처리/추론 → 후보 ID → Application 판단 → 같은 ID의 설명 조회. 홈과 예시는 모델 적재를 기다리지 않는다. 최초 다운로드·취소·재시도·메모리를 검증한다.
- 서버 대안: 같은 연결부에서 사진 → Python ONNX Runtime 추론 → 후보 ID/상태 응답. 로컬 CPU 실행만 확인했으며 서버 API·공개 배포는 구현하지 않았다. 전송·보관·비용·장애 기준을 정해야 한다.

실기기에서 검증할 것은 선택한 ONNX의 WASM 연산 호환성·초기 다운로드·단일/다중 thread·결과 parity·UI 응답·중단/재입력·메모리다. WebGPU는 실제 adapter·연산·HTTPS를 확인한 뒤 추가 비교한다. 자세한 근거는 [모바일 웹 실행 조사](mobile-web-inference-options.md)에 있다.

## 7. 이번 주 백로그·다음 결정에 미치는 영향

- Sprint 0: 6개 건물의 공식 소량 자료 확보와 두 후보 계열의 PC 실행 근거가 생겼다. 학습셋 확보·독립 평가·Android 실행은 남았다.
- US-05: 현재 방식의 품질이 부족하므로 자료 확충과 학습/참조 방식 재검토가 필요하다. **8 SP 가안과 Sprint 배치는 자동 변경하지 않았다.** 실기기·데이터 확보 결과를 더한 뒤 재추정한다.
- US-01·04·08: 첫 화면·입력·검수 콘텐츠 연결은 모델 선정과 분리해 진행할 수 있다. 예시 결과를 실제 입력의 모델 결과로 표시하지 않는다.
- 다음 실행 제안: 눈높이 독립 사진을 확보하면서 작은 모델의 브라우저 실행을 확인한다. 새 학습에 들어가기 전 자료 분리와 건물별 평가 사례를 정한다. 참조 한 장만 바꾸고 기존 probe 점수가 오른 것을 독립 성능 개선으로 부르지 않는다.
- 사용자와 정할 항목: 브라우저 실행을 우선 검증할지, 서버 전송을 허용하는 대안도 비교할지, Android 시험 기기. 대기 시간·메모리 예산은 기기와 첫 사용 흐름을 정할 때 함께 정한다.

이번 작업으로 양식 6에 기재할 수 있는 것은 **자료 출처·취급, 책임 경계, 후보 실행 기록, 확인한 개발 환경, 미검증 항목과 다음 실험**이다. 제출용 Word·PPT 작성, 실제 사용자 재시험, 커밋·push·배포는 수행하지 않았다.
