# 작업 채팅과 컨텍스트 관리

채팅을 시작하거나 작업을 인계할 때 읽는다. 공통 규칙은 저장소 문서, 작업의 목적·완료 기준은 Issue, 변경·검증 증거는 PR을 기준으로 이어받는다.

## 채팅의 역할

| 채팅 | 책임 | 완료 기록 |
| --- | --- | --- |
| AI Workflow·개발환경 | 공통 문서, 스킬 연결, CI, Wiki, 작업·인계 규칙 | 설정 Issue·PR |
| 프로토타입 | 특정 사용자 과업과 화면 흐름 확인 | 관찰 결과, 구현 한계, 후속 Issue |
| 기능 구현 | 하나의 Issue 또는 밀접한 작업 묶음 구현 | PR, 실행한 검사, 문서 변경 |
| 제품 테스트·실험 | 지정 버전에서 사용자·모델·기기 검증 | 조건, 기준선, 결과, 실패·미확인 항목 |

프로토타입·기능·제품 테스트 채팅은 실제 작업을 시작할 때 프로젝트 안에 생성한다. 사용자 요청 없이 빈 채팅을 미리 여러 개 생성하지 않는다. 환경 설정을 검증하는 검사는 AI Workflow 작업에서 수행한다.

채팅 하나는 목적이 분명한 작업 단위를 다룬다. 같은 변경을 구현하고 확인하는 과정은 필요한 경우 같은 채팅에서 끝내도 된다. 별도 테스트 채팅이 필요한 경우에는 먼저 검증할 커밋을 고정한다.

## 새 채팅의 시작 정보

시나리오 프로토타입을 Sol에게 넘길 때는 [작성된 인계문](prototype/HANDOFF.md)을 사용한다. 설계 문서가 포함된 실제 커밋/PR을 전달한다. 미커밋 문서라면 같은 checkout의 변경 목록을 명시하며, 새 worktree에 자동 공유된다고 가정하지 않는다.

다음 내용을 새 채팅의 첫 요청에 전달한다. 정보가 빠졌다면 저장소·Issue에서 확인하고, 안전한 진행을 막는 사항만 질문한다.

```text
작업 종류: 프로토타입 / 기능 구현 / 제품 테스트·실험
목적:
작업 Issue URL:
기준 브랜치·커밋 또는 PR:
변경할 범위와 이번 범위 밖:
관련 문서: AGENTS.md + 이번 작업에 필요한 docs 경로
완료 기준:
검증: AI가 수행할 검사 / 사람이 확인할 항목
선행 작업과 남은 미정 사항:
```

AI는 실제 Git 상태와 문서를 확인한 뒤 시작한다. 대화 전체를 복사하는 대신 결정과 재현 가능한 기록을 연결한다. 문서에 없는 제품 선택을 이전 대화의 합의라고 추정하지 않는다.

## 작업을 마칠 때

- Issue·PR에 기준 커밋, 변경, 실제 검사, 남은 제한, 다음 작업 링크를 남긴다.
- 다른 채팅이 이어받을 작업은 위 시작 정보와 함께 마지막으로 확인한 버전을 전달한다.
- 공통 규칙의 문제를 발견하면 AI Workflow 채팅에서 검토할 근거와 개선안을 연결한다. 일회성 결과는 해당 작업 기록에 둔다.

## 동시에 작업할 때

각 구현 채팅은 담당 Issue와 변경 범위를 명시한다. 병렬 편집이 필요하면 별도 브랜치·worktree를 사용하고 같은 파일의 책임을 조정한다. 동일 checkout을 공유하는 채팅의 변경을 자기 작업으로 커밋하거나 되돌리지 않는다.

채팅 분리는 불필요한 대화를 줄이는 데 도움이 되지만 필요한 맥락도 빠질 수 있다. 위 시작 정보와 공통 문서를 함께 사용해야 한다. Wiki는 main의 게시본이므로 작업 브랜치의 최신 설계는 로컬 문서에서 확인한다.
