# Visual Travel Guide

**경복궁에서 눈앞의 건물과 문양·구조물 같은 관심 부분을 알아보고, 출처 있는 설명까지 이어서 볼 수 있도록 돕는 탐색 가이드**

> **현재 단계: 문제·사용자 경험 정의 및 프로토타입·기술 검증 준비**
>
> 이 저장소는 프로젝트의 목표, 개발 범위, 검증 계획과 구현 현황을 공개적으로 정리합니다. 아래의 서비스 흐름과 성능 수치는 **설계안 또는 검증 목표**이며, 실제 구현·측정이 끝났다는 의미가 아닙니다.

개발 작업을 시작할 때는 **[개발 문서 안내서](docs/README.md)**를 읽습니다. 첫 클릭형 흐름의 범위는 [PRODUCT](docs/PRODUCT.md), AI 협업은 [DEVELOPMENT](docs/DEVELOPMENT.md), 개별 채팅의 시작·인계는 [THREADS](docs/THREADS.md), 검증 기준은 [QUALITY](docs/QUALITY.md)에서 관리합니다. [개발 Wiki](https://github.com/HyunKN/visual-travel-guide/wiki/Development-Home)는 병합된 문서의 게시본입니다.

**지금 만드는 단위는 [시나리오 기반 프로토타입](docs/prototype/README.md)입니다.** 준비된 장면에서 건물 전체나 문양·구조물을 선택하고 기본 설명·관련 질문을 확인하는 흐름과 작은 호기심 카드를 설계했습니다. [8개 작업안](docs/prototype/TASKS.md)과 [Sol 인계문](docs/prototype/HANDOFF.md)을 마련했으며 앱 구현과 사람 관찰은 아직 하지 않았습니다. 아래의 검색·촬영·모델 실험·성능 목표는 후속 구상이며 첫 프로토타입의 필수 구현이 아닙니다.

## 1. 프로젝트 개요

### 해결하려는 문제

경복궁을 자유롭게 관람하는 관광객은 눈앞의 건물이 궁금하더라도 건물 이름을 모를 수 있습니다. 관광 지도, 공식 안내, 오디오 가이드, 범용 이미지 검색 등 이미 다양한 정보 접근 방법이 있지만, 상황에 따라 **실제로 보고 있는 건물과 안내 정보를 직접 대조하고 해당 설명을 찾아야 하는 과정**이 남을 수 있습니다.

프로젝트는 기존 관광 서비스의 기능 부족을 단정하지 않습니다. **경복궁 현장에서 대상을 확인하고 필요한 설명에 도달하는 과정에 개선할 여지가 있는지**를 실제 사용 경험과 기술 실험으로 검증합니다.

### 대상 사용자

- 경복궁을 가이드 없이 자유롭게 둘러보는 국내·외 관광객
- 궁궐의 건물 이름이나 배치, 건축적 특징에 익숙하지 않은 방문객
- 텍스트 검색보다 사진·위치·주변 건물 등 현장에서 얻을 수 있는 단서로 탐색하려는 사용자

### 핵심 목표

**사용자가 알고 있는 단서에서 탐색을 시작해, 대상을 확인하고 출처 있는 설명까지 연결하는 것**입니다.

```text
경복궁에서 궁금한 건물 발견
        ↓
이름 검색 / 지도·주변 사진 선택 / 직접 촬영
        ↓
건물 확인 (불확실하면 후보 비교)
        ↓
건물 명칭 · 간단한 설명 · 관람 포인트 · 출처 확인
```

사진을 사용하는 경우 위치정보는 건물 후보를 좁히는 **보조 단서**입니다. 가까운 건물이 반드시 촬영 대상인 것은 아니며, 위치 권한을 거부하거나 정확도가 낮더라도 다른 방법으로 탐색할 수 있도록 설계합니다.

## 2. 핵심 사용자 경험과 개발 범위

| 사용자 상황 | 제안하는 경험 | 현재 상태 |
| --- | --- | --- |
| 이름을 아는 건물을 찾고 싶음 | 이름 검색, 지도 또는 건물 목록에서 선택 | 화면·흐름 설계 단계 |
| 눈앞의 건물 이름을 모름 | 사진 촬영과 사용 가능한 위치정보로 건물 후보 탐색 | 이미지 식별 방식 검증 예정 |
| 후보 건물이 서로 비슷함 | 위치·현판·외관 등 구별 단서를 이용해 2~3개 후보를 비교하고 사용자 확인 | 화면·흐름 설계 단계 |
| 건물의 의미가 궁금함 | 확인한 건물에 대한 짧은 설명, 추가 설명, 관람 포인트와 출처 제공 | 콘텐츠·출처 연결 방식 설계 단계 |
| 촬영 실패 또는 위치 권한 없음 | 재촬영, 검색, 지도·사진 목록 등 대체 경로 제공 | 예외 흐름 설계 단계 |

**첫 사용자 경험 검증에는 건물 전체와 선별된 문양·구조물의 탐색·지정·설명 연결을 포함합니다.** 준비된 사진과 영역을 사용하며, 세부 요소의 자동 인식까지 구현하는 것은 아닙니다. 경복궁 전체의 지원을 약속하지 않으며 실제 대상은 자료 확보와 검수 결과로 정합니다.

다음 항목은 핵심 기능과 구별하여 후속 탐색 또는 장기 과제로 관리합니다.

- 현판·문양·장식 등 **세부 요소의 자동 식별**: 건물 단위 식별과 다른 문제이므로 별도로 실험합니다. 일부 선별된 설명을 연결하는 경험을 검토할 수 있지만 자동 인식 성능은 확인되지 않았습니다.
- 경복궁 관람 전후의 **종로 지역 연계**, 추천 동선, 고도화된 길찾기
- LLM/RAG 기반 질의응답, AR·3D 안내, 완전한 오프라인 실행

해당 기능들은 **현재 구현을 확정한 요구사항이 아닙니다.**

## 3. 구현과 검증을 분리한 접근

사용자에게 유용한지 확인하는 실험과 이미지 인식 기술이 실제로 동작하는지 확인하는 실험을 구분합니다.

### A. 사용자 경험 프로토타입

- **HTML/CSS/JavaScript 클릭형 프로토타입(설계 작성):** 건물 전체와 문양·구조물을 탐색하고, 이름·짧은 설명을 먼저 본 뒤 필요하면 준비된 관련 질문을 선택합니다. 실제 AI 인식이나 GPS 연동 없이 준비된 자료를 사용합니다. 화면·자료·관찰·작업 분할은 [상세 설계](docs/prototype/README.md)를 따릅니다.
- **현장 Wizard-of-Oz 방식(계획):** 일부 결과를 진행자가 제공하는 방식으로 사용 흐름을 관찰합니다. 이는 실제 AI 모델의 정확도나 응답 속도를 증명하지 않습니다.
- **기존 방식과 비교(계획):** 관광 지도·공식 안내·검색을 사용하는 과업과 제안한 화면을 사용하는 과업을 비교하고 실패·재시도·탐색 시간을 기록합니다.

### B. 건물 식별 기술 PoC

특정 모델이나 추론 방식을 미리 확정하지 않고 동일한 데이터 조건에서 후보를 비교합니다.

1. **초기 데이터 구축:** 외관이 비슷한 건물 약 6~10개를 대상으로 다양한 촬영 각도·거리·조건의 이미지를 확보하는 소규모 파일럿을 검토합니다. 실제 데이터 확보 수량은 아직 확정되지 않았습니다.
2. **식별 방식 비교:** 같은 이미지 특징 추출 모델을 기준으로 분류기, 건물별 대표 벡터 비교, 여러 참조 사진을 활용한 검색을 비교합니다.
3. **모델 후보 비교:** MobileCLIP2-S2, DINOv3 ViT-S/16 등을 검토하고 필요 시 SigLIP2를 추가합니다. **선정·성능 검증은 완료되지 않았습니다.**
4. **위치정보의 기여 검증:** 사진만 사용한 결과와 사진+위치정보 결과를 비교합니다. 멀리 있는 건물을 촬영하거나 위치정보가 부정확한 상황도 포함합니다.
5. **실제 기기 검증:** 서버 처리와 모바일 브라우저·기기 내 처리 중 적절한 구조를 실제 실행 가능성, 지연 시간, 메모리, 네트워크 조건 등을 보고 결정합니다.

건물 **개체 식별**과 문양 **종류 분류**, 특정 건물에 있는 **개별 장식 식별**은 서로 다른 과업으로 관리합니다. 한 과업의 결과를 다른 과업의 성능으로 해석하지 않습니다.

### 데이터 및 평가에서 주의할 점

- 같은 촬영 장면의 연속 사진·잘라낸 이미지가 학습 데이터와 테스트 데이터에 동시에 들어가지 않도록 구분합니다.
- 지원 대상이 아닌 사진, 유사한 외관, 흐림·역광·가림, 위치 권한 거부 등의 사례를 포함합니다.
- Top-3은 중복 사진 3장이 아니라 **서로 다른 건물 후보 최대 3개**를 기준으로 평가합니다.
- 잘못된 높은 확신과 결과 없음 상황을 기록하고, 사용자 확인 없이 불확실한 답을 사실처럼 안내하지 않습니다.
- 연구용 PC에서 작동하는 결과를 실제 스마트폰에서 구현된 성능으로 간주하지 않습니다.

## 4. 초기 성공 기준(검증 전 목표)

아래는 사용자 경험 및 기술 실험의 방향을 정하기 위한 **초기 목표치**입니다. 측정된 성능이 아니며 파일럿 결과에 따라 측정 방법과 목표를 조정할 수 있습니다.

이 목표치는 첫 모의 관찰의 합격 기준이 아닙니다. 진행자와 소수 참여자로 수행하는 첫 관찰에서는 독립 수행·도움·미지원·설명 이해를 기록하며 일반 성공률이나 개선 효과를 추정하지 않습니다.

| 지표 | 초기 목표 | 측정 관점 |
| --- | --- | --- |
| 건물 식별 Top-1 정확도 | 80% 이상 | 첫 번째 건물 후보가 정답인지 |
| 건물 식별 Top-3 정확도 | 90% 이상 | 서로 다른 건물 후보 3개 안에 정답이 있는지 |
| 대상 확인·설명 접근 과업 성공률 | 85% 이상 | 사용자가 대상 확인과 필요한 설명 찾기를 완료하는지 |
| 현장 확인 시간 | 기존 방식 대비 30% 이상 단축 | 같은 난이도의 과업으로 비교하는지 |
| 사용자 유용성 평가 | 5점 만점 중 4점 이상 | 실제 테스트 참여자 평가 |

사용성 평가에서는 **성공률과 실패율을 함께** 보고, 걸린 시간은 실패·중단 여부와 구분하여 분석합니다. 과업 순서에 따른 학습 효과도 고려합니다. 기준선이 없거나 실제 실험이 수행되지 않았다면 개선 효과를 달성했다고 표현하지 않습니다.

**현재 저장소는 기획·개발 문서와 AI Workflow 설정을 관리합니다.** 앱 구현 코드, 실행 방법, 제품 테스트 결과가 추가되면 이 표를 실제 상태에 맞춰 갱신합니다.

## 6. 향후 작업 순서

1. **사용자 흐름과 클릭형 프로토타입:** 대표 시나리오를 화면으로 연결하고 누락된 행동·예외 상황을 확인합니다.
2. **Product Backlog 작성:** 기능별 User Story, 우선순위, 수용 기준(Acceptance Criteria), 기술 검증 과제를 구분합니다.
3. **초기 개발 환경 및 데이터 설계(Sprint 0):** 지원 건물과 자료 구조, 촬영·위치 입력 방식, 실험 환경을 구체화합니다.
4. **건물 식별 기능 구현(Sprint 1):** 사진과 위치 단서를 이용한 건물 후보 제시 및 실패 시 대체 탐색 경로를 우선 검증합니다.
5. **핵심 경험 통합(Sprint 2):** 후보 비교, 사용자 확인, 출처 있는 설명 연결과 예외 흐름을 통합합니다.
6. **현장 평가 및 개선:** 기존 방식과 실제 결과를 비교하고 지원 범위·화면·식별 방식을 조정합니다.

위 내용은 **개발 계획**이며, 각 Sprint가 완료되었다는 의미가 아닙니다. 우선순위는 프로토타입과 초기 실험 결과에 따라 조정합니다.
