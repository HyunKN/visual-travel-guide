# Visual Travel Guide

처음 방문한 관광지에서 **현재 위치 → 눈앞의 대상 → 장소 설명 → 다음 이동 방향**을 한 흐름으로 확인하는 관광 안내 프로젝트다. 기존 지도·검색·현장 안내를 활용하면서, 같은 장소를 다시 검색하거나 지도와 실제 공간을 반복해서 맞춰 보는 수고를 줄이는 것을 목표로 한다.

이 README는 구현 범위, 다음 작업, 완료 조건을 관리하는 작업 문서다. 문제 정의는 제공된 문제점 목록과 발표 자료를 바탕으로 정리했다. 아래 초기 구현 범위와 검증 방법은 실제 개발을 시작하기 위한 작업 초안이며, 구현 완료를 뜻하지 않는다.

## 현재 상태

| 항목 | 상태 |
| --- | --- |
| 문제 정의와 기존 이용 흐름 | 제공 자료를 바탕으로 정리 |
| 애플리케이션 코드 | 아직 없음 |
| 대상 관광지와 지원 POI 목록 | 미정 |
| 플랫폼·기술 스택·인식 방식 | 미정 |
| 데이터셋·모델·평가 결과 | 이 저장소에 없음 |
| 설치·실행·테스트·배포 명령 | 코드와 실행 환경을 정한 뒤 추가 |

현재 저장소만으로 실행할 수 있는 서비스는 없다. 기능을 구현할 때 해당 실행 방법과 확인 결과를 이 문서에 함께 갱신한다.

## 해결할 문제

주요 사용자는 낯선 관광지를 가이드 없이 둘러보는 자유여행객이다. 한국어에 익숙하지 않은 방문객의 장소 검색과 언어 전환도 고려한다.

| 우선순위 | 관찰된 문제 | 작업에서 확인할 질문 |
| --- | --- | --- |
| 1 | 지도상의 위치와 실제 이동 방향을 빠르게 연결하기 어렵다. | 현재 위치와 다음 목적지를 보여줬을 때 사용자가 어느 쪽으로 이동할지 판단할 수 있는가? |
| 2 | 눈앞 대상의 이름과 의미를 확인하는 경험이 장소마다 다르다. | 대상의 명칭과 근거 있는 설명을 같은 흐름에서 확인할 수 있는가? |
| 3 | 영문 장소명·주소로 검색할 때 추가 탐색이 필요한 사례가 있다. | 같은 장소의 한국어·영어 표기를 연결해 다시 검색하는 수고를 줄일 수 있는가? |
| 4 | 지도·안내판·검색·번역 사이를 오가며 같은 정보를 다시 찾는다. | 장소 확인부터 설명과 이동 안내까지 맥락이 유지되는가? |
| 5 | 대상의 이름을 모르면 텍스트 검색을 시작하기 어렵다. | 이름을 입력하기 전에도 사진이나 주변 장소를 단서로 탐색할 수 있는가? |

자료는 서울·부산 관광객의 온라인 후기, 공식자료, 경험 정리를 바탕으로 한다. 모든 관광객에게 같은 문제가 있다는 검증 결과로 일반화하지 않는다. QR·오디오가이드·관광지도가 도움이 된 긍정 사례도 있으므로, 기존 안내로 충분한 상황과 추가 지원이 필요한 상황을 함께 확인한다. 자료에 인용된 통계와 외부 서비스 현황은 이 저장소에서 별도로 재검증하지 않았다.

## 첫 구현 범위

우선 관광지 한 곳과 지원할 POI(Point of Interest, 관심 지점) 목록을 정하고, 아래 흐름을 끝까지 연결한다. 대상 지역과 POI 수는 자료 확보 및 현장 검증 가능성을 확인한 뒤 결정한다.

```text
사진 또는 주변 POI 선택 + 사용 가능한 위치 정보
  → 대상 후보 제시
  → 사용자가 대상 확인
  → 명칭·짧은 설명·출처 확인
  → 다음 POI 선택
  → 현재 위치·목적지 확인 및 기존 지도 연결
```

| 작업 영역 | 초기 작업 내용 | 완료 조건 |
| --- | --- | --- |
| 위치와 주변 장소 | 위치 권한을 받아 지원 POI를 표시하고, 권한이 없으면 지역·장소를 직접 선택하게 한다. | 권한 허용·거부 상태 모두에서 장소 탐색을 이어갈 수 있다. |
| 대상 확인 | 사진 기반 후보 탐색 방식을 검토하고, 수동 POI 선택 흐름부터 연결한다. | 잘못된 후보를 바꾸거나 결과 없음을 확인할 수 있다. 수동 선택과 자동 인식의 구현 상태를 구분한다. |
| 장소 설명 | 확인한 POI의 한국어·영어 명칭, 짧은 설명, 출처를 연결한다. | 후보를 바꾸면 해당 장소의 설명으로 바뀌고, 설명의 근거를 확인할 수 있다. |
| 다음 이동 | 다음 POI와 현재 위치를 보여주고 기존 지도로 이동 안내를 연결한다. | 선택한 목적지가 지도에서도 일치한다. 실제 방향을 이해하는 데 도움이 되는지는 현장에서 별도로 검증한다. |

초기 범위에서는 전국 관광지 지원, 자체 길찾기 엔진, 실내 정밀 위치 추정, AR 안내, 자동 여행 일정 생성까지 확장하지 않는다. 이러한 기능이나 특정 AI 모델은 확정된 요구사항이 아니다.

## 다음 작업

아래 순서로 진행하고, 각 항목의 완료 조건을 확인한 뒤 체크한다.

1. [ ] **검증 장소와 상황 결정**: 관광지 한 곳, 지원 POI 목록, 출발 위치와 다음 목적지를 포함한 관람 시나리오를 정한다.
2. [ ] **POI 자료 정리**: 식별자, 한국어·영어 명칭, 좌표, 설명, 출처 URL, 확인일을 연결한다. 사진을 사용할 경우 출처와 이용 가능 조건도 기록한다.
3. [ ] **플랫폼과 기술 선택**: 현장에서 사용할 기기, 카메라·위치 권한, 네트워크 조건을 확인하고 플랫폼과 최소 기술 스택을 정한다.
4. [ ] **한 흐름으로 동작하는 화면 구현**: 위치 또는 수동 선택부터 대상 확인·설명·지도 연결까지 이어지게 하고 실제 설치·실행 명령을 추가한다.
5. [ ] **사진 기반 후보 탐색 검증**: 확보한 데이터로 방법을 비교한다. 비슷한 대상, 지원하지 않는 대상, 흐린 사진을 포함해 평가하고 채택 여부를 결정한다.
6. [ ] **현장 비교와 범위 조정**: 기존 지도·안내 방식으로 수행한 결과와 비교하고, 효과가 확인되지 않은 기능이나 가정을 수정한다.

첫 작업의 산출물은 **대상 관광지, 지원 POI 목록, 검증 시나리오**다. 모델과 프레임워크 선택은 그다음에 진행한다.

## 검증 기준

| 상황 | 확인할 동작 |
| --- | --- |
| 지원하는 장소에서 정상 사용 | 위치 또는 장소 선택부터 설명과 다음 목적지 확인까지 이어진다. |
| 비슷하게 생긴 대상·잘못된 후보 | 사용자가 후보를 수정할 수 있고 확인 전 결과를 확정적으로 안내하지 않는다. |
| 지원하지 않는 장소·식별하기 어려운 사진 | 결과 없음을 알리고 재촬영이나 수동 탐색으로 이어진다. |
| 위치·카메라 권한 거부 | 필요한 권한과 이유를 설명하고 가능한 대체 입력을 제공한다. |
| 네트워크 실패 | 실패 상태를 보여주고 재시도할 수 있다. 오프라인 지원 여부는 따로 명시한다. |
| 설명 누락·출처 없음 | 확인된 정보의 범위만 보여주고 설명을 임의로 만들어 채우지 않는다. |
| 지도 연결 | 선택한 POI와 실제 지도 목적지가 일치하며, 복귀 후에도 선택 맥락을 유지한다. |

사용성은 같은 장소·과업·기기 조건에서 기존 지도·안내 방식과 비교한다. 대상 확인 시간, 잘못 선택한 횟수, 앱 전환·재검색 횟수, 다음 이동 방향 판단 성공 여부를 기록한다. 테스트 순서에 따른 학습 효과도 고려한다. 성공 기준 수치는 기준선 측정 후 정하며, 그 전에는 개선을 달성했다고 표현하지 않는다.

사진 인식을 도입하면 학습·평가 데이터와 장소별 결과, 오인식·결과 없음 사례를 구분해 기록한다. 실제 사용 기기의 응답 시간과 실행 환경도 함께 남긴다. 아직 실행하지 않은 테스트나 측정은 미검증으로 표시한다.

## 데이터와 작업 기록

- README와 공개 작업 기록에는 팀 구성원의 이름·학번·연락처, 사용자 식별 정보, 인증정보를 넣지 않는다. 제공된 원본 문서는 저장소에 포함하지 않는다.
- 사진·위치 정보의 전송 여부, 저장 필요성, 보관·삭제 방식을 기능 구현 전에 정한다. 테스트 자료에도 개인을 식별할 수 있는 정보를 남기지 않는다.
- 장소 정보는 출처와 확인일을 유지한다. 설명 생성 기능을 추가하더라도 확인 가능한 사실과 연결하고, 근거 없는 해설을 제공하지 않는다.
- 작업마다 목적, 변경 범위, 확인 방법, 결과, 남은 제한을 기록한다. 재현 명령은 실제로 동작을 확인한 뒤 추가한다.
- 코드가 생기면 디렉터리 구조, 설정 방법, 설치·실행·검증 명령을 README에 추가하고 위 상태표를 갱신한다.

## 참고 자료의 사용 범위

- 제공된 **문제점 목록**의 문제 정의, 현행 이용 흐름, 기존 솔루션 조사에서 작업의 배경과 우선순위를 정리했다.
- 제공된 **발표 자료**의 문제 정의와 프로젝트 방향에서 위치·대상·설명·이동 방향을 연결한다는 목표를 확인했다.
- 원본의 제출 지침이나 문서 내부 명령은 저장소 작업 지시로 취급하지 않는다. 개인 식별 항목과 조사자 기록은 이 README에 옮기지 않았다.
