# 궁금한 궁 · 시나리오 프로토타입

준비된 경복궁 사진으로 전체 건물·부분 선택 → 설명·출처 → 관련 질문을 체험한다. 설명에서 ‘다른 대상 알아보기’로 다른 사진을 선택하고 돌아올 수 있다. v2 콘텐츠는 사진 6장·대상 7개·답변 13개·관련 질문 6개다. 자동 인식·LLM·실제 GPS·카메라·DB·관찰 이력 수집은 없다.

질문은 준비된 목록 중 선택하며 필수가 아니다. 검수된 추가 질문이 없으면 설명 화면에서 그 한계를 알리고 빈 목록으로 보내지 않는다. 원하는 내용이 없으면 기본 설명·다른 부분·다른 대상·후보 재비교로 돌아갈 수 있다. 자유 입력이나 진행자의 실시간 답변은 제공하지 않는다.

## 실행

확인한 환경은 Windows, Node.js `24.11.1`, npm `11.6.2`, Vite `8.3.4`다. Node.js `22.12.0` 이상을 사용한다. 저장소 루트에서:

```powershell
cd prototype
npm.cmd ci
npm.cmd run dev
```

기본 주소는 [프로토타입 홈](http://127.0.0.1:5173/)이다. 개발 서버가 실행되는 동안 사용할 수 있다. Windows PowerShell에서 `npm.ps1` 실행 정책에 막히지 않도록 `npm.cmd`를 표기했다.

홈의 메뉴에서 **사진으로 둘러보기(2안)**와 **움직이는 궁궐(1안)**을 비교한다. `?preset=S3&design=photo` / `?preset=S3&design=story`로도 같은 화면을 지정할 수 있다. 디자인을 바꾸면 새 여정으로 시작하며 이전 선택을 복원하지 않는다. 기존 문구·설명·질문 자료는 두 안이 함께 사용한다.

2안은 큰 사진 위에 맥락·메뉴·주 행동을 두고, 아래 탐색 카드에서는 큰 사진 뒤에 질문을 표시한다. 1안은 직접 작성한 3D 일러스트를 보여준다. 전체 궁궐 건물 → 가까이 보기 → 연못의 누각의 세 장면이 약 19.5초 이어진 뒤 멈춘다. 재생·정지·다음 장면으로 이어서 살펴볼 수 있다. 실제 조사·복원 모형이 아니다.

처음에는 `prefers-reduced-motion`을 따른다. 메뉴의 **움직임 효과**를 켜거나 끌 수 있으며 명시적으로 선택한 값은 해당 탭의 sessionStorage에 보관해 새로고침에도 유지한다. 사용 이력은 저장하지 않는다. 저장소 접근이 차단되면 메모리 설정과 기기 기본값을 사용한다. 동작 줄이기가 켜졌어도 이야기의 재생을 직접 선택하면 이야기만 재생한다. 버튼 누름·사진 전환·이야기는 준비된 자료의 시각 동작이며 실제 촬영·AI 분석을 수행하지 않는다.

| 주소 뒤 설정 | 장면 / 확인할 흐름 |
| --- | --- |
| `?preset=S1` | 경회루 · 홈 → 건물 전체 → 기본 설명 → 재건 시기 질문 |
| `?preset=S2` | 근정전 · 사진 아래 가운데 돌바닥 → 미리보기 → 설명 → 부분 수정 |
| `?preset=S3` | 십장생굴뚝 · 호기심 카드 → 문양 설명 → 관련 질문 / 연기 배출구 재선택 |
| `?preset=S3&card=0` | 같은 장면에서 카드 없이 시작 |
| `?preset=S3&context=before-visit&card=0` | 방문 전 문구, 카드 없이 시작 |
| `?preset=S5` | 경회루 설명 → 다음 관람 카드 ‘수정전 살펴보기’ → 수정전 기본 설명/질문 → 뒤로. 또는 다른 대상 알아보기로 새 사진 선택 |
| `?preset=S4` | 입력 사진 → ‘이 사진으로 알아보기’ → 준비된 사정전/수정전 비교 → 선택한 참고 사진·설명. 후보 재비교/해당 없음/입력 사진 재시도 |
| `#test` | 진행자용 장면·맥락·카드·200% 글자·오류 복구 설정 |

진행자는 `#test`에서 설정한 뒤 ‘새 테스트 시작’을 누른다. 설정을 참여자에게 정답 안내로 읽어주지 않는다. 사진 확대는 단순 2배 보기이며 확대 사진 안에서는 스크롤할 수 있다. 영역 밖은 가까운 대상으로 맞추지 않는다. 키보드로 사진 버튼을 실행하면 글로 고르는 대안이 열린다.

홈은 현재 장면의 홈으로 이동하며 같은 실행을 유지한다. 브라우저 뒤로는 직전 설명·스크롤·사진 확대·내부 스크롤·가능한 원래 조작부 포커스를 복원한다. 새로고침과 ‘새 테스트 시작’은 새 실행이며 이전 실행의 이력을 거부한다. URL에는 시작 preset·맥락·카드를 유지하므로 새로고침은 시작 장면 H로 돌아간다. 오류·글자 확대 설정은 새로고침하면 해제된다.

S1·S2는 C01/C02만 이동 가능해 굴뚝을 미리 노출하지 않는다. S3은 기존 C01~C03을 허용한다. S4 후보 입력·참고 사진은 앞선 새 탐색 목록에 노출하지 않는다. S5는 S4 뒤에 진행하며 기존에 본 수정전의 탐색 연결을 확인한다. P01 진행자 정답표는 publicDir 밖에 유지한다. 새 사진은 해당 화면에서만 요청하며 초기 홈에서 6장 전체를 불러오지 않는다. P06에서 화면용 이미지 최적화와 전체 시나리오를 확인한다.

## 검사와 빌드

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build`는 콘텐츠 참조·이미지 크기·SHA-256 검사를 먼저 수행하고 `dist/`에 정적 파일을 만든다. `preview`는 빌드 결과를 [로컬 미리보기](http://127.0.0.1:4173/)로 제공한다. `dist/`는 생성물이므로 커밋하지 않는다. `index.html`을 파일 탐색기에서 바로 여는 방식은 지원하지 않는다.

`vite.config.js`의 `publicDir`은 [콘텐츠 원본](../docs/prototype/content/)이다. 앱이 읽는 `content.json`과 사진은 이 한 곳에서 관리하고 Vite가 개발 서버/빌드 결과에 제공한다. 복사본을 수동 수정하지 않는다.

스마트폰 실기기는 같은 LAN의 개발 서버 또는 별도 정적 호스팅이 필요하다. 현재 기본 명령은 PC의 loopback에만 연결된다. 인터넷 공개 배포·방화벽 변경·LAN 공개는 수행하지 않았다. 실행 방법을 정한 뒤 실제 기기에서 터치·스크롤·회전을 확인해야 한다.

## 코드 읽는 순서

1. [content.json](../docs/prototype/content/content.json): 준비된 사진·장면·대상·질문·답변·출처.
2. [content.js](src/content.js): 자료 무결성, contain 좌표 계산, 영역 선택, 답변 표시 조건.
3. [state.js](src/state.js): 행동에 따른 선택·질문·오류 상태 전환. API나 저장소를 호출하지 않는다.
4. [main.js](src/main.js): 상태 → H/V/A/Q/E 화면, 브라우저 이동 기록, 진행자 설정, 사진 복구.
5. [style.css](src/style.css): 흰 바탕·먹청색·작은 주홍 포인트, 둥근 UI, 키보드 포커스와 글자 확대.
6. [core.test.js](test/core.test.js): 잘못된 참조·좌표 경계·교차 대상 답변·상태 초기화 검사.

추가 화면·모션은 [app-design.css](src/app-design.css), [motion.js](src/motion.js), [palace-story.js](src/palace-story.js)에서 읽는다. Three.js `0.186.1`을 1안에서만 동적으로 불러온다. 3D 모형은 외부 모델을 다운로드한 것이 아니라 형상과 부재를 코드로 작성했다. 화면 밖·다른 탭에서는 자동 재생을 쉬고 다른 화면으로 이동하면 프레임·observer·이벤트·GPU 자원을 정리한다.

실제 390px viewport 캡처는 [2안](screenshots/photo-home.png) · [1안](screenshots/story-home.png) · [가까이 보는 장면](screenshots/story-closeup.png)이다. 생성 시안이 아니라 브라우저에서 실행한 화면이다. 스크린샷 자체로 모션이나 실기기 성능을 검증하지 않는다.

입력 → 정적 자료의 지원 영역/ID 확인 → 메모리 상태 갱신 → 같은 대상의 설명·출처를 표시한다. 영구 저장과 질문 처리 API는 없다. 외부 출처는 사용자가 누를 때 연결된다.

## 관찰 시작 전

검사 결과·미확인 항목은 [검증 기록](VERIFICATION.md), 사람 관찰 절차는 [TESTING](../docs/prototype/TESTING.md)을 확인한다. 실기기와 첫 사용 참여자 관찰(P08)은 자동 검사로 대체하지 않는다. 촬영일이 미상인 사진이며, 경회루 사진은 높은 시점이라 현장 시선과 차이가 있다. 사진 3장의 편의성 확인을 경복궁 전체 지원이나 자동 인식 성능으로 일반화하지 않는다.

## 색과 버튼 반응 비교

[재질 비교 화면](http://127.0.0.1:5173/materials.html)은 남색·적갈색·무채색 버튼을 사진과 흰 배경 위에서 비교한다. 현재 채택 재질은 오른쪽의 맑은 무채색 유리이며 글자는 짙은 남색이다. 메뉴의 비교 링크로도 열 수 있다. 버튼을 눌러도 화면을 교체하지 않으므로 빠른 누름·길게 누름·키보드·포인터 추종과 탄성 복귀를 반복해 볼 수 있다. 실제 앱의 주요 행동은 즉시 다음 화면으로 이동하며 움직임을 보여주려고 지연시키지 않는다.

위쪽의 ‘배경 굴절’로 동일 격자·사진에서 효과를 켜고 끈다. 외곽 14px의 볼록 곡면만 최대 각 축 5px로 굴절하며 중앙은 중립이다. [glass-map.js](src/glass-map.js)의 SVG gradient와 [glass-optics.js](src/glass-optics.js)의 backdrop 필터를 사용한다. 유리는 Canvas를 사용하지 않는다. 기존 1안의 Three.js 3D 렌더는 별도다. 굴절은 현재 Chromium용이며 다른 엔진·접근성 설정은 기본 재질로 대체한다. 네이티브 Liquid Glass 재현이나 스마트폰 성능 검증을 뜻하지 않는다.
