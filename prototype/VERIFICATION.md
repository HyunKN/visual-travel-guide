## 관찰 전에 남은 항목

1. 사용자가 실제 사진·설명·선택 영역·시각 방향을 확인한다. 돌바닥은 아래 가운데 영역만 준비했으므로 같은 바닥의 다른 위치에서 관심을 표현하면 미지원으로 기록될 수 있다. 영역 지정을 인식 성능으로 해석하지 않는다.
2. 스마트폰 접근 방법을 정하고 실제 기기에서 기본 흐름, 터치·사진 스크롤·회전·글자 크기를 확인한다. 현재 서버는 loopback이며 LAN 공개·호스팅 배포·방화벽 변경은 하지 않았다.
3. [사람 관찰 절차](../docs/prototype/TESTING.md)에 따라 협조자 1명과 S1→S2→S3을 진행하고 개입·미지원·흥미 없음도 기록한다. **P08은 미실행**이다.

P01~P06의 로컬 자료·구현과 P07의 PC/브라우저 확인을 준비했다. 실기기·사용자 콘텐츠 확인이 남아 있으므로 P07 전체나 상위 Issue를 모두 완료했다고 표시하지 않는다. 현장 효과·자동 인식 정확도·일반 사용자 성공률은 이번 검사에서 측정하지 않았다.

## 2026-10-15 디자인 수정의 추가 확인

추가 표시 확인: 비교안 명칭을 1안(3D 궁궐), 2안(사진 두 개)로 통일했다. 중단된 로컬 preview 서버를 다시 실행하고 새 탭에서 두 안의 사진과 3D canvas 표시를 확인했다. 390×844 viewport로 두 홈 캡처를 갱신했다. 번호 수정 뒤 콘텐츠 검사와 정적 빌드를 다시 통과했다. 헤더 꽃 모티프는 아직 그대로이며 궁궐 형태는 참고 후보만 조사했다.

사용자 요청으로 큰 사진의 2안과 3D 이야기의 1안, 단청 조합의 유리 버튼·누름 복귀·사진 공유 전환, 사진 다음 질문이 오는 탐색 카드를 적용했다. 기존 콘텐츠·문구·S1~S3은 유지했다. [실제 캡처 2안](screenshots/photo-home.png) · [1안](screenshots/story-home.png)은 390px viewport에서 저장했으며 콘텐츠 캡처 폭은 scrollbar를 뺀 375px이다.

- 브라우저에서 메뉴의 두 안 전환, native dialog의 초점·닫기, 정상 3D canvas 생성, 수동 세 장면 전환을 확인했다. 원본 게임의 화면·모델은 앱 자산으로 사용하지 않았다.
- 검사 브라우저는 `prefers-reduced-motion=true`였다. 기본 정지 상태와 메뉴에서 움직임 효과를 켠 상태를 따로 검사했다. 켠 상태에서 자동 이야기가 마지막 장면과 진행 표시까지 바뀐 뒤 재생 버튼으로 돌아오는 것을 확인했다. 재생·즉시 정지와 수동 다음 장면도 확인했다.
- 사진형 홈 → 선택에서 실제 공유 사진 overlay 생성과 목적지 사진의 임시 opacity를 확인했고 완료 후 제거되는 것을 확인했다. 사진 변형은 균일 scale이며 cover/contain의 차이는 crop으로 처리한다. 실제 카메라 촬영은 하지 않았다.

- 격자 영역 `(120,380)-(575,495)`의 RGB 평균 절대 차이는 약 `[.349,.345,.356]`, 사진 `(680,380)-(1130,495)`은 `[2.167,2.101,2.427]`이다(채널 범위 0~255). 격자 중앙 `(165,407)-(535,465)`은 `[0,0,.00061]`이다. 외곽 변화와 중앙 안정성의 증거이며 굴절의 체감 품질·정확한 광학·성능을 수치화한 결과가 아니다.
- 비교 화면에서 ON/OFF 상태 문구 전환을 확인했다. 사진 위 라벨은 흰 글자와 국소 그림자로 대비를 보완했다. 미지원 브라우저 또는 접근성 재질 대체 시 SVG 활성으로 오표기하지 않도록 계산된 backdrop 연결 여부를 표시한다. 연결 여부 자체는 렌더 통과 판정이 아니다.
- 실제 앱을 다시 로드해 주 행동 → S3 사진 선택 → 홈 복귀를 확인했다. 사진형 홈의 Canvas 요소는 0개였고 메뉴·주 행동·카드 아이콘에 SVG backdrop이 연결됐다. 같은 크기의 메뉴/아이콘은 동일 필터를 공유했다. 화면 교체 뒤 사용하지 않는 필터가 누적되지 않고 홈에서 2개였다. 이것은 단기 확인이며 장시간 메모리 측정은 아니다.
